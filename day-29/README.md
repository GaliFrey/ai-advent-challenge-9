# День 29 — оптимизация локальной LLM для WebTutor RAG

## Задание и отличие от дня 28

Настроить параметры локальной LLM, изменить prompt под свою задачу, попробовать
квантование и сравнить качество, скорость и потребление ресурсов до/после.
Оригинал задания: `resources/task.md`. Формат сдачи — видео и код.

Видео результата: [День 29 — оптимизация локальной LLM](https://yadi.sk/i/m797-Ea7xk_-wg).

День 28 сравнивал локальный RAG с облачным ответом. Здесь сравниваются два
локальных профиля на **одинаковых вопросах, источниках и памяти**. DeepSeek
оценивает ответы как вспомогательный судья; не генерирует ответ вместо Qwen3.
Корпус прежний: локальная документация WebTutor — Datex, Portal и SQL/XML-модель.
Обучение модели и изменение retrieval в эксперимент не входят.

## Подготовка и запуск

Самостоятельный Python 3.12+/uv-проект. Нужны готовый локальный `webtutor-docs`,
Node.js для MCP и установка Ollama из `../day-28/resources/ollama-local/`.
Веса не перемещаются и не попадают в Git. Код дней 27/28 не импортируется.

```bash
cd day-29
uv sync --locked
test -e .env || cp .env.example .env
uv run --locked python tui.py
```

Ключ задаётся в `day-29/.env` или `DEEPSEEK_API_KEY` окружения;
модель судьи — `DEEPSEEK_MODEL`, по умолчанию `deepseek-flash`.
Ключ не сохраняется в отчётах и не передаётся процессу MCP/Ollama.
MCP использует только регистрацию `[mcp_servers.webtutor-docs]` в конфигурации
Codex либо `WEBTUTOR_MCP_COMMAND` и JSON-массив `WEBTUTOR_MCP_ARGS`.

TUI показывает ответы «Первого профиля» и «Второго профиля», время, скорость, RAM/GPU-память, общие
источники и снимок памяти. Можно выбрать профили, изменить параметры каждого,
ввести ручной вопрос либо выбрать один из десяти сохранённых случаев.
Для ручного поиска можно выбрать Datex, Portal, оба корпуса или SQL/XML;
в CLI это аргумент `--source`.
Каждый ручной вопрос — отдельное сравнение, без накопления истории чата.
Диалоговый тест использует заранее зафиксированную ошибочную историю.
Верхние профили и параметры задают новое сравнение: слева отдельный блок
«Первый профиль», справа — «Второй профиль». Температура, контекст, лимит ответа
и рассуждения редактируются независимо в каждом блоке. Выбор пресета заполняет
только его блок. Пакетный эксперимент использует заранее заданную процедуру настройки.
Ниже показан выбранный результат с номером случая и повтора:
его профили берутся из сохранённого запуска, а не из текущих полей сверху.
Над каждым ответом повторяются его модель, prompt, состояние рассуждений,
температура, размер контекста и лимит ответа. Эти параметры относятся к показанному
ответу и сохраняются при изменении настроек следующего запуска.
Обезличенная оценка требует двух вызовов DeepSeek на сравнение; переключатель
позволяет отключить её для ручных вопросов. Без судьи предметная оценка остаётся
ручной, автоматического выбора победителя нет.

Во вкладке Ollama сервер запускается только кнопкой. При выходе останавливается
только собственный процесс; внешний сервер не затрагивается. Проверки состояния
не запускают генерацию и не загружают веса. Во время эксперимента используются
последовательные запросы; управление профилями и сервером заблокировано.

CLI:

```bash
# Проверить уже работающую Ollama, GPU и наличие ключа без генерации.
uv run --locked python main.py preflight

# Загрузить отсутствующую вторую квантовку (~16 GB).
uv run --locked python main.py prepare --start-ollama

# Одно сравнение, без облака.
uv run --locked python main.py compare --case opt-empty --after no-thinking --no-judge --start-ollama

# Ручной вопрос: один поиск MCP, общий контекст двух профилей.
uv run --locked python main.py compare --question 'Что делает ArrayOptFirstElem?' --start-ollama

# Полный эксперимент: локальная генерация + облачный судья.
uv run --locked python main.py experiment --start-ollama

# Читать сохранённый отчёт без запросов к моделям и MCP.
uv run --locked python main.py report reports/ИМЯ.json
uv run --locked python tui.py --report reports/ИМЯ.json

# Использовать фактически выбранный профиль из пакетного эксперимента.
uv run --locked python main.py compare --case open-missing --profile-report reports/ИМЯ.json --start-ollama
```

`--start-ollama` подключается к существующему серверу либо запускает свой,
затем останавливает только свой процесс. Прерванные загрузки продолжает Ollama.
Посторонние модели из памяти не выгружаются: освободите сервер перед экспериментом.
Запускать один экземпляр экспериментатора за раз.

## Профили и протокол

База соответствует записанному эксперименту дня 28: Qwen3:14b Q4_K_M,
temperature=0, num_ctx=16384, num_predict=3072, thinking=true и исходный prompt.
Во всех новых профилях дополнительно фиксируется seed=42 для воспроизводимости;
он не гарантирует побитовую идентичность ответов. Для ручного поиска K=4,
max_chars=5000, source=docs; планировщик отключён, ищется исходный вопрос.

Шесть этапов настройки относительно текущего принятого профиля:

1. thinking=false.
2. Короткий предметный prompt с примером JSON.
3. num_predict=1536.
4. num_ctx=8192.
5. temperature=0,2.
6. Qwen3:14b Q8_0 вместо Q4_K_M.

Именованные профили в TUI/CLI — накопительные рецепты этих изменений.
Фактический победитель пакетного эксперимента может отличаться от рецепта:
отклонённые изменения не включаются в следующий этап. При открытии отчёта
победитель доступен в TUI как `selected`.

`documents.json` содержит прочитанные через MCP документы с происхождением;
`cases.py` — шесть случаев настройки и четыре отложенных случая, с заранее
составленными фактами, обязательными элементами и запретами. Эти артефакты
нужны для запуска и входят в Git. Отложенные случаи не используются для выбора
изменений. Часть API повторяется между группами: это маленький учебный набор,
а не независимая оценка обобщения на всю платформу.

Фиксируются полный вопрос, источники и память, их SHA-256; изменяется только
системный prompt и параметры генерации. Источники не сокращаются под профиль.
Бюджет UTF-8-байты/2 с резервом 1024 токена — оценка, не токенизатор.
Профиль с превышением бюджета получает `context_limit`, запрос не выполняется.
Фактический prompt_eval_count также сравнивается с зарезервированным контекстом.
Для ручного поиска исходное чтение может быть усечено по общему max_chars;
усечение отмечено и одинаково для обоих профилей.

Перед каждым измеряемым ответом выгружаются только модели этого эксперимента,
затем модель загружается пустым запросом с нужным контекстом. Время этой загрузки
сохраняется отдельно, в измерение ответа не входит. Очистка также уменьшает
влияние кэша префикса. На этапе настройки ответ текущего профиля переиспользуется
из сохранённого прогона; итоговые сравнения полностью генерируются заново.

Итог: база и кандидат получают четыре отложенных случая по три раза. Порядок
первого и второго профилей чередуется. Любое ухудшение отдельного критерия на любом случае
блокирует принятие. Среди равных по качеству вариантов выбирается меньшая
медиана времени, затем память. Исправление нарушения формата/цитат также
считается улучшением. Если преимущество не подтверждено, остаётся база.
При неразрешённой оценке статус `manual_review`, а не доказанный победитель.

## Оценка, ресурсы и отчёты

Локально проверяются JSON-контракт, ссылки и дословные цитаты, завершённость.
Это не доказывает семантическую правильность и исполнимость кода на WebTutor.
DeepSeek получает вопрос, источники, фиксированную память, критерии и два
обезличенных ответа. Выполняются оценки A/B и B/A по шкале 0–2:
правильность, полнота, подтверждённость, обоснованность ответа/отказа.
Расхождение оценок, существенных ошибок или запрос ручной проверки блокируют
автоматический выбор. Некорректный ответ API сохраняется без автоматического
повтора. Сведения об источниках и ответы отправляются DeepSeek при включённом судье.

Ручная оценка спорного сравнения, индекс начинается с 0:

```bash
uv run --locked python main.py review reports/ИМЯ.json --comparison 0 --side before --scores 2,2,2,2 --reason 'Проверено по S1: ...'
uv run --locked python main.py review reports/ИМЯ.json --comparison 0 --side after --scores 2,2,2,2 --reason 'Проверено по S1: ...'
uv run --locked python main.py experiment --resume reports/ИМЯ.json --start-ollama
```

`--critical-error` добавляет существенную ошибку. Ручные оценки и их история
сохраняются отдельно от оценок судьи. Продолжение не повторяет завершённые
генерации. Если правка уже принятого этапа меняет последующие профили,
нужен новый эксперимент; прежние ответы не сравниваются с другой конфигурацией.

Метрики: время HTTP-генерации, первый текст, входные/выходные токены,
eval_count/eval_duration, время загрузки. Thinking входит в выходные токены.
RAM — сумма RSS процессов Ollama, общие страницы могут учитываться повторно.
GPU — вся использованная память устройств, включая другие приложения.
Размещение модели сохраняется через `/api/ps`. Отсчёты каждые 0,5 секунды;
если сбор дольше, частота уменьшается. Максимум наблюдений не гарантирует
захват кратковременных пиков. Недоступные значения — null/«н/д», не ноль.

Полные локальные отчёты лежат в игнорируемом `reports/`: атомарная запись,
права 0600, версии зависимостей/Ollama, digest и квантовка модели, prompt,
сообщения, ответы и рассуждения, прогрев, сырые отсчёты ресурсов, судья,
решения по этапам. Чтение отчёта не вызывает API. Отмена сохраняет частичный
результат. Платформа WebTutor и её сервер выполнения здесь не запускаются.

открыт в headless TUI без новых API-вызовов. При ревью исправлена проверка
неизвестных ссылок: правильная цитата из S1 больше не маскирует ссылку на S99.
Результаты последних пяти пар перепроверены этим валидатором и не изменились.
При публикации новые генерации и облачные вызовы не выполнялись.
Визуальной проверки интерфейса и содержания видео не было. Файл видео проверен
через ffprobe: MP4/H.264, 2560×1440, 290,4525 с, один видеопоток без аудио.
Офлайн-проверки:

```bash
uv run --locked python -m unittest discover -v
uv run --locked python -m py_compile core.py clients.py engine.py judge.py resources_monitor.py ollama.py cases.py main.py tui.py
uv lock --check
```

Headless-тесты подменяют модели, облако и управление сервером; это функциональная
проверка TUI, без визуальной оценки. В текущем sandbox завершение executor Python
после Textual зависает; вне sandbox офлайн-набор завершился нормально.

## Сценарий демонстрации с нуля

1. Во вкладке «Ollama» запустить сервер; в «Сравнении» выбрать `distinct-code`
   и baseline / no-thinking, показать параметры над ответами и время.
2. Во вкладке «Источники и память» показать общие основания для обоих профилей.
3. В «Сравнении» выбрать `missing-contract` и baseline / temperature-02,
   показать обоснованный отказ; во вкладке «Отчёт» — оценки и ресурсы.
4. На том же вопросе сравнить temperature-02 / q8, в «Диагностике» показать
   сведения о модели. Параметры одинаковые, отличается только квантование.
5. Показать дополнительные сравнения prompt/лимита и температуры 2,0;
   объяснить ускорение отдельных ответов, отсутствие преимущества Q8_0 и
   отклонение ответа без `[S1]`.

Все численные выводы выше основаны на сохранённых отчётах. Содержание записи
визуально не проверялось.

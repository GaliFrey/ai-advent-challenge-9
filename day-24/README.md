# День 24 — цитаты, источники и анти-галлюцинации

## Задание

Доработать RAG: модель возвращает ответ, список источников
(`source + section/chunk_id`) и цитаты из найденных чанков.
На десяти вопросах проверить наличие источников и цитат, а также
соответствие смысла ответа цитатам. При релевантности ниже порога
ассистент говорит «не знаю» и просит уточнение. Формат сдачи — видео + код.
Оригинал: локальный `resources/task.md`.

## Решение

Отдельный uv-проект и полноэкранный Textual TUI. Цепочка одна:
**вопрос → rewrite → top-20 → reranker → порог → до 5 чанков → ответ → проверка цитат → оценка LLM**.
K до/после и порог reranker настраиваются. Начальный порог 0,10 —
экспериментальный, оптимальность не установлена. Оценки reranker не являются
вероятностями наличия ответа.

Переиспользуются helpers дней 22–23: rewrite, атомарное сохранение,
отбор, read-only поиск и локальный CPU reranker
`cross-encoder/mmarco-mMiniLMv2-L12-H384-v1` с ревизией
`1427fd652930e4ba29e8149678df786c240d8825`, sigmoid и пределом 512 токенов
на пару. Длинные пары могут усекаться. Индекс и кэш эмбеддингов находятся
в дне 21, кэш reranker — в дне 23. Нужен весь репозиторий;
код предыдущих дней не изменён. Корпус — README дней 0–20,
секреты, чаты, журналы и ресурсы в поиск не попадают.

В отличие от дня 23, ссылки `[S1]` дополнены **точными текстовыми цитатами**.
Модель возвращает JSON с полями:

- `status`: `answered` или `unknown`;
- `answer`: список утверждений, у каждого `text` и непустые `citations`
  с `source_id` и `quote`;
- `sources`: ровно использованные источники с `source_id`, `source`,
  `section`, `chunk_id`;
- `clarification`: уточняющий вопрос, обязательный для отказа.

Автоматически проверяются структура, наличие доказательств у каждого
утверждения, существование ссылок в отобранном контексте, точность метаданных,
непустые цитаты и их **дословное вхождение в текст указанного чанка**.
Неверный результат сохраняется для диагностики, но не показывается
как принятый ответ. Автоматических повторов запроса нет.
Наличие точной цитаты не доказывает, что она подтверждает вывод:
смысл оценивает LLM **отдельным запросом** после успешных проверок кода.
Проверяющий получает исходный вопрос, ответ, цитаты и отобранный контекст,
без диалога генератора, результатов rewrite и ожидаемых ответов из набора вопросов.
Используется та же настроенная модель DeepSeek с отдельной инструкцией.
Она оценивает подтверждение цитатами, полноту по доступному контексту
и обоснованность ответа/отказа с уточнением. Возвращает три проверки,
вердикт pass/fail и объяснение; pass допустим только при трёх положительных проверках.
Оценка LLM не гарантирует корректность: модель может ошибаться и повторять
ошибки генератора. Результат явно подписан «Оценка LLM».

Генератор и проверяющий учитывают требуемую конкретность. На вопрос
«где хранится» scope пользователя не заменяет конкретный файл, путь или таблицу.
Если нужного места хранения нет в найденных чанках, модель должна явно
обозначить пробел в `clarification` и запросить сведения. Подтверждённая
часть составного вопроса остаётся в ответе с цитатами. Проверяющий должен
отметить `coverage=false`, если ответ молча подменяет место хранения scope
или пропускает часть вопроса без уточнения.

Оценка и исходный ответ сохраняются раздельно. Расхождение не стирает ответ.
Некорректная оценка или ошибка API не заменяются положительным вердиктом.
При неверном формате самого ответа оценка смысла не вызывается.
Отказ по порогу тоже оценивается, но только относительно пустого допущенного
контекста — это не проверка качества порога или отсутствия данных во всём корпусе.
Старые отчёты открываются без новых запросов: ручные оценки обозначены как старые,
отсутствие LLM-оценки показано явно.

Если ни один кандидат не прошёл порог, приложение возвращает
«Не знаю по доступным данным» с просьбой уточнить, без вызова генерации.
Если чанки прошли порог, но не содержат ответа, модель должна вернуть
`unknown` с конкретным уточнением. При частичном ответе модель указывает
подтверждённые сведения и запрашивает недостающие данные в `clarification`.
Реальные ответы и ограничения этого поведения описаны ниже.
У корректного отказа `answer=[]`, `sources=[]`; цитаты отсутствуют.
Это явное исключение из требования «цитаты в каждом ответе», поскольку
при отсутствии доказательств их нельзя выдумывать.

## Подготовка и запуск

Нужны Python 3.12+, uv, индекс дня 21 и ключ DeepSeek.

```bash
cd day-24
uv sync --locked
test -e .env || cp .env.example .env
# Заполнить DEEPSEEK_API_KEY; существующий .env не перезаписывать.
uv run --locked python main.py prepare
uv run --locked python main.py tui
```

`prepare` использует кэш reranker дня 23, при необходимости скачивает модель.
Если индекс отсутствует или устарел:

```bash
cd ../day-21
uv sync --locked
HF_HOME="$PWD/indexes/hf-cache" uv run --locked python indexer.py build
cd ../day-24
```

Настройки `.env`: `DEEPSEEK_API_KEY`, `DEEPSEEK_MODEL` (по умолчанию
`deepseek-flash`). Системные переменные имеют приоритет. После изменения
`.env` перезапустить TUI. Ключ не попадает в результаты и журналы.
При подготовке проекта существующий локальный `.env` дня 23 скопирован
в игнорируемый `.env` дня 24 без вывода содержимого.

Один вопрос требует **до трёх платных вызовов DeepSeek**: rewrite, ответ
и проверка смысла. При пустом контексте — rewrite и оценка отказа.
Десять вопросов — до 30 вызовов.
DeepSeek получает исходный вопрос для rewrite; для ответа — исходный вопрос
и отобранные фрагменты README. Проверяющий получает дополнительно ответ
с цитатами. `temperature=0`, thinking отключено,
явный `max_tokens` не задан; timeout запроса — до 90 секунд.

## TUI

Рекомендуемый терминал — 180×60. При открытии запросы не выполняются.
Сверху: выбор вопроса, поле своего вопроса, кнопка ответа, кнопка прогона
десяти вопросов, настройки K и порога. Кнопки показывают максимальное
число внешних вызовов. Во время работы видны этап, индикатор и время;
запуск и настройки заблокированы, вопросы и вкладки доступны.

- **Ответ и доказательства**: ответ, цитаты с привязкой к утверждениям,
  пути источников, разделы, chunk_id, проверки кода и отдельная оценка LLM
  с тремя критериями, объяснением, токенами и временем проверяющего.
  Ручных кнопок и обязательного ручного подтверждения нет.
- **Поиск и контекст**: исходный и rewritten запросы, все кандидаты,
  ранги, similarity, rerank score, причины отбора и полный текст чанка.
- **10 вопросов**: статус, ответ/отказ, число источников и цитат,
  автоматическая проверка и отдельная оценка LLM. Enter
  на строке открывает соответствующий ответ.
- **Диагностика**: ошибки проверки, исходный ответ модели и исходная оценка проверяющего.

Текстовые панели прокручиваются независимо. Чанки выбираются стрелками
или мышью. Ctrl+Q прекращает запуск следующих этапов; текущий запрос
может завершаться до своего timeout, после чего сохраняется частичный отчёт.
Результаты сохраняются после каждого этапа в `resources/` с правами 0600;
диагностические события без ключей, текстов запросов/ответов и сообщений
исключений — в `logs/`. Оба каталога исключены из Git.

Открыть сохранённый результат без моделей и сети:

```bash
uv run --locked python main.py tui resources/demo-<UTC>.json
uv run --locked python main.py show resources/demo-<UTC>.json
```

CLI-запуск:

```bash
uv run --locked python main.py ask 'Какие слои памяти очищаются в дне 11?'
uv run --locked python main.py benchmark
```

## Проверки и ограничения

```bash
uv run --locked python -m unittest -v
uv run --locked python -m compileall -q main.py pipeline.py evidence.py retrieval.py \
  shared.py session_log.py tui.py judge.py check_local.py test_pipeline.py test_tui.py test_judge.py
uv lock --check
```

Прошли 17 офлайн-тестов, компиляция, проверка lock-файла,
CLI-справка, просмотр сохранённого отчёта и `git diff --check`.
Тесты проверяют контракт, точность цитат и метаданных, отсутствие
доказательств, отказ по порогу без генерации, отказ модели при тематическом
контексте, частичный результат, отмену, сохранение и отдельную оценку LLM,
несогласованный вердикт, ошибочный формат и отказ API проверяющего.
Headless TUI проверяет запуск, цитаты и источники, контекст, автоматические оценки, старые отчёты,
прогон десяти вопросов, отклонённые ответы, отказ и replay.
Визуальная проверка пользовательского терминала не выполнялась.

Настоящие индекс, эмбеддинги и reranker прошли десять вопросов с подменными
rewrite, генерацией и оценкой смысла без сети. Результат
`resources/local-check-20261001T172303.036042Z.json` помечен
`validation_only=true`; TUI явно показывает синтетический характер ответов и оценок.
Это проверка работоспособности цепочки, **не оценка качества RAG**.
Повторить при заполненных кэшах:

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 uv run --locked python check_local.py
```

## Результаты реального прогона

Полный прогон `resources/demo-20261001T181147.699446Z.json` выполнен
1 октября 2026 года с `deepseek-flash`: K кандидатов = 20, итоговый K = 5,
порог reranker = 0,10. Все десять вопросов и оценки завершены; ошибок
этапов в журнале нет. Сохранены ответы, исходные запросы, чанки и оценки LLM.
При подготовке публикации повторно проверены дословность всех цитат,
метаданные, структура ответов и согласованность вердиктов с критериями.
Новых запросов DeepSeek не выполнялось.

| Вопросы | Результат | Источники и цитаты | Оценка LLM |
| --- | --- | --- | --- |
| q01–q06 | Ответы | Есть; проверки кода прошли | pass |
| q07 | Частичный ответ с уточнением | Есть; проверки кода прошли | fail по полноте, остальные критерии положительные |
| q08 | Отказ: для сравнения дней 19/20 нет данных дня 20 в контексте | Пустые списки по контракту отказа | pass |
| q09 | Отказ: нет результатов нагрузочного теста | Пустые списки по контракту отказа | pass |
| q10 | Отказ: нет бюджета и SLA в контексте | Пустые списки по контракту отказа | pass |

Итого: **7 ответов, 3 отказа с уточнением, 26 точных цитат,
9 pass и 1 fail от LLM-проверяющего**. Прогон использовал 30 вызовов
(rewrite, генерация, оценка для каждого вопроса) и 40 047 токенов суммарно.
Это оценки конкретного сохранённого запуска, а не доказательство общей точности.

**q07:** генератор правильно ответил про диалог дня 9, привёл сведения
про scope памяти дня 11 и явно запросил документ с конкретным путём хранения.
Проверяющий признал цитаты достоверными и уточнение обоснованным, но выставил
`coverage=false`, посчитав описание scope подменой места хранения несмотря
на обозначенный пробел. Это спорная оценка частичного ответа и ограничение
LLM-проверки; результат не исправлялся задним числом.

**q08:** поиск отобрал только фрагменты дня 19. Отказ обоснован отобранным
контекстом, но сведения дня 20 в корпусе есть: ограничение поиска не позволяет
сделать сравнение. Положительная оценка отказа не означает полноту retrieval.

Отдельный запуск `resources/ask-20261001T181439.530568Z.json` проверил q10
при пороге reranker **1,0**. Ни один чанк не прошёл порог; приложение
вернуло «Не знаю по доступным данным» и просьбу уточнить. Генерация
не вызывалась; rewrite и оценка отказа потребовали два вызова, 925 токенов.
Оценка отказа — pass, ошибок этапов нет.

Вывод: обязательные доказательства, проверка точности цитат, автоматическая
оценка смысла и отказ по порогу работают в сохранённых запусках. При этом
качество ответа ограничено найденными фрагментами, а LLM-проверяющий может
спорно оценивать полноту. Требование десяти проверенных вопросов выполнено;
гарантия безошибочности и оптимальность порога не заявляются.

## Сценарий видео

Показать q03 при пороге 0,10: ответ, цитаты, источник, раздел и chunk_id,
исходный чанк, проверки кода и объяснение LLM. Затем q07: частичный ответ,
уточнение и спорную оценку полноты. Отдельно q10 при пороге 1,0: пустой
контекст, отказ с уточнением и отсутствие генерации. В конце открыть полный
сохранённый прогон и таблицу всех десяти результатов. Полный отчёт и отдельный
запуск сохраняются независимо; их просмотр не вызывает API.

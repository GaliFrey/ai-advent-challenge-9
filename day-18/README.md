# День 18 — планировщик SSH-журнала и MCP-сводка

## Задание

Сделать MCP-инструмент с отложенным или периодическим выполнением: сохранять
данные в JSON или SQLite, выполнять работу по расписанию и возвращать
агрегированный результат. Формат сдачи: видео + код. Исходное задание находится
в `resources/task.md`.

## Решение

На отдельной учебной VM `yc` с Ubuntu 24.04 системный таймер раз в минуту
запускает `collect.py`. Он читает JSON-записи `ssh.service` из journald и
сохраняет события `Accepted` в отдельную SQLite-базу. Курсор журнала
сохраняется в той же базе: следующий запуск читает только новые записи.
Первый запуск импортирует доступные записи за последние 24 часа. Времена
хранятся в UTC, а MCP возвращает их в `Europe/Kirov` (UTC+03:00). Данные переживают перезапуск коллектора и VM,
пока доступны соответствующие записи системного журнала.

`server.py` предоставляет три read-only MCP-инструмента:

| Инструмент | Результат |
| --- | --- |
| `ssh_recent_logins(hours=1, limit=50)` | Список успешных SSH-аутентификаций: время, пользователь, IP, метод; общее число и признак сокращения выдачи |
| `ssh_login_summary(hours=24)` | Общее число входов, число уникальных IP, группировка по пользователям и часам Europe/Kirov |
| `ssh_collector_status()` | Время последнего сбора и границы сохранённых данных |

`hours` ограничен диапазоном 1–168, `limit` — 1–100. `Accepted` подтверждает
успешную SSH-аутентификацию; это не обязательно интерактивный терминальный
сеанс. Неудачные попытки и действия внутри сеанса не собираются. Если сборщик
не запускался или journald уже удалил старые записи, сводка не доказывает
отсутствие входов; для оценки полноты предусмотрено время последнего сбора.

Сервис запускается от `heimdall` с группой `systemd-journal`, без root.
MCP-сервер читает только SQLite. База находится в
`~/.local/state/ai-advent-day18/logins.sqlite3` с правами `0600` в каталоге
`0700`. Сетевой порт MCP не открывается: самостоятельный TUI дня 18 запускает
STDIO-сервер на VM через `ssh -T yc`. Код и зависимости дня 17 не изменены;
действующий VPS с WireGuard не используется.

Локальный `main.py` — Textual-приложение со списком MCP-инструментов и их
схемами, чатом с DeepSeek и цепочкой фактических LLM/MCP-вызовов. Сеанс
записывается в `sessions/*.jsonl` с правами `0600`. Каталог `sessions/` не
игнорируется Git: вместе с кодом можно сохранить полную историю демонстрации.
В журнале остаются вопросы, ответы, IP и имена пользователей; API-ключ и
SSH-ключ не записываются. Ранее сохранённая контрольная сессия и её описание
удалены по решению пользователя. Демонстрационная сессия сохранена в
`sessions/20260923-200600-60e62968.jsonl` и включена в Git.

## Локальные проверки

```bash
cd day-18
uv sync --locked
uv run --locked python -m unittest -v
uv run --locked python -m compileall -q agent.py check_mcp.py collect.py login_store.py main.py mcp_client.py server.py servers.py tool_metrics.py trace_log.py test_login_store.py test_tui.py
uv lock --check
```

Тесты используют временный журнал и SQLite; headless-тест TUI подменяет ответы
MCP и LLM. Реальный SSH-журнал и внешний API для этих тестов не нужны.

## Развёртывание на учебной VM

Код `collect.py`, `login_store.py`, `server.py`, `pyproject.toml` и `uv.lock`
размещён в `/home/heimdall/ai-advent-day18`. Зависимости установлены через
`uv sync --locked --python /usr/bin/python3.12`. Unit-файлы из `deploy/`
установлены в `/etc/systemd/system/`; таймер включён командой:

```bash
sudo systemctl enable --now ssh-login-collector.timer
```

Проверка на VM для демонстрации:

```bash
systemctl is-active ssh-login-collector.timer
systemctl list-timers ssh-login-collector.timer --no-pager
sudo journalctl -u ssh-login-collector.service -n 10 --no-pager
cd /home/heimdall/ai-advent-day18
~/.local/bin/uv run --locked --no-sync python check_mcp.py
```

Первые три команды показывают работающий планировщик и его повторные запуски.
`check_mcp.py` запускает локальный STDIO MCP-сервер, получает список трёх tools
и вызывает `ssh_collector_status`. MCP-процесс работает во время подключения
клиента, поэтому постоянно активного `ssh-login-mcp.service` в `systemd` нет.

На локальной машине запустить отдельный TUI дня 18:

```bash
cd day-18
uv run --locked python main.py
```

Выбрать «Yandex VM · SSH-входы», нажать «Получить инструменты» и спросить:
«Кто успешно входил по SSH на учебную VM за последний час? Покажи время и IP».
Для LLM нужен локальный `day-18/.env` с `DEEPSEEK_API_KEY` по образцу
`.env.example`. SSH-алиас `yc` должен работать через локальный SSH-агент.
Результаты MCP и вопросы сохраняются в локальном JSONL-журнале TUI и
передаются DeepSeek для ответа.

## Результат и выводы

23.09.2026 на отдельной VM таймер `ssh-login-collector.timer` был активен,
повторные запуски сборщика добавляли новые записи без повторного учёта.
`check_mcp.py` получил три MCP-инструмента и статус базы. Файл SQLite имеет
права `0600`. Действующий VPS с WireGuard не изменялся.

В сохранённой JSONL-сессии TUI агент дважды вызвал `ssh_recent_logins` и
`ssh_collector_status`. Первый запрос показал 44 входа в базе и последний вход
в 20:03:04 по `Europe/Kirov`; список был сокращён до 20 записей с явным
признаком сокращения. Во втором запросе база содержала 48 входов, список из
48 записей не был сокращён, последний вход произошёл в 20:08:16. Агент
сопоставил два результата и сообщил о четырёх новых входах того же пользователя
с того же IP. Это подтверждает работу периодического сбора, накопления данных
и ответа агента через MCP для показанного периода. История до доступного
снимка journald не восстанавливается; `Accepted` обозначает успешную
аутентификацию, а не действия внутри сеанса.

Локально прошли четыре unit/headless-теста, компиляция Python-файлов и проверка
`uv.lock`. Видео результата записано пользователем: MP4/H.264, 2560×1440,
4:00,398, один видеопоток, 13 151 817 байт. Удалённый файл на Яндекс Диске
совпал с локальным по размеру и MD5; публичные метаданные подтвердили имя,
`video/mp4` и статус `clean`. Визуальная проверка кадров не выполнялась.

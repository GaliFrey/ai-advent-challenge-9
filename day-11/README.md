# День 11. Явная модель памяти агента

Textual-приложение показывает один агент и три раздельных слоя памяти:

- **краткосрочная** — завершённые пары текущего диалога в scope сессии;
- **рабочая** — явно сохранённые данные активной задачи;
- **долговременная** — явно сохранённый профиль и устойчивые знания пользователя.

Справа одновременно видны все слои и их scope. Соседняя вкладка показывает последний фактический массив сообщений, отправленный DeepSeek. Он сохраняется вместе с выбранной сессией и восстанавливается при просмотре истории.

## Запуск

```bash
cd ~/Dev/AI_Advent_Challenge/day-11
uv sync --locked
cp .env.example .env
```

Добавить `DEEPSEEK_API_KEY` в `.env` и запустить:

```bash
uv run --locked python main.py
```

Локальная память по умолчанию сохраняется в `data/` и не добавляется в Git. Для отдельного эксперимента можно передать другой каталог:

```bash
uv run --locked python main.py --data-dir /tmp/day-11-memory
```

## Явная маршрутизация

- `Спросить` вызывает модель. Только успешно завершённая пара вопрос/ответ атомарно попадает в short-term текущей сессии.
- `В рабочую` без API-вызова сохраняет введённую заметку в scope активной задачи.
- `В долговременную` без API-вызова сохраняет заметку в scope пользователя.
- `Новая сессия` начинает пустую short-term, сохраняя working и long-term.
- `Новая задача` начинает пустые short-term и working, сохраняя long-term.
- Список `Задача` загружает последнюю сохранённую сессию выбранной задачи.
- Список `Сессия` открывает любой её сохранённый диалог; продолжить разговор можно прямо в нём.

Физически слои разделены:

```text
data/
├── short_term/<task_id>/<session_id>.json
├── working/<task_id>.json
└── long_term/<user_id>.json
```

Файл сессии атомарно хранит завершённые пары диалога и последний фактический API-prompt. Сессии ранней версии, содержавшие только массив диалога, продолжают открываться; для них prompt появится после следующего успешного ответа. Файлы из прежнего пути `short_term/<session_id>.json` остаются доступны внутри `task-01` и автоматически не перемещаются.

Рабочая и долговременная память включаются в системный prompt отдельными маркированными блоками недоверенных данных. Краткосрочная память передаётся как история ролей `user`/`assistant`.

## Автодемо

`Ctrl+D` или кнопка `Автодемо` выполняет шесть запросов:

1. спрашивает без памяти: «Какой цвет выбрать?»;
2. повторяет вопрос после long-term факта «любимый цвет пользователя — зелёный»;
3. добавляет working-контекст выбора цвета кнопки «Сохранить» и повторяет вопрос;
4. сохраняет в short-term просьбу называть цвет по-английски;
5. повторяет вопрос со всеми тремя слоями и получает максимально короткий ответ;
6. начинает новую сессию и повторяет вопрос без прежнего short-term формата.

После этого приложение переключается на новую задачу: её working и short-term пусты, а long-term пользователя сохраняется. Все созданные демо-сессии остаются в списке первой задачи, поэтому можно вернуться к каждому этапу и посмотреть его диалог. Автодемо запускается только с пустыми активными слоями, чтобы результат не зависел от старых данных.

Чтобы записать новый сценарий, не удаляя предыдущие результаты, можно запустить его в отдельном чистом хранилище:

```bash
uv run --locked python main.py --data-dir data/color-demo
```

## Фактический эксперимент

Ручной прогон на `deepseek-v4-flash` выполнил восемь запросов и последовательно показал границы памяти:

| Scope | Доступная память | Фактический результат |
| --- | --- | --- |
| `task-01 / session-01` | пусто | модель запросила назначение цвета и предложила общие варианты |
| `task-01 / session-02` | long-term | на общий вопрос ответила `Зелёный` |
| та же сессия | long-term + working | после требования для кнопки ответила `Синий` |
| та же сессия | все три слоя | временное указание изменило язык ответов на `Blue` и `Green` |
| `task-01 / session-03` | long-term + working, новая short-term | ответы вернулись к русским `Синий` и `Зелёный` |
| `task-02 / session-01` | long-term, пустая working | требование синего не перенеслось, ответ — `Зелёный` |

Одинаковый вопрос о цвете костюма получил `Green` внутри второй сессии и `Зелёный` после её смены. Одинаковый общий вопрос получил синий ответ в первой задаче и зелёный во второй. Это отдельно показывает влияние short-term, изоляцию working по задачам и сохранение long-term между задачами. Последний сохранённый prompt каждой сессии содержит именно те слои и сообщения, которые фактически были переданы API. Итоговый счётчик интерфейса — 1 724 токена.

## Проверки

```bash
uv run --locked python -m unittest -v
uv lock --check
```

Пройден 21 локальный тест: файловая изоляция scope, восстановление диалога и фактического prompt, сохранение пустых новых задач и сессий, совместимость с прежними форматом и расположением сессий, атомарность, повреждённый JSON, отсутствие записи при ошибке API, ручная маршрутизация без API и полный headless-сценарий автодемо.

Дополнительно выполнен реальный ручной прогон DeepSeek. Видео визуально проверено по кадрам на протяжении записи; секреты в выбранных кадрах не обнаружены.

Векторный поиск, RAG, автоматический классификатор памяти и state machine намеренно не добавлены: они не требуются для проверки трёх явных слоёв дня 11.

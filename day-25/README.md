# День 25 — RAG-чат с историей и памятью задачи

## Задание

Мини-чат хранит историю диалога, при каждом новом вопросе ищет контекст
через RAG, отвечает по найденной информации и выводит источники.
Усиление — память задачи: цель, уточнения, ограничения и термины.
Проверка — два длинных сценария по 10–15 сообщений. Формат сдачи — видео + код.
Оригинал задания хранится локально в `resources/task.md`.

## Решение

Самостоятельный uv-проект и полноэкранный Textual TUI по README репозитория.
Переиспользуются индекс дня 21, helpers дней 22–23 и контракт цитат дня 24.
Нужен весь репозиторий. Корпус — README дней 0–20; чаты, секреты и ресурсы
не индексируются. Код предыдущих дней не изменён.

Каждая реплика проходит:

1. Сохранение пользовательского сообщения.
2. Один вызов DeepSeek: обновление памяти, самостоятельный вопрос
   для разрешения местоимений и от одного до четырёх коротких поисковых запросов.
3. Проверка схемы памяти и происхождения её пунктов.
4. Новый поиск с общим бюджетом до 20 кандидатов, локальный reranker,
   отбор до пяти чанков при начальном пороге 0,10.
5. Ответ по текущим источникам с точными цитатами и проверка JSON-контракта,
   метаданных источников и дословного вхождения цитат в указанные чанки.

Самостоятельный вопрос содержит смысл реплики и условия ответа. Поисковые
запросы должны содержать предметные темы, без просьб «собери итог», «без кода»
и других условий оформления. Для сравнения предусмотрены отдельные запросы
по README каждой стороны; если день не установлен — поиск по всему корпусу.
Ограничение по источнику применяется до выбора top-K соответствующего поиска.
Общий бюджет распределяется между запросами; дубликаты удаляются.
Чанк может оцениваться по нескольким запросам: сохраняются все оценки и максимум.
Если итоговый K достаточен, отбор сохраняет хотя бы один прошедший порог чанк
каждой поисковой темы, затем дополняет контекст по оценке. Покрытие сравнения
никогда не отменяет порог.

Reranker — `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`, ревизия
`1427fd652930e4ba29e8149678df786c240d8825`, CPU, sigmoid, до 512 токенов
на пару. Длинные пары могут усекаться. Оценки не являются вероятностями
правильного ответа; порог 0,10 экспериментальный, оптимальность не установлена.
Индекс и кэш эмбеддингов находятся в дне 21, кэш reranker — в дне 23.

## История, память и источники

Диалог атомарно сохраняется после каждого этапа в `sessions/chat-*.json`
с правами 0600. Файл содержит вопросы, принятые ответы, исходные результаты
LLM, фактические запросы, чанки, проверки, метрики и снимки памяти.
Новый диалог начинает пустую историю и память; сохранённый можно открыть
и продолжить. Между разными диалогами память не переносится.

Модель получает последние три хода; текст каждого прошлого ответа ограничен
6000 символами. Полная история остаётся на диске. Память содержит `goal`,
`constraints`, `terms`, `clarifications`, `open_questions`: до одной цели
и до восьми пунктов остальных видов. Пункт содержит текст до 400 символов,
номер реплики и дословную цитату пользователя. Новый или изменённый пункт
должен происходить из текущей реплики; старый переносится без изменения.
Ошибка проверки оставляет прежнюю память и останавливает ход без поиска
и генерации. Проверка происхождения не доказывает правильность интерпретации.

Планировщик получает результаты ответов на открытые вопросы, включая старые
ходы вне окна истории. После принятого ответа `answered` без `clarification`
соответствующий вопрос автоматически удаляется из `open_questions`.
Частичные ответы, отказы и ошибки не удаляются автоматически, если планировщик
включил их в этот список. Полнота ответа определяется контрактом модели;
семантическая корректность не гарантируется. Общая цель не должна расширять
каждый локальный вопрос до сравнения всех дней.

История и память нужны для понимания запроса. Факты о репозитории подтверждаются
только текущими чанками; прошлый ответ не считается источником.
Ссылки отображаются вместе с номером хода (`4:S1`), чтобы номера источников
разных ответов не смешивались. Блок источников есть у каждого ответа.
При отказе он показывает «Подтверждающие источники не найдены» и уточнение.
Если ни один чанк не прошёл порог, генерация пропускается. Модель также может
отказаться при тематически близком, но недостаточном контексте.
Неверный формат или цитаты не показываются как принятый ответ.

## Подготовка и запуск

Нужны Python 3.12+, uv, индекс дня 21 и ключ DeepSeek.

```bash
cd day-25
uv sync --locked
test -e .env || cp .env.example .env
# Заполнить DEEPSEEK_API_KEY в .env; существующий файл не перезаписывать.
uv run --locked python main.py prepare
uv run --locked python main.py tui
```

`prepare` использует кэш reranker дня 23; при отсутствии скачивает модель.
Если индекс дня 21 отсутствует или устарел:

```bash
cd ../day-21
uv sync --locked
HF_HOME="$PWD/indexes/hf-cache" uv run --locked python indexer.py build
cd ../day-25
```

Модель задаётся `DEEPSEEK_MODEL`, по умолчанию `deepseek-flash`.
Системные переменные имеют приоритет; после изменения `.env` нужно
перезапустить приложение.

Обычная реплика — до двух платных вызовов: память/поиск и ответ.
При CLI-прогоне сценария добавляется отдельная оценка: до трёх на реплику,
до 36 на сценарий, до 72 на два сценария. При открытии интерфейса вызовов нет.
DeepSeek получает текущую реплику, память, последние три хода и результаты
открытых вопросов; для генерации — также найденные фрагменты README.
`temperature=0`, thinking отключено, явный `max_tokens` не задан;
таймаут запроса — 90 секунд. Автоматических повторов нет.

## Полноэкранный интерфейс

Ориентир для записи — 180×60 символов. Чат занимает две трети ширины,
память — треть. При ширине меньше 120 колонок боковая память скрывается,
а вкладка «Память подробно» остаётся доступна.

- **Диалог:** история, источники и память справа.
- **Источники и поиск:** выбор хода, исходная реплика, самостоятельный вопрос,
  фактические поисковые запросы, все кандидаты, оценки и причины отбора.
  Таблица и текст чанка занимают равные половины ширины; путь и раздел идут
  на разных строках, длинные названия переносятся. Enter на строке чанка
  показывает полный текст; ниже находятся цитаты и результаты проверки.
- **Память подробно:** состояние выбранного хода и цитаты пользователя.
- **Проверка сценария:** история ходов и доступные оценки LLM из CLI-отчёта.
  Клик, стрелки или Enter показывают оценку ниже без смены вкладки;
  кнопка «Источники выбранного хода» открывает поиск и цитаты этой реплики.
  Обновления диалога сохраняют выбранный для просмотра ход.
- **Настройки:** число кандидатов, итоговый K и порог. У каждого поля есть
  постоянная подпись, назначение, диапазон и значение по умолчанию.

В TUI вопросы вводятся вручную по одному; демо-кнопки и пакетного запуска нет.
Enter отправляет, Shift+Enter добавляет строку; Ctrl+Enter тоже отправляет,
если терминал различает сочетание. Сверху доступны новый диалог и открытие
сохранённого. Во время обработки видны этап и время; запуск, редактирование
и настройки заблокированы, вкладки доступны. «Остановить» прекращает следующие
этапы; текущий запрос может ждать до таймаута. Ctrl+Q во время обработки
запрашивает остановку, после завершения повторный Ctrl+Q закрывает приложение.

При ручной отправке отдельная LLM-оценка не запускается. Вкладка проверки
показывает отсутствие оценки, если её нет в открытом файле.

Диалоги в `sessions/` включены в Git по запросу пользователя для преподавателя.
В них сохранены реальные реплики и ответы с известными ошибками, без исправления
задним числом. Типичные признаки API-ключей, авторизации и приватных ключей
в двух публикуемых файлах не обнаружены. API-ключи и HTTP-заголовки приложение
не сохраняет, но текст реплик сохраняется полностью: секреты в него вводить нельзя.
Диагностические журналы без текстов диалога и сообщений исключений — в `logs/`.
Журналы, `.env`, видео и кэши исключены из Git; видео и задание — в `resources/`.

## CLI и сценарии

```bash
uv run --locked python main.py ask sessions/my-chat.json 'Как устроена память дня 11?'
uv run --locked python main.py ask sessions/my-chat.json 'А что сохраняется при новой сессии?'
uv run --locked python main.py show sessions/my-chat.json
uv run --locked python main.py tui sessions/my-chat.json
uv run --locked python main.py benchmark --scenario memory
uv run --locked python main.py benchmark --scenario mcp
# Оба, до 72 платных вызовов:
uv run --locked python main.py benchmark
```

`scenarios.py` содержит два сценария по 12 реплик: память дней 10–11 и MCP
дней 19–20. Каждый начинается отдельно. Есть ранняя цель, определения терминов,
местоимения, возврат к цели после нескольких подтем, смена ограничения
на девятом ходу и итоговый запрос. В MCP-сценарии есть вопрос о неподтверждённой
пропускной способности.

CLI-проверяющий получает пользовательскую историю, ожидаемую память текущего
хода, план, ответ и чанки; ожидания не передаются генератору. Он оценивает
подтверждение ответа (`support`), память (`memory`) и связность (`continuity`).
`pass` возможен только при трёх true. Используется та же модель с отдельной
инструкцией; это оценка LLM, а не гарантия правильности. Ошибка оценки сохраняется
как ошибка. Синтетические отчёты явно помечены и не продолжаются живыми сообщениями.

Всего: 24 поиска, 22 ответа с источниками, два отказа, 112 точных цитат,
47 LLM-вызовов и 136 488 токенов. Ошибок этапов нет. Формат, метаданные,
дословное вхождение цитат и происхождение памяти повторно проверены офлайн
на всех ходах. Это не независимая автоматическая проверка смысла.

В первом диалоге цель из реплики 1 и термин из реплики 3 сохранились до конца.
На реплике 9 ограничение «без примеров кода» заменено разрешением одного
примера только из документации. Реплика 10 корректно сравнивает ветвление
дня 10 со сменой задачи дня 11. Итоговая реплика 12 содержит сравнение
с источниками обоих дней; прежнего отказа по пустому контексту нет.
Примера кода не добавлено: он разрешён, но не обязателен.

Во втором диалоге на реплике 9 область и цель изменены на один день 20;
определение оркестрации и запрет инструкций установки сохранились.
Итоговая реплика 12 описывает порядок вызовов и передачу результатов
по дню 20 с источниками. На репликах 6 и 7 получены отказы: подтверждения
требований согласования и гарантии 1000 запросов/с в допущенном контексте нет.
На реплике 7 ни один чанк не прошёл порог, генерация пропущена.
В ручных диалогах отдельная LLM-оценка не выполнялась.

### Ограничения, обнаруженные в прогонах

- **Смысловая ошибка на реплике 4 первого диалога:** рабочая память ошибочно
  названа содержимым файла сессии. Цитата описывает историю сессии, а рабочая
  память по README дня 11 хранится в `data/working/<task_id>.json`.
  Точная цитата прошла проверку, но не подтверждает это утверждение.
- Найденные чанки местами обрывают предложения и таблицы. Поэтому ответы
  о путях и ролях серверов неполные; модель просит полный документ.
- `open_questions` пуст во всех снимках обоих диалогов, включая частичные
  ответы и отказы: планировщик не добавил нерешённые вопросы. Автоматическое
  удаление отвеченных вопросов не гарантирует полноту этого списка.
- Локальные вопросы не всегда сохраняют узкую область: реплика 5 первого
  диалога расширена на оба дня; на реплике 7 второго поиск выполнен по всему
  корпусу несмотря на ограничение днями 19–20. Итоги сохранили актуальные цели.
- Некоторые уточнения избыточны: модель требует авторское сравнение в одном
  разделе, хотя обе стороны уже подтверждены раздельными источниками.

Вывод: требование двух длинных сценариев выполнено; прогоны показывают историю,
поиск на каждом ходу, ответы с источниками и сохранение/смену цели, терминов
и ограничений. При этом полнота retrieval и смысловая корректность ответов
не гарантируются. Известная ошибка и частичные ответы сохранены для проверки.

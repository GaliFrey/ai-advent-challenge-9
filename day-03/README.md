# День 3. Разные способы рассуждения

## Задание

Взять одну логическую, алгоритмическую или аналитическую задачу и решить её через API четырьмя способами:

1. Получить прямой ответ без дополнительных инструкций о рассуждении.
2. Добавить инструкцию «решай пошагово».
3. Попросить модель сначала составить промпт для решения задачи, затем использовать созданный промпт.
4. Создать группу экспертов и получить решение от каждого участника.

После этого необходимо сравнить ответы и определить, какой способ дал наиболее точный результат. Формат сдачи: видео и код.

## Выбранная задача

Во всех четырёх способах используется одна задача:

```text
Используя числа 3, 3, 8 и 8 ровно по одному разу и только операции +, -, *, / и скобки, составь выражение, значение которого равно 24.

Последнюю непустую строку ответа запиши строго в формате:
FINAL: <выражение>
```

Требование к строке `FINAL` одинаково для всех способов и нужно для объективной автоматической проверки. Оно задаёт только формат результата, но не подсказывает способ рассуждения.

Задача выбрана потому, что ответ можно проверить программно: выражение должно использовать заданные числа ровно по одному разу и иметь точное значение 24.

## Реализация

`main.py` обращается к DeepSeek Chat Completions API и поддерживает четыре способа:

| Способ | Что отправляется модели | API-вызовов |
|---|---|---:|
| `direct` | Только исходная задача | 1 |
| `step-by-step` | Исходная задача и требование решать пошагово | 1 |
| `generated-prompt` | Сначала запрос на создание промпта, затем созданный промпт без ручного изменения | 2 |
| `experts` | Исходная задача и роли аналитика, инженера и критика | 1 |

Для чистоты сравнения во всех вызовах используются одинаковые настройки:

- модель `deepseek-v4-flash`;
- thinking mode отключён;
- `temperature=0`;
- `max_tokens=1200`;
- streaming отключён.

В консоли до каждого API-вызова показывается фактический промпт, а после вызова — полный ответ. Метаданные объединены в одну строку, успешная автоматическая проверка — в один итог. Исходная задача отдельно не дублируется, поскольку она уже видна внутри отправленного промпта. Подробности проверок выводятся только при ошибке.

### Автоматическая проверка

Программа извлекает выражение из единственной итоговой строки `FINAL`. Выражение разбирается через `ast.parse`, но не выполняется через небезопасный `eval`.

Проверяется, что:

- ответ содержит ровно одну итоговую строку;
- используются только целые числа и операции `+`, `-`, `*`, `/`;
- отсутствуют имена, функции и другие конструкции Python;
- литералы совпадают с набором `3, 3, 8, 8`;
- результат, вычисленный через `Fraction`, точно равен 24;
- в режиме экспертов присутствуют метки `ANALYST`, `ENGINEER` и `CRITIC`.

Результат каждого способа сохраняется в `resources/results/<method>.json`. Это локальные воспроизводимые данные без API-ключа; каталог `resources/` исключён из Git.

## Подготовка

День 3 является самостоятельным `uv`-проектом. Если активно окружение другого дня, сначала выйдите из него:

```bash
deactivate
```

Затем выполните:

```bash
cd ~/Dev/AI_Advent_Challenge/day-03
uv sync
cp .env.example .env
```

Запишите настоящий ключ в `day-03/.env`:

```dotenv
DEEPSEEK_API_KEY=...
```

Файл `.env` исключён из Git. Не показывайте его содержимое и API-ключ на видео.

## Запуск

Способы можно запускать по одному. Это удобно для записи нескольких фрагментов видео и позволяет контролировать число внешних запросов:

```bash
uv run python main.py run direct
uv run python main.py run step-by-step
uv run python main.py run generated-prompt
uv run python main.py run experts
```

После четырёх запусков детерминированное сравнение выполняется локально, без обращения к API:

```bash
uv run python main.py compare
```

Для качественного разбора можно добавить отдельный LLM-вызов:

```bash
uv run python main.py compare --with-llm
```

Сначала программа показывает локальную таблицу. Затем отдельная системная роль методолога получает полные сохранённые промпты, ответы и метрики всех стратегий. Она сравнивает точность, качество проверки и эффективность, но не может отменить результат локального математического валидатора.

Чтобы не загромождать видео, полный пакет данных не печатается повторно: консоль показывает системную роль, количество переданных материалов и итоговый ответ модели. LLM-анализ выполняет один дополнительный API-вызов и сохраняется локально в `resources/results/comparison.json`.

Можно запустить весь эксперимент одной командой. Она выполнит пять внешних API-вызовов и поэтому требует явного подтверждающего флага:

```bash
uv run python main.py run-all --yes
```

Вызов `run-all` без `--yes` завершается до обращения к API и показывает предупреждение.

## Фактический результат

Итоговый эксперимент записан 2 сентября 2026 года. Все ответы завершились с `finish_reason=stop` и прошли автоматическую проверку.

| Способ | Результат | Проверка | Вызовов | Входные токены | Выходные токены | Всего |
|---|---|---:|---:|---:|---:|---:|
| Прямой ответ | `8/(3-8/3)` | PASS | 1 | 79 | 26 | 105 |
| Пошаговое решение | `8/(3-8/3)` | PASS | 1 | 122 | 261 | 383 |
| Промпт, созданный моделью | `8 / (3 - 8/3)` | PASS | 2 | 494 | 306 | 800 |
| Группа экспертов | `8 / (3 - 8/3)` | PASS | 1 | 226 | 437 | 663 |

### Сравнение

- Все четыре способа получили математически корректный результат и выполнили контракт ответа, поэтому по точности этого запуска они равны.
- Прямой способ оказался самым эффективным: один вызов и 105 токенов.
- Пошаговый способ показал явную проверку вычисления и использовал 383 токена.
- Группа экспертов дала перекрёстную ролевую проверку и использовала 663 токена.
- Создание промпта моделью потребовало два вызова и 800 токенов, но не улучшило точность на этой задаче.

Отдельный LLM-анализ подтвердил локальный вывод и использовал ещё 2586 входных и 376 выходных токенов, всего 2962. Эти токены относятся к интерпретации эксперимента и не включены в таблицу четырёх способов.

### Как интерпретировать результат

- `PASS` означает, что ответ соблюдает формат `FINAL`, использует нужные числа и операции и имеет точное значение 24.
- Правильное выражение без обязательной строки `FINAL` математически верно, но не проходит полный контракт ответа.
- Созданный моделью промпт используется без ручной правки. Если он приводит к ошибке или конфликтующим инструкциям, это полноценный результат эксперимента, а не повод незаметно менять промпт или перезапускать только этот способ.
- Если несколько способов получили `PASS`, они равны по точности этого запуска; качество объяснения и расход токенов сравниваются отдельно.
- Один запуск не доказывает статистическую стабильность стратегии. Вывод относится только к ответам, показанным в итоговой записи.
- Токены дополнительного LLM-сравнения учитываются отдельно от четырёх исследуемых способов.
- При повторном запуске ответы и расход токенов могут измениться даже с `temperature=0` после обновления модели или серверной инфраструктуры.

## Автоматические проверки

Локальные тесты не обращаются к DeepSeek и не расходуют API-баланс:

```bash
uv run python -m unittest -v
```

Проверяются:

- содержание промптов четырёх способов;
- одинаковые настройки API;
- извлечение полной статистики токенов;
- точное вычисление корректного выражения;
- отклонение неправильных чисел и небезопасных Python-конструкций;
- обязательное положение `FINAL` в последней непустой строке;
- наличие всех ролей в режиме экспертов;
- два последовательных вызова и неизменная передача созданного промпта;
- локальное сохранение и сравнение четырёх результатов;
- защита полного запуска явным подтверждением;
- компактность консольного вывода и отсутствие повторного блока исходной задачи;
- отдельная системная роль для LLM-сравнения полных сохранённых ответов;
- повторная локальная проверка ответа перед передачей результата LLM-методологу.

## Сценарий записи видео

1. Показать формулировку задания и выбранную задачу в этом README.
2. Выполнить четыре команды `run` по очереди либо записать их отдельными фрагментами.
3. В каждом фрагменте показать название способа, отправленный промпт, ответ и результат автоматической проверки.
4. Для `generated-prompt` показать оба этапа: созданный промпт и решение этим промптом.
5. Выполнить `uv run python main.py compare --with-llm` и показать локальную таблицу вместе с выводом отдельной системной роли.
6. Озвучить вывод: объективную корректность подтверждает код, а LLM объясняет качественные различия способов.

Запись результата следует хранить локально как `resources/day-03-result.mp4`.

# День 26 — запуск локальной LLM

## Задание

Установить и запустить любую локальную LLM, проверить обращение через CLI
или HTTP API и выполнить минимум три запроса разной сложности.
Результат — модель работает локально и отвечает на запросы.
Исходная формулировка: «Видео + Код»; оригинал находится в `resources/task.md`.

проверить модель в любом клиенте (сообщение 4633), а на вопрос о необходимости

В этом дне используется готовый CLI Ollama; отдельное приложение не создавалось.

## Установка и запуск

Для Linux x86_64 с работающим драйвером NVIDIA, `curl`, `tar` и `zstd`.
Команды выполняются из корня репозитория; установка не создаёт системную службу.

```bash
mkdir -p day-26/resources/ollama-local
cd day-26/resources/ollama-local
curl -fL https://ollama.com/download/ollama-linux-amd64.tar.zst -o ollama.tar.zst
tar --zstd -xf ollama.tar.zst
rm ollama.tar.zst

OLLAMA_MODELS="$PWD/models" \
OLLAMA_CONTEXT_LENGTH=8192 \
OLLAMA_NUM_PARALLEL=1 \
./bin/ollama serve
```

Ссылка скачивает текущий выпуск; версия в записанном эксперименте — 0.35.1.
Установка в каталог не является контейнерной изоляцией: служебные файлы
и история CLI могут появиться в `~/.ollama`.

Во втором терминале из `day-26/resources/ollama-local/`:

```bash
./bin/ollama pull qwen3:14b
./bin/ollama --version
./bin/ollama list
./bin/ollama show qwen3:14b
./bin/ollama run qwen3:14b
```

Внутри чата:

```text
/set parameter num_ctx 8192
/set verbose
/set nothink
```

Перед независимыми запросами очищать контекст через `/clear`.
Для третьего запроса включить `/set think`.
После диалога выйти через `/bye` и проверить `./bin/ollama ps`.
Сервер останавливается через `Ctrl+C` в его терминале.

Для записи терминала используется `script` (пакет Fedora `util-linux-script`):

```bash
script -q -f -c bash "../session-$(date +%Y%m%d-%H%M%S).log"
```

В открытой оболочке выполнить команды и три запроса; после `/bye`
и `ollama ps` завершить запись командой `exit`.

## Эксперимент 05.10.2026

Источник результатов — `resources/session-20261005-205037.log`:
20:50:37–20:54:44, UTC+3, код завершения оболочки 0.
Выполнены ровно три запроса; между ними контекст очищался.

### 1. Объяснение по-русски, thinking выключен

Запрос:

> Объясни по-русски в трёх предложениях, чем локальная языковая модель отличается от облачной.

Ответ состоит из трёх предложений: локальные вычисления на устройстве,
приватность данных и сравнение с вычислениями на удалённых серверах.
Русский язык и ограничение длины соблюдены. Утверждение о большей
производительности облачных моделей — обобщение ответа, а не измеренный
в этом эксперименте результат сравнения.

### 2. Извлечение данных в JSON, thinking выключен

Запрос:

> Из текста «Анна заказала 3 книги по 450 рублей и 2 блокнота по 120 рублей» извлеки данные. Верни только JSON с полями customer, items и total. Каждый элемент items должен содержать name, quantity, unit_price и subtotal. Не добавляй Markdown и пояснения.

Модель вернула только JSON с нужными полями. `customer` — «Анна»;
книги: количество 3, цена 450, сумма 1350; блокноты: количество 2,
цена 120, сумма 240; `total` — 1590. Формат и арифметика корректны:
сохранённый ответ извлечён из журнала и проверен через `jq`.
Режим принудительного JSON не включался: модель соблюла текстовую инструкцию.

### 3. Исправление Python-функции, thinking включён

Запрос: найти ошибку, исправить функцию удаления повторов с сохранением
порядка первого появления, объяснить причину и показать результаты для
`[3, 1, 3, 2, 1]`, `[]` и `[5, 5, 5]`, без внешних библиотек.
Исходная функция:

```python
def unique_in_order(values):
    result = []
    for value in values:
        if value not in result:
            result.append(value)
        else:
            result.remove(value)
    return result
```

Модель верно обнаружила ошибочное удаление уже сохранённого элемента
и предложила убрать весь блок `else`. Для трёх примеров указаны правильные
результаты: `[3, 1, 2]`, `[]`, `[5]`. В рассуждениях также рассмотрен
пример `[5, 5, 6, 5]`, демонстрирующий нарушение порядка исходной функцией.
Исправление проверено по содержанию; Python-код в записанной сессии
не исполнялся. Проверка наличия элемента в списке оставляет квадратичную
сложность в худшем случае; оптимизация не требовалась запросом.

токенов соответственно. Это отдельные прогоны, не статистический бенчмарк.

## Результат и выводы

Все требования задания подтверждены сохранённой CLI-сессией:
модель запущена локально, доступна через CLI, отвечает на простой запрос
и выполнила три запроса разной сложности. В конце сессии подтверждены
`100% GPU` и контекст 8192. HTTP API в этой записи не проверялся;
по заданию достаточно CLI или API.

На данной конфигурации Qwen3-14B Q4_K_M дала правильные результаты
для JSON и исправления функции, соблюла язык и длину простого ответа.
Генерация составила 58–60 токенов/с. Ответ с thinking занял около 33 секунд
из-за длинных рассуждений; простые ответы без thinking — около двух секунд.
Сравнение режимов на одинаковом запросе не выполнялось, поэтому влияние
thinking на качество по этим трём заданиям не установлено.

Проверены лог сессии, требования ДЗ и контейнер видео через `ffprobe`:
MP4/H.264, 1706×1440, 223,476 секунды, один видеопоток, без аудио.
Визуальная проверка содержания видео не выполнялась.
При оформлении новых вызовов модели не было.

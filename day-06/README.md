# День 6. Первый агент

Одно терминальное приложение содержит два независимо создаваемых LLM-агента. Каждый агент принимает сообщения, сам формирует HTTP-запрос к DeepSeek, хранит собственную историю и возвращает ответ своей панели интерфейса.

## Требования задания

- принять запрос пользователя;
- вызвать LLM через API;
- получить и показать ответ;
- инкапсулировать запрос, ответ, конфигурацию и стек сообщений в отдельной сущности агента;
- предоставить видео и код.

Две панели расширяют минимальное требование и наглядно показывают изоляцию сессий внутри одного процесса. Постоянное хранение истории, инструменты и оркестрация в этом дне не используются.

## Архитектура

`AgentConfig` хранит модель, системный промпт, температуру и лимит ответа. Каждый экземпляр `Agent` владеет отдельными `messages` и статистикой. TUI отвечает только за ввод и отображение; формат DeepSeek API ему неизвестен.

```text
DualAgentApp
├── Session A → Agent A → messages A + stats A
└── Session B → Agent B → messages B + stats B
```

Оба агента используют один асинхронный HTTP-клиент, но не разделяют изменяемое состояние. Запросы разных панелей могут выполняться одновременно. Пока один агент отвечает, повторная отправка только в его панели заблокирована.

На ошибке пользовательское сообщение не записывается в контекст агента. Автоматических повторов нет: при сетевом сбое сервер уже мог обработать запрос.

## Подготовка и запуск

Требуются Python 3.11 или новее и `uv`.

```bash
cd ~/Dev/AI_Advent_Challenge/day-06
uv sync --locked
cp .env.example .env
```

Добавь настоящий ключ в локальный `.env`, затем запусти:

```bash
uv run python main.py
```

`.env` исключён из Git. Не показывай ключ в видео и логах.

## Демонстрация изоляции

1. В левой панели отправь: `Меня зовут Влад`.
2. Там же спроси: `Как меня зовут?` — агент должен использовать историю и ответить «Влад».
3. В правой панели спроси: `Как меня зовут?` — агент должен сообщить, что имя в этой сессии неизвестно.
4. Сравни независимые истории и блоки статистики.

Для каждой панели показаны модель, число успешных запросов и попыток, количество сообщений, токены последнего вызова и всей сессии, время и `finish_reason`.

`Вход` в последнем вызове — `prompt_tokens` всего отправленного контекста: системная инструкция, прежняя история и новое сообщение. Накопленные токены отражают расход API и поэтому повторно учитывают историю, пересланную в следующих запросах.

История хранится только в памяти экземпляра. После закрытия приложения обе сессии очищаются.

## Результат

## Проверки

```bash
uv run python -m unittest -v
```

Тесты используют `httpx.MockTransport` и не вызывают внешний API. Они проверяют:

- разные стеки сообщений двух агентов;
- передачу предыдущих реплик только внутри нужной сессии;
- независимую статистику токенов;
- отсутствие ошибочного запроса в истории;
- безопасный текст API-ошибки;
- наличие двух панелей и двух экземпляров агента в TUI.

Локальные тесты не подтверждают доступность DeepSeek API и внешний вид приложения в конкретном терминале.

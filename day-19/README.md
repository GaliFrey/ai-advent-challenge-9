# День 19 — композиция MCP-инструментов: SSH-отчёт

## Задание

Создать несколько MCP-инструментов и автоматическую цепочку: получение
данных → обработка → сохранение. Проверить выполнение цепочки и передачу
данных. Сдача: видео + код. Исходник: `resources/task.md`.

## Решение

Отдельный Textual TUI с DeepSeek и тремя инструментами MCP. Агент получает
один запрос и выбирает последовательные вызовы по описаниям инструментов:

1. `get_login_events(hours=24)` читает SQLite существующего сборщика дня 18
   на VM `yc`, возвращает идентификатор снимка, SHA256 и сведения о периоде.
2. `analyze_login_events(snapshot_id)` обрабатывает именно этот снимок:
   число аутентификаций, уникальных IP, группировки по пользователям и IP.
3. `save_report(report_id, filename)` сохраняет полученный отчёт в Markdown
   на VM и возвращает путь, размер и SHA256 файла.

События остаются в памяти MCP-процесса; модель передаёт идентификаторы из
ответов предыдущих инструментов. Анализатор не перечитывает изменившуюся
базу, сохранение не принимает произвольный текст от модели. Все три вызова
выполняются в одном MCP-подключении; при новом запросе создаётся новое.
Расчёты выполняет Python, выбор инструментов — LLM. Жёстко заданного
клиентского запуска трёх шагов нет; самостоятельный выбор LLM проверен реальным прогоном.

База читается в режиме read-only, сборщик дня 18 не изменяется. Период:
1–168 часов, максимум 10000 событий; при превышении цепочка завершается
ошибкой вместо отчёта по усечённым данным. При неизвестном времени сбора
или задержке более 180 секунд отчёт содержит предупреждение. `Accepted`
означает успешную аутентификацию, а не действия в сеансе; доступная история
journald может не покрывать весь период.

Отчёты: `/home/heimdall/ai-advent-day19/reports/`, права файлов `0600`.
Разрешено только простое ASCII-имя `.md`, без каталогов и перезаписи.
По умолчанию сервер создаёт имя `ssh-YYYY-MM-DD_HH-MM-SS.md` по времени
сохранения в Europe/Kirov, например `ssh-2026-09-24_18-45-30.md`.
Агент не передаёт `filename`, если пользователь не задал имя явно.
При совпадении имени (в том числе сохранении в ту же секунду) возвращается
ошибка без перезаписи существующего отчёта.
После `save_report` клиент автоматически скачивает файл по SSH в
`day-19/reports/` с тем же именем. Проверяются размер и SHA256, права локальной
копии — `0600`; существующий файл не перезаписывается. В TUI появляется шаг
скачивания и локальный путь в чате. Результат для LLM дополнен `local_path`;
`path` по-прежнему обозначает оригинал на VM. При сбое скачивания клиент
сообщает об ошибке и расположении сохранённого оригинала на VM.
Локальные отчёты исключены из Git.

## Подготовка и запуск

```bash
cd day-19
uv sync --locked
cp .env.example .env
# Заполнить DEEPSEEK_API_KEY локально.
uv run --locked python main.py
```

MCP запускается через SSH/STDIO с использованием алиаса `yc` и SSH-агента.
Отдельный сетевой порт не нужен. На VM после проверки ключа хоста следует
разместить `server.py`, `pyproject.toml`, `uv.lock` в
`/home/heimdall/ai-advent-day19` и выполнить:

```bash
cd /home/heimdall/ai-advent-day19
~/.local/bin/uv sync --locked --python /usr/bin/python3.12
```

Для нового сервера сначала настройте [сборщик дня 18](../day-18/README.md#развёртывание-на-учебной-vm).
Существующая база: `~/.local/state/ai-advent-day18/logins.sqlite3`.
Для тестовых окружений пути переопределяются переменными `DAY19_DB_PATH`
и `DAY19_REPORT_DIR`.

В TUI нажать «Получить инструменты», затем отправить:
«Подготовь и сохрани отчёт об SSH-входах за последние сутки».
Верхний блок инструментов занимает 9 строк. Справа в «TURN · ШАГИ»
Turn увеличивается при каждом обращении к LLM, включая раунды внутри одного
пользовательского запроса. Ответ LLM и связанные вызовы/результаты MCP
относятся к тому же Turn. Нумерация продолжается между запросами пользователя;
новое получение tools сбрасывает историю и счётчики. Поле ввода при запуске
заполнено текстом «Подготовь и сохрани отчёт об SSH-входах за последние сутки». Выбор пункта
показывает только его подробности. При просмотре старого шага новые события
не переключают выбор; на последнем шаге работает автоматическое следование.
Полные промпты остаются доступны в соответствующих шагах и JSONL.
Для видео показать три вызова с идентификаторами, шаг скачивания и локальный файл.
Полные запросы, ответы и результаты записываются в `sessions/*.jsonl`;
журнал может содержать IP и имена пользователей. Ключ API не записывается.

## Проверки и состояние

```bash
cd day-19
uv run --locked python -m unittest -v
uv run --locked python -m compileall -q . -x '/\.venv/'
uv lock --check
```

Интеграционный тест запускает настоящий STDIO MCP-сервер с временной SQLite,
а ответы LLM подменяет. Между первым и вторым шагами база очищается:
отчёт должен сохранить исходные три события. Проверяются передача ID,
агрегации, SHA256 файла, права, пустая выборка, неверные ID, отказ от
перезаписи и выхода из каталога. Отдельно проверяются остановка агента
при ошибке MCP и TUI в headless-режиме.

24.09.2026 выполнено развёртывание на VM `yc` (Ubuntu 24.04,
Python 3.12.3). На этой VM не было прежнего окружения, поэтому установлен
uv 0.12.18, размещён сборщик из дня 18 и включён минутный systemd-таймер.
Первый сбор сохранил 4 входа, следующий — ещё 4. История прежней VM
не восстанавливалась. Локальные файлы дня 18 не изменялись.

Прошли 5 локальных unit/integration/headless-тестов, компиляция и проверка
`uv.lock`. Проверены также скачивание, права локальной копии, отказ при
неверном SHA256 и недопустимом пути.

## Результат и выводы

В репозитории сохранены два реальных сеанса TUI:

| Сеанс | Входы | Уникальные IP | Локальный отчёт |
| --- | ---: | ---: | --- |
| [19:13](sessions/20260924-191330-20324cfa.jsonl) | 22 | 1 | `reports/ssh-2026-09-24_19-13-50.md` |
| [19:14](sessions/20260924-191459-705d67d6.jsonl) | 25 | 1 | `reports/ssh-2026-09-24_19-15-16.md` |

В каждом сеансе один запрос пользователя привёл к последовательным вызовам
`get_login_events → analyze_login_events → save_report`, затем файл был
автоматически скачан. Проверка сохранённых JSONL подтвердила передачу точных
ID, совпадение SHA256 снимка между этапами и согласованность итогов с
группировками. Обе локальные копии имеют размер 767 байт; их SHA256 совпали
с метаданными MCP и событиями завершения скачивания.

Цепочка демонстрирует композицию зависимых MCP-инструментов: следующий шаг
использует результат предыдущего, а неизменяемый снимок сохраняет
согласованность расчётов при новых входах на сервер. Выбор шагов делает LLM,
расчёты и запись выполняет код. Два успешных сеанса не гарантируют правильный
выбор инструментов для любого запроса. Отчёты описывают только сохранённые
аутентификации в доступной истории; они не доказывают полноту SSH-аудита.

Видео записано пользователем: MP4/H.264, 2560×1440, 3:50,632, один видеопоток,
18 620 146 байт. После загрузки на Яндекс Диск размер и MD5 совпали с локальным
файлом; публичные метаданные дополнительно подтвердили SHA256, имя,
`video/mp4` и статус `clean`. Визуальная проверка кадров не выполнялась.
Повторные LLM-вызовы при публикации не выполнялись.

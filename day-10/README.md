# День 10. Стратегии управления контекстом

Textual-приложение сравнивает три независимые сессии:

- **Sliding Window** передаёт модели только последние N сообщений;
- **Sticky Facts** передаёт актуальные facts и последние N сообщений;
- **Branching** создаёт две независимые ветки от общего checkpoint.

В каждой вкладке слева находится чат, справа — состояние памяти и последний контекст, отправленный в API. Четвёртая вкладка показывает общее сравнение.

## Запуск

```bash
cd ~/Dev/AI_Advent_Challenge/day-10
uv sync --locked
cp .env.example .env
```

Добавить `DEEPSEEK_API_KEY` в `.env` и запустить:

```bash
uv run --locked python main.py
```

`Ctrl+D` запускает автоматическое демо из 49 API-вызовов. После него полный JSON-отчёт сохраняется в `results/`.

## Эксперимент

Все стратегии работали с одним сценарием подготовки конференции. Ранние сообщения содержали код проекта и требования площадки, более поздние — изменённые дату, бюджет, подрядчика и открытый вопрос.

Для Branching после шести общих сообщений создавались две несовместимые версии проекта. Один контрольный вопрос задавался отдельно в каждой ветке.

Параметры прогона:

- модель `deepseek-v4-flash`;
- `temperature=0`;
- последние `N=6` сообщений;
- 49 успешных API-вызовов.

Исходный отчёт: [`results/demo-20260912T173450-295356Z.json`](results/demo-20260912T173450-295356Z.json).

## Результаты

| Стратегия | Качество | Рабочие токены | Служебные токены | Общий расход | Последний prompt |
| --- | ---: | ---: | ---: | ---: | ---: |
| Sliding Window | 3/7 | 2 987 | 0 | 2 987 | 354 |
| Sticky Facts | 7/7 | 4 930 | 5 313 | 10 243 | 581 |
| Branching, обе ветки | 7/7 вручную | 7 322 | 0 | 7 322 | 712 |

Автоматическая проверка поставила каждой ветке Branching 6/7. Это формальное расхождение, а не потеря факта: модель указала `ИНТЕРНЕТ=две независимые линии`, тогда как строковый валидатор искал полную фразу «две независимые линии интернета». Поле ответа уже задавало предмет, поэтому при ручной проверке обе ветки содержательно дали 7/7.

Ветки не смешались: проверки отсутствия даты, бюджета, подрядчика и открытого вопроса соседней версии прошли 4/4 для A и 4/4 для B.

Стоимость Branching распределилась так:

| Общий префикс | 1 537 |
| Ветка A после checkpoint | 2 907 |
| Ветка B после checkpoint | 2 878 |
| Одна версия A с общим префиксом | 4 444 |

## Вывод

Sliding Window оказался самым дешёвым и простым вариантом, но потерял четыре из семи проверяемых сведений: код проекта, дату и оба ранних требования площадки. Он подходит, когда важна только недавняя часть разговора.

Sticky Facts единственный полностью сохранил линейную историю при коротком окне. За стабильность пришлось заплатить: общий расход оказался в 3,4 раза выше Sliding Window, потому что после каждого сообщения выполнялся дополнительный запрос для обновления facts. В коротком диалоге это механизм памяти, а не экономии токенов.

Branching корректно сохранил общий контекст и две несовместимые версии без взаимного загрязнения. Он удобнее всего для параллельного исследования альтернатив, но не заменяет Sliding Window или Facts и сам по себе не сокращает контекст. Общий префикс был обработан один раз, поэтому две ветки вместе стоили меньше, чем два полностью независимых прогона тех же версий.

Итог: универсального победителя нет. Sliding Window оптимален по цене, Facts — по сохранению важных сведений в линейном диалоге, Branching — по работе с альтернативными решениями.

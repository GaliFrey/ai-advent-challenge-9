# День 17 — MCP-инструмент Datex и агент в TUI

## Задание

Реализовать свой MCP-сервер вокруг API, описать параметры инструмента и
возвращаемый результат, подключить инструмент к агенту и показать вызов из
приложения. Формат сдачи: видео + код. Исходное задание хранится локально в
`resources/task.md`.

## Что сделано

Самостоятельный `uv`-проект с Textual-интерфейсом. Верхняя часть TUI продолжает
функциональность дня 16: выбор MCP-сервера, запрос `tools/list`, список
инструментов, описание, `inputSchema` и оценка объёма их определений. Доступны:

| Сервер | Транспорт |
| --- | --- |
| Datex · локальный | STDIO, `server.py` |
| Microsoft Learn | Streamable HTTP |
| DeepWiki | Streamable HTTP |
| Cloudflare Docs | Streamable HTTP |

Нижняя часть — полноценный чат. После получения tools пользователь задаёт
вопрос; агент передаёт доступные инструменты модели DeepSeek и исполняет её
`tool_calls` через выбранный MCP-сервер. Слева виден диалог, справа —
прокручиваемая цепочка: полный JSON каждого запроса и ответа LLM, вызовы MCP
с параметрами, результаты инструментов и ошибки. В цепочке показаны именно
фактически отправленные и полученные данные; API-ключ туда не попадает.
История чата сохраняется в памяти для следующих вопросов и сбрасывается при
смене сервера. Во время запросов конфликтующие элементы интерфейса заблокированы.

### Сохранение цепочки

Каждый запуск TUI автоматически создаёт отдельный файл
`resources/logs/YYYYMMDD-HHMMSS-XXXXXXXX.jsonl`. Его точный путь показан в
интерфейсе под метрикой tools. Каждая строка — JSON-событие с временем,
сервером, типом и данными: запрос/ответ LLM, вызов/результат MCP, ошибка,
смена сервера. Запись выполняется после каждого события; смена сервера
очищает панели TUI, но не этот файл. Права нового файла — `0600`.

Из каталога `day-17` файлы можно найти командой `ls -lt resources/logs/`, а
затем открыть нужный `.jsonl` редактором или `less`. Логи содержат вопросы и
текст результатов инструментов, поэтому локально исключены из Git. API-ключ
и HTTP-заголовок авторизации в цепочку не записываются. Сеансы, выполненные
до добавления автолога, восстановить нельзя.

Локальный сервер Datex предоставляет:

| Инструмент | Параметры | Результат |
| --- | --- | --- |
| `datex_search` | `query: str`, `limit: int = 3` (1–3) | Статьи с ID, заголовком, фрагментом и URL |
| `datex_read` | `document_id: str` | Текст статьи до 6000 символов, URL, ID снимка и признак сокращения |
| `datex_status` | нет | ID снимка, число документов и известные пробелы |

Индекс открывается только на чтение. Запросы к SQLite параметризованы;
длина параметров ограничена. Если MCP-результат длиннее 24 000 символов,
панель цепочки показывает его целиком, а модель получает первые 24 000
символов с явной отметкой об этом. Число раундов LLM ограничено шестью, а
число фактических MCP-вызовов на вопрос — четырьмя. Для локального Datex
дополнительно разрешены не более двух поисков и двух чтений. Повторный поиск
после непустой выдачи доступен только после чтения найденной статьи.
Для обычных вопросов по API служебный `datex_status` не передаётся модели;
его схема остаётся видимой в TUI, а модель получает его при вопросах о
состоянии корпуса или снимка. После исчерпания бюджета модель должна дать
итог по полученным данным; служебную разметку вместо ответа приложение
не выдаёт пользователю.
Текст документации считается данными, а не инструкциями модели.

## Корпус

`corpus/datex-index.sqlite3` — побайтовая копия одного SQLite/FTS5-индекса
публичной справки Datex из `websoft-devkit`, снимок
`20260921T203254.308820Z`. SHA-256 индекса:
`52d205b967e22eaa4a0b899a72c90a7281ecb7b3558f79b4e5ac0d033a93c5c3`.
Рядом находится `snapshot.json`. В индексе 1774 документа; зафиксированы 13
ошибок HTTP 500. Отсутствие совпадения не доказывает отсутствия API.
Версия целевой сборки WebSoft неизвестна. Для запуска не нужен исходный
`websoft-devkit`; его файлы не изменялись.

## Запуск

Нужны Python 3.12+, `uv` и SQLite с FTS5:

```bash
cd day-17
uv sync --locked
uv run --locked python main.py
```

TUI открывается **без аргументов**. Сначала выберите сервер и нажмите
`Получить инструменты`. Для чата создайте локальный `day-17/.env` по
`.env.example` и задайте `DEEPSEEK_API_KEY`. Просмотр tools работает без ключа;
чат использует внешний DeepSeek API. Выход — `Ctrl+Q`. Рекомендуемый размер
терминала: от 110 столбцов и 36 строк.

В запросах модели используется `deepseek-flash` и `tool_choice=auto`:
текущий режим DeepSeek отклоняет `required`. Описание формата function tools —
в [документации DeepSeek](https://api-docs.deepseek.com/guides/tool_calls/).
Модель может ответить без вызова tools; панель цепочки покажет отсутствие
вызова. Для демонстрации задайте вопрос о конкретном API из Datex.

## Проверки

22.09.2026 локальный Datex MCP вернул три tools. Публичные серверы также
вернули списки: Microsoft Learn — 3, DeepWiki — 3, Cloudflare Docs — 2.
При повторной проверке Cloudflare Docs не ответил за 20 секунд; его
доступность зависит от внешнего сервиса, и запрос можно повторить в TUI.
Headless-тест TUI проверил выбор сервера, показ схемы, чат и видимую цепочку;
интеграционный тест проверил передачу результатов `datex_search` и
`datex_read` в последующие запросы модели.

Реальный вопрос об `ArraySort()` был отправлен через headless TUI с выбранным
Datex: интерфейс показал `LLM REQUEST`, `LLM RESPONSE`, `MCP CALL`,
`MCP RESULT`, а финальный ответ содержал ссылку на статью Datex. Это проверка
полного маршрута с внешним LLM. Интерактивная визуальная проверка терминала
не проводилась.

После оптимизации повторён вопрос «Какие функции есть в Datex для работы по
сортировке массивов?». В одном контрольном прогоне агент сделал один поиск,
прочитал `ArraySort()` и `ArraySortExt()`, затем ответил со ссылками на обе
статьи. Это заняло 3 запроса LLM, 3 MCP-вызова и 3939 токенов
(3280 входных, 659 выходных). В прежнем сохранённом прогоне того же вопроса
было 5 запросов LLM, 7 MCP-вызовов и 23 932 токена. Разница относится к двум
конкретным прогонам; число ходов модели может меняться.

```bash
uv run --locked python -m unittest -v
uv run --locked python -m compileall -q agent.py corpus.py main.py mcp_client.py server.py servers.py tool_metrics.py trace_log.py test_agent.py test_app.py test_corpus.py
uv lock --check
```

## Результат и выводы

Контрольный прогон подтверждает полный маршрут задания: приложение получает
описания инструментов локального MCP-сервера, модель вызывает `datex_search`
и `datex_read`, получает тексты статей и отвечает со ссылками на источники.
Для вопроса о сортировке массивов сохранённый лог фиксирует 3 запроса LLM,
3 вызова MCP и 3939 токенов. Ограничения на число вызовов и размер выдачи
сдерживают расход в этом сценарии; фактический расход других вопросов зависит
от ответов модели и объёма найденных документов.

[Видео результата](https://yadi.sk/i/luy9n2phCwBYhg) опубликовано на Яндекс
Диске. Локальный MP4/H.264 имеет разрешение 2560×1440, длительность
2:14,162 и размер 11 963 747 байт. Удалённые размер и MD5 совпали с
локальными; публичные метаданные подтвердили имя, тип `video/mp4` и статус
проверки `clean`. Содержимое кадров отдельно не проверялось.

## Сценарий демонстрации

1. Запустить `uv run --locked python main.py`.
2. Выбрать локальный Datex, нажать `Получить инструменты`, показать
   `datex_search` и его `inputSchema`.
3. Спросить: «Что делает функция ArraySort в SP-XML Script? Укажи источник».
4. В панели цепочки показать фактический запрос модели, `datex_search`,
   `datex_read`, переданные результаты и ответ со ссылкой.

Видео и локальные JSONL-логи находятся в `resources/` и исключены из Git.

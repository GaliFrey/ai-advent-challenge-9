# День 31 — ассистент разработчика для Guitar Trainer

Видео: [демонстрация дня 31 без звука](https://disk.yandex.ru/i/6Bb7UemTRVALhw).

## Задание

Подключить README и папку docs проекта к RAG, получать текущую Git-ветку
через MCP и реализовать `/help`, отвечающий о структуре проекта с учётом
документации и контекста. Формат сдачи — видео + код. Оригинал задания
хранится локально в `resources/task.md`.

## Проект и решение

Guitar Trainer остаётся отдельным Git-репозиторием. Его код не копируется
в репозиторий челленджа. Начальное состояние приложения — `3d0b39d`;
README разделён на `docs/architecture.md`, `docs/audio.md` и
`docs/development.md` без изменения функций приложения. Для запуска
ассистента нужен весь репозиторий челленджа и отдельный проект с подготовленной
документацией. Guitar Trainer в эту публикацию не входит: он остаётся локальным
самостоятельным репозиторием. Вместо него можно указать любой доступный
Git-проект с README.md и docs через `--project`; соседний каталог — лишь
настройка по умолчанию, а не скачиваемая зависимость на момент сдачи дня 31.
В дне 32 проект опубликован отдельно:
[Guitar Trainer](https://github.com/GaliFrey/guitar-trainer).
Его можно клонировать и передать путь через `--project`.

Самостоятельный Python/uv-проект. Из дня 21 переиспользуются функции
разбиения, SQLite-схема и семантический поиск; его фиксированный корпус
README дней 0–20 не используется. Поэтому нужен весь репозиторий челленджа.
У предыдущих дней код не меняется.

На каждом вопросе:

1. Проверяются принадлежность индекса проекту и SHA-256 текущих документов.
2. Через настоящий MCP stdio выполняются initialize, tools/list и два
   tools/call: `get_project_context` и `list_project_files`.
3. В документации ищутся семантически близкие фрагменты. Короткие разделы
   до 1800 символов раскрываются целиком; повторяющиеся контексты удаляются.
4. DeepSeek получает вопрос, текущие источники документации и Git-контекст.
5. Проверяются JSON-контракт, ссылки и точное вхождение каждой цитаты в её
   источник. Отклонённый ответ не показывается как принятый; автоматических
   повторов облачных запросов нет.

По умолчанию терминал показывает краткий ответ, затем использованные источники
и фрагмент чанка до 160 символов для каждого источника. Фрагмент берётся из
проверенной цитаты, пробелы объединяются для компактного вывода; длинный текст
показывается с многоточием. Ниже — одна строка MCP с веткой/HEAD.
Полный список файлов, найденные тексты
и цитаты доступны через `--details`; они не повторяются в обычном выводе.
Нет истории диалога: каждый вопрос независим.

## Подготовка

Нужны Git, uv и Python 3.12+. Для тестов Guitar Trainer — Node.js 22+.
Проверенное окружение ассистента: Python 3.14, MCP SDK 1.30.0.

```bash
cd day-31
uv sync --locked
test -e .env || cp .env.example .env
```

Задайте `DEEPSEEK_API_KEY` в локальном `.env` или окружении.
`DEEPSEEK_MODEL` по умолчанию — `deepseek-flash`. Ключи в ответы и отчёты
не записываются; дочерний MCP-процесс не получает облачный ключ.
DeepSeek получает выбранные документы и результаты Git-инструментов,
а не весь код приложения. Эти запросы используют платный API.

По умолчанию ищется соседний репозиторий `../../guitar-trainer` относительно
`day-31`. Его путь можно изменить через `DAY31_PROJECT` в `.env` либо
параметр `--project` (параметр имеет приоритет). Для другого проекта нужны
README.md и хотя бы один Markdown-документ в docs.

```bash
uv run --locked python main.py --project /home/heimdall/Dev/guitar-trainer --index
uv run --locked python main.py --project /home/heimdall/Dev/guitar-trainer
```

В цикле ввода:

```text
/help
/help Какой командой запускать unit-тесты и какая версия Node.js нужна?
/help Как YIN, Worker и AudioWorklet участвуют в распознавании высоты ноты?
/help Какой точный годовой доход от платных подписок за 2025 год?
/exit
```

`/help` без вопроса запрашивает обзор структуры. Один вопрос можно выполнить
без цикла; ошибка или отклонённый ответ дают ненулевой код выхода:

```bash
uv run --locked python main.py '/help'
uv run --locked python main.py '/help Как устроена аудиообработка?'
# Подробный вывод для проверки источников и демонстрации:
uv run --locked python main.py --details '/help'
# Настоящий MCP и RAG, без обращения к DeepSeek:
uv run --locked python main.py --retrieve-only '/help'
```

## Индекс и источники

Корпус ограничен README.md и видимыми `docs/**/*.md` выбранного приложения.
Исходники, PLAN.md, чаты, env, скрытые документы, видео и другие репозитории
в индекс не попадают. Символические ссылки в документации отклоняются.
Максимальный размер отдельного документа — 1 МБ.

Эмбеддинги локальные: `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`,
ревизия `e8f8c211226b894fcb81acc59f3b34ba3efd5f42`, CPU. Первое получение
модели может потребовать загрузки Hugging Face; при готовом кэше она работает
без сети. Чанки `section_windows` ограничены 112 токенами модели, с
перекрытием. Нормализованные векторы хранятся в SQLite; поиск использует
скалярное произведение. Из 16 кандидатов отбираются до восьми уникальных
контекстов после раскрытия коротких разделов. Score не является вероятностью
правильного ответа; отсечения по экспериментальному порогу нет.

Индекс создаётся атомарно в `resources/indexes`, отдельно для каждого
абсолютного пути проекта, с правами 0600. Добавление, изменение или удаление
документа требует повторного `--index`. До переиндексации вопрос отклоняется
без облачного запроса. При смене местоположения проекта нужен новый индекс.
Повреждённый SQLite-файл или неверная схема также дают сообщение о необходимости
переиндексации, без необработанного traceback.

Источники `S1…S8` относятся к документации; `G1` — ветка/HEAD, `G2` — файлы.
Git-ветка относится к репозиторию, содержащему приложение. Для вложенного
приложения это ветка общего репозитория; каталог показан отдельно.
Список файлов ограничен 500 отслеживаемыми путями приложения, с признаком
усечения. Новые неотслеживаемые документы могут войти в RAG, но появятся
в Git-списке только после добавления в Git. Документация читается из текущей
рабочей копии; HEAD обозначает последний коммит, а не снимок этих документов.

## Проверки

```bash
uv run --locked python -m unittest -v
uv run --locked python -m py_compile shared.py index.py clients.py project_mcp.py assistant.py main.py verify_live.py test_assistant.py
uv lock --check
```

Офлайн-тесты подменяют эмбеддинги и DeepSeek, но MCP проверяется реальным
stdio-соединением во временном репозитории: вложенный проект, смена ветки,
detached HEAD, отслеживаемые файлы и ошибка вне Git. Проверены изменение
корпуса, границы источников, несуществующие ссылки и поддельные цитаты.
HTTP-вызовы в provider-тестах выполняются через MockTransport, без сети.

Реальная приёмка делает четыре платных запроса, по одному на случай,
без автоматических повторов:

```bash
uv run --locked python verify_live.py
```

Проверяет формат/цитаты, ожидаемый отказ и использование соответствующих
документов. Смысловую точность ответа нужно дополнительно сверить с текстами.
Индивидуальные JSON-отчёты и сводка сохраняются в `resources/logs` с правами
0600, вне Git; это диагностика, а не память следующего вопроса.

В этом окружении sandbox препятствует работе дочернего MCP-процесса;
проверка stdio выполнена вне sandbox. Приложение для обхода ограничения
не менялось. При ошибках MCP или сети ответ не подменяется успешным.

## Сдача и ограничения

### Проверенный результат 13.10.2026

- Индекс содержит 4 документа и 141 embedding-чанк; модель взята из локального
  кэша, при построении индекса платных запросов не было.
- В записанной демонстрации три вопроса прошли проверку: `/help` объясняет
  компоненты и структуру; вопрос об YIN/Worker/AudioWorklet получает ответ
  из docs/audio.md; вопрос о доходе за 2025 год получает отказ. Модель —
  `deepseek-flash`, все три ответа завершились `finish_reason=stop`.
- MCP прочитал `main`, HEAD `208474a` и 46 отслеживаемых файлов отдельного
  Guitar Trainer. README/docs уже включены в этот коммит приложения.
- Сохранённые ответы и цитаты перепроверены текущим валидатором без API,
  смысл ответов сверён с источниками. Локальные отчёты демонстрации:
  `resources/logs/20261013T164055Z-d826e187.json`,
  `20261013T164116Z-76b69d27.json`, `20261013T164147Z-1b2b2a97.json`.
- Перед публикацией прошёл полный набор из 23 офлайн-тестов. При ревью
  исправлена обработка повреждённого индекса; после изменения прошли
  10 тестов корпуса, включая новый регрессионный случай (24 разных теста
  всего). Также прошли Python-компиляция и проверка uv.lock. Ранее успешно
  выполнен `npm test` приложения: 15 файловых тестов, без браузера.
- Видео проверено через ffprobe и выборочные кадры: MP4/H.264, 2560×1440,
  189,9257 с (3:09), один видеопоток без аудио. Видны подготовка индекса,
  документация, ответы с источниками и короткими фрагментами, MCP, отказ
  и завершение CLI. В конце показан экран приложения; это не проверка
  распознавания звука с настоящей гитарой. Просмотрено шесть кадров через
  30 секунд, а не каждый кадр записи; на просмотренных кадрах ключей нет.
- Видео загружено пользователем. Публичная страница доступна без авторизации;
  имя `day-31-result.mp4`, размер 31 827 524 байта, MD5 и SHA-256 совпадают
  с локальным файлом, `antivirus_status=clean`.

### Выводы

README и docs дают основания для ответов о структуре и аудиообработке,
а MCP добавляет актуальный Git-контекст без копирования приложения.
Краткий вывод показывает ответ, источник и подтверждающий фрагмент;
подробности доступны через `--details`. Отсутствие сведений о доходе
привело к отказу, а не к придуманным числам.

При разработке обзор структуры сначала отклонялся из-за цитат, склеенных
из соседних чанков. Раскрытие целого короткого раздела устранило проблему
в проверенной выборке без ослабления валидатора. Три успешных вопроса
не доказывают правильность произвольных будущих ответов.

### Ограничения

Проверка точного вхождения цитат не доказывает, что все утверждения следуют
из них, и не гарантирует правильность будущих ответов. Без сведений модель
должна возвращать отказ; это инструкция, а не семантический валидатор.
Экспериментальная проверка струны на настоящей гитаре остаётся непроверенной,
как указано в документации приложения. Новые браузерные и микрофонные
прогоны при публикации не запускались; визуально проверены только кадры
записанного видео. Новых платных LLM-запросов для публикации не выполнялось.
CI и автоматическое PR-ревью относятся к следующему дню.

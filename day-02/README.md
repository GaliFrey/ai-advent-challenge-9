# День 2. Управление ответом LLM

## Задание

Отправить один и тот же запрос в LLM дважды и сравнить результаты:

1. Свободный ответ без явных ограничений.
2. Контролируемый ответ с описанием формата, ограничением длины и условием завершения.

Формат сдачи: видео и код.

## Реализация

`main.py` отправляет запрос в DeepSeek Chat Completions API. Пользовательский текст в обоих вызовах полностью совпадает; различаются только настройки управления ответом.

| Настройка | `free` | `controlled` |
|---|---|---|
| Пользовательский запрос | Один и тот же | Один и тот же |
| Формат | Не задан | Фиксированный Markdown |
| Длина | Не ограничена явно | `max_tokens=220`, до 5 ингредиентов и 4 шагов |
| Завершение | Не задано явно | `stop=["<END>"]` |

Доступны три режима:

- `free` выполняет только свободный вызов;
- `controlled` выполняет только контролируемый вызов;
- `compare` последовательно выполняет оба вызова и используется по умолчанию.

После каждого ответа выводятся `completion_tokens` и `finish_reason`, полученные от API.

Каждый контролируемый ответ дополнительно проходит локальную валидацию. Если хотя бы одна проверка завершается с `FAIL`, программа возвращает ненулевой код выхода.

## Как работает контролируемый ответ

Системная инструкция задаёт точную Markdown-структуру:

```text
# Название

## Ингредиенты
- не более пяти пунктов

## Приготовление
1. не более четырёх шагов
```

Ограничение `max_tokens=220` задаёт верхнюю границу числа генерируемых токенов. Это не количество символов или слов. Дополнительные смысловые ограничения помогают модели закончить ответ до достижения технического лимита.

После последнего шага модель должна сгенерировать `<END>`. API получает тот же маркер в параметре `stop`, перехватывает его и завершает генерацию. Поэтому `<END>` не отображается в тексте ответа — это ожидаемое поведение, а не потерянная строка.

Значение `finish_reason=stop` означает, что генерация завершилась естественно либо на заданной stop-последовательности. API не различает эти два случая отдельными значениями, поэтому программа показывает и `finish_reason`, и фактически переданную настройку `stop`.

Локальная валидация проверяет:

- один заголовок блюда первого уровня;
- наличие и порядок разделов `## Ингредиенты` и `## Приготовление`;
- от одного до пяти ингредиентов;
- от одного до четырёх шагов;
- отсутствие завершения по причине `length`;
- число сгенерированных токенов не выше `max_tokens`;
- `finish_reason=stop` и отсутствие служебного `<END>` в возвращённом тексте.

## Подготовка

Для дня 2 используется собственное окружение. Если в приглашении терминала отображается активное окружение другого дня, сначала выйдите из него:

```bash
deactivate
```

Затем подготовьте проект:

```bash
cd ~/Dev/AI_Advent_Challenge/day-02
uv sync
cp .env.example .env
```

Откройте `.env` и замените `your_api_key_here` настоящим ключом DeepSeek. Файл `.env` исключён из Git; не показывайте ключ в терминале, исходном коде и видео.

Использовать `uv sync --active` из окружения другого дня не следует: команда синхронизирует текущий проект именно с активным чужим окружением. Обычные `uv sync` и `uv run` автоматически выбирают `day-02/.venv`.

## Запуск

Основной сценарий для сравнения:

```bash
uv run python main.py "Составь рецепт салата Цезарь для двух человек"
```

То же самое с явным указанием режима:

```bash
uv run python main.py --mode compare "Составь рецепт салата Цезарь для двух человек"
```

Запуск отдельных вызовов:

```bash
uv run python main.py --mode free "Составь рецепт салата Цезарь для двух человек"
uv run python main.py --mode controlled "Составь рецепт салата Цезарь для двух человек"
```

Если текст запроса не передан, программа предложит ввести его интерактивно.

Проверка стабильности формата на десяти реальных контролируемых вызовах:

```bash
uv run python main.py --mode controlled --runs 10 \
  "Составь рецепт салата Цезарь для двух человек"
```

Параметр `--runs` принимает значения от 1 до 20 и доступен только вместе с `--mode controlled`. Ограничение защищает от случайного запуска большого числа платных API-запросов. После серии программа выводит общий результат, например `Валидацию прошли: 10/10`.

## Автоматические проверки

Локальные тесты не обращаются к DeepSeek и не расходуют API-баланс:

```bash
uv run python -m unittest -v
```

Проверяется, что:

- пользовательский запрос в двух режимах совпадает;
- свободный вызов не содержит явных ограничений;
- контролируемый вызов передаёт формат, `max_tokens` и `stop`;
- обработка ответа сохраняет метаданные;
- консоль поясняет отсутствие `<END>` в полученном тексте.
- валидный контролируемый ответ проходит все проверки;
- лишние ингредиенты и обрыв по лимиту обнаруживаются как ошибки;
- число повторов ограничено безопасным диапазоном.

Контрольная серия из десяти реальных вызовов выполнена 1 сентября 2026 года. Все ответы прошли валидацию (`10/10`), использовали от 162 до 197 токенов из доступных 220 и завершились с `finish_reason=stop`.

## Запись результата

Для видео достаточно одного запуска в режиме `compare`. В кадре должны быть видны:

1. Одинаковый исходный запрос.
2. Свободный развёрнутый ответ.
3. Контролируемый структурированный ответ.
4. Настройки и метаданные обоих режимов.
5. Пояснение, почему `<END>` отсутствует в полученном тексте.

Отдельную серию `--runs 10` можно показать после основного сравнения либо использовать как предварительную проверку стабильности перед записью.

Запись результата хранится локально как `resources/day-02-result.mp4`. Содержимое `resources/`, включая исходное задание, исключено из Git.

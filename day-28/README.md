# День 28 — локальный WebTutor RAG и сравнение моделей

## Задание и выбранный корпус

Подключить локальную LLM к RAG, выполнять поиск локально и сравнить ответы
с облачной моделью по качеству, скорости и стабильности. Результат — видео
и код; оригинал задания: `resources/task.md`.

По согласованию с пользователем требование использовать индекс недели 5
снято. Основной корпус — предметная документация готового локального
MCP-сервера `webtutor-docs`: Datex, WebSoft HCM Portal и SQL/XML-модель.

## План и устройство

План сохранён в [PLAN.md](PLAN.md). Самостоятельный Python/uv-проект;
нужен весь репозиторий: расчёт метрик Ollama переиспользуется
из дня 27 без изменения его файлов. MCP-сервер установлен отдельно.

Каждый ход:

1. Снимок памяти: общие заметки и последние шесть вопросов, отдельно предыдущие
   ответы локальной и облачной модели.
2. Локальная Qwen3 формирует самостоятельный вопрос и 1–3 запроса поиска.
   Планировщик можно выключить: тогда ищется исходный вопрос.
3. Один набор поисков MCP через stdio, отбор до K материалов с распределением
   между запросами. В режиме docs учитываются ссылки alsoIn на другой корпус.
4. Чтение исходных материалов через `webtutor_read`; карточки поиска сами
   по себе не используются как доказательство. Для schema читаются overview,
   object_columns, catalog_columns и xml_fields через `webtutor_schema_read`.
5. Qwen3 и, при включённом сравнении, DeepSeek получают общий текущий вопрос
   и источники, но каждая модель видит только свои предыдущие ответы.
   Генерации идут независимо и параллельно; ошибка одной модели
   не удаляет ответ другой. Поиск повторно для облака не выполняется.
6. Для Ollama задаётся JSON-схема в format, для DeepSeek — JSON mode.
   Ответы сохраняются; JSON-контракт и дословное наличие цитат проверяются
   локально. Неправильные и незавершённые ответы видны с соответствующим
   статусом и не выдаются за принятые. Без найденных материалов генерация
   пропускается.

MCP выполняет поиск и собственный reranking локально. По документации
сервера при недоступном reranker возможен лексический режим: подсказки
поиска и состояние сервера сохраняются в сессии. Приложение не скачивает
поисковые модели и не строит индекс автоматически.

## Подготовка

Нужны uv, Python 3.12+, установленный `webtutor-docs` с готовым индексом,
Node.js для его запуска и Ollama с уже загруженной Qwen3:14b.
В текущем окружении используются сервер 0.6.0 и Ollama 0.35.1.

```bash
cd day-28
uv sync --locked
test -e .env || cp .env.example .env
```

Настройки MCP по умолчанию берутся только из блока
`[mcp_servers.webtutor-docs]` в `~/.codex/config.toml`: `command`, `args`.
Другие секции и ключи не загружаются. При отсутствии этой регистрации
задайте `WEBTUTOR_MCP_COMMAND` и `WEBTUTOR_MCP_ARGS` в `.env` по примеру.
Необходимые серверу переменные `WEBTUTOR_*` передаются процессу;
DeepSeek-ключ ему не передаётся. stderr процесса скрыт; ошибки этапа
показываются в TUI без содержимого потенциально чувствительных исключений.

Ключ `DEEPSEEK_API_KEY` задаётся в `day-28/.env` или системном окружении.
Облако выключено по умолчанию; ключ для локального режима не нужен.
`DEEPSEEK_MODEL` задаёт начальную облачную модель; далее она редактируется
в настройках сессии. Ключи и HTTP-заголовки в JSON не сохраняются.

`day-28/resources/ollama-local/`; повторная загрузка не нужна.

## TUI

- **Ответы:** локальный и облачный ответы рядом, русские статусы, цитаты и метрики.
  Во время генерации показывается только текст ответа, ещё не прошедший проверку;
  исходный JSON, рассуждения и подробные метрики доступны в сворачиваемой диагностике.
  При отказе показываются понятная подпись «Модель не нашла ответа в переданных
  источниках» и объяснение из gaps, даже если модель нарушила формат цитат.
  Такой ответ сохраняет статус invalid и предупреждение о проверке; подробный
  список ошибок остаётся в диагностике и не занимает панель метрик.
- **Источники и поиск:** исходный и самостоятельный вопросы, обычный список
  поисковых запросов, прочитанные материалы и их текст. Усечение обозначено словами.
  Хеш контекста и служебные данные поиска находятся в сворачиваемой диагностике.
- **Память:** редактируемые общие заметки и снимок памяти выбранного хода;
  видно, какие заметки и вопросы вошли в запрос и сколько старых вопросов исключено.
  Служебный JSON доступен в сворачиваемой диагностике.
- **Ollama:** состояние локального сервера, ручной запуск и остановка, список
  установленных локальных моделей, выбор модели для следующих вопросов,
  размер весов, квантование и модели в памяти с использованием GPU.
- **Настройки:** модели, облачное сравнение, локальный планировщик, thinking,
  температура, контекст, лимит генерации, K, размер материалов и корпус.

Вкладка «Ollama» проверяет состояние при открытии приложения и обновляет
его каждые три секунды, пока вкладка активна. Это только GET /api/tags
и GET /api/ps; автоматического запуска сервера или загрузки модели нет.
«Обновить список» также обновляет сведения о моделях в памяти. Выбор модели
синхронизирован с полем в настройках, сохраняется в сессии и применяется
к следующему планированию/ответу. Веса загружаются при первом запросе;
во время генерации смена модели и управление сервером заблокированы.

«Запустить» использует бинарный файл и каталог моделей дня 28,
localhost:11434, контекст из настроек, один параллельный запрос,
keep_alive=30m и OLLAMA_NO_CLOUD=1. Если сервер уже доступен из другого
терминала, приложение подключается к нему. Кнопка остановки доступна
только для собственного процесса. При нормальном выходе TUI свой сервер
останавливается; внешний сервер не затрагивается. Аварийное завершение TUI
не гарантирует остановки сервера. Ошибки запуска показываются во вкладке;
сырой stdout/stderr процесса не отображается. Модели не скачиваются;
удалённые модели с remote_host/remote_model и суффиксом cloud исключаются
из списка. Для установки дополнительных весов используйте Ollama отдельно.

Сверху — сохранённые сессии, новая сессия, сохранение и остановка;
ниже — выбор хода и повтор на том же контексте. Новый ход появляется сразу,
а его список источников обновляется после поиска, до завершения генерации.
Просмотр прежнего хода во время генерации не сбрасывает выбранный источник.
Заголовок показывает выбранные модели и состояние облачного сравнения. Enter отправляет,
Shift+Enter добавляет строку, Ctrl+Q сохраняет и закрывает, Escape отменяет
активные задачи. Рекомендуемый терминал — 180×60; headless-компоновка
проверяется также при 120×40 и 80×24. При ширине меньше 100 колонок или
высоте меньше 32 строк включается компактный режим: сокращены панели и метрики,
подробности остаются в диагностике. Настройки и заметки блокируются на время хода.

Кнопка повтора копирует **точные сохранённые сообщения**, включая прежнюю
память и источники. Поиск и планировщик не запускаются; новые заметки
в повтор не входят. Параметры моделей можно менять между повторами.
Для проверки стабильности сохраняйте те же параметры и сравнивайте минимум
три ответа. Повтор обозначается номером исходного хода.

## Память и сохранение

JSON-сессии хранятся в `sessions/`, полностью вне Git. Они содержат полный
архив пользовательских вопросов, оба ответа, рассуждения, настройки,
поисковые карточки, прочитанные страницы и фактически отправленные сообщения.
Обновление атомарное, права файла 0600. Промежуточный текст сохраняется
не чаще раза в секунду; завершение/ошибка/отмена сохраняются сразу.
Незавершённые ходы после загрузки получают статус interrupted.

Заметки сохраняются кнопкой «Сохранить», перед отправкой, сменой
сессии и выходом. Принудительное завершение может потерять последние правки
и последний фрагмент потока. При ошибке диска выход/смена сессии не выполняются.

Каждая модель получает свои предыдущие ответы и описание пробелов, включая
отказы. Ответы с ошибками цитат/формата включаются, если из них можно извлечь
текст; в истории сохраняется статус invalid. Рассуждения, незавершённый поток
и ошибки API в память не входят. Для каждого вопроса берётся последний доступный
ответ данного провайдера, включая повтор этого вопроса; повтор не добавляет
дубликат вопроса. История сохраняет имя модели, поэтому смена модели внутри
одного провайдера не очищает её. Планировщик использует локальную историю.

Истории могут расходиться и накапливать разные суждения. Предыдущие ответы
и заметки не считаются документацией платформы: факты проверяются по текущим
источникам. Старые ссылки [S1] относятся к документам своего хода. Во вкладке
«Память» отображаются обе отправленные истории; их сообщения, бюджеты и хеши
сохраняются отдельно в provider_messages/provider_contexts. Поля messages/context
сохранены для совместимости и описывают локальный запрос. Старые сессии читаются
без преобразования; точный повтор старого хода сохраняет его прежний контекст.

История ограничена шестью пользовательскими вопросами с ответами. Оценка входного
бюджета — UTF-8 байты / 2 с запасом на шаблон и генерацию; это не точный
токенизатор. Общие источники подгоняются по байтовому бюджету обеих моделей:
длинные тексты сокращаются с одинаковым верхним пределом на документ, безопасно
для UTF-8. Все идентификаторы источников сохраняются, усечение отмечается явно;
полный прочитанный текст остаётся в read_text и pages сессии. Проверка цитат
выполняется по фактически отправленному тексту, повтор использует его же.
История сохраняется, пока помещается вместе с минимумом 512 байт каждого
документа; затем старые вопросы исключаются вместе с ответами. Число исключений
показывается в памяти. Текущий вопрос и заметки автоматически не удаляются:
если они не помещаются даже с минимальными источниками, ход останавливается.
При усечении часть значимых разделов может не попасть в ответ. Модель или сервер
всё ещё могут усечь вход; точное отсутствие усечения не гарантируется.

Чтение MCP ограничено тремя страницами одного документа; у схемы — двумя
страницами каждого раздела по 20 строк. Текст каждого материала дополнительно
ограничен max_chars. Полные прочитанные страницы сохраняются отдельно;
признаки truncated/hasMore/complete отражаются в неполноте источника.
Приложение не является агентом, самостоятельно исследующим весь корпус.

## Метрики и оценка

Поиск и чтение измеряются отдельно. Метрики каждого ответа: время HTTP-
генерации, время до первого текста, входные и выходные токены. Ollama также
возвращает скорость по eval_count/eval_duration; thinking входит в генерацию.
DeepSeek возвращает usage через SSE. Его скорость по чистому серверному
времени недоступна и не выдумывается. Полное время хода включает локальное
планирование, поиск и обе генерации; при повторе поиска нет.

Проверка цитат доказывает только наличие цитируемого текста и известный ID
источника. Она не доказывает логический вывод, полноту, корректность кода
или подтверждение всех утверждений. Предметное качество оценивается при сравнении ответов; отдельного поля оценки в TUI нет.
thinking локальной модели и cloud thinking различаются: облачный отключён,
локальный управляется переключателем. Холодный запуск измеряйте отдельно
от запросов с загруженными моделями.

В локальном режиме приложение обращается только к localhost Ollama и
локальному MCP. Включение облака разрешает один платный DeepSeek-вызов
на ход/повтор и отправку общих заметок, выбранной истории и документации.
При включённом планировщике добавляется один локальный запрос, без оплаты
облачному провайдеру. Автоматических повторов нет; открытие TUI не вызывает LLM.

следствие усечения документа. Всего проверку формата и цитат прошли 2 из 3
локальных и все 3 облачных ответов; отказ тоже может пройти эту проверку.

Кнопка точного повтора реализована и проверена офлайн; это не заменяет
эксперимент по стабильности реальных моделей.

используется готовый индекс webtutor-docs. Это отклонение от исходной формулировки

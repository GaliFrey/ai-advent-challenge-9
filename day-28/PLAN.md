# День 28 — план реализации

По согласованию с пользователем вместо индекса недели 5 используется готовый
локальный MCP-сервер webtutor-docs. Предыдущие дни не изменяются.

1. Создать отдельный uv-проект и подключить установленный MCP через stdio.
   Поиск выполняется один раз; карточки раскрываются до исходных разделов.
   Сохранять параметры поиска, прочитанные материалы и признаки неполноты.
   Подгонять общий текст источников по байтовому бюджету обеих моделей,
   отмечать усечение и сохранять полный прочитанный текст для разбора.
2. Использовать Qwen3:14b через локальную Ollama и опциональный DeepSeek.
   Передавать обеим моделям общий вопрос и источники, свои прошлые ответы; сохранять ответы,
   рассуждения, ошибки, метрики и проверку дословных цитат независимо.
3. Сохранять JSON-сессии атомарно, вне Git. Общая память: последние
   пользовательские реплики и редактируемые заметки. У каждого провайдера
   отдельная история ответов, отказов и пробелов; ответы не становятся фактами.
   Локальный планировщик разрешает ссылки на прошлые вопросы и локальные
   ответы, выделяет до трёх поисковых запросов.
4. Сделать Textual TUI: ответы рядом, выбор хода, источники и поиск,
   память, настройки, открытие/новая сессия, остановка. Повтор на фиксированном
   контексте позволяет исследовать стабильность. Поле ручной оценки снято
   по просьбе пользователя для записи видео. Добавлена вкладка Ollama:
   ручной запуск/остановка собственного сервера, выбор установленных моделей
   и состояние памяти. Автозапуска нет; внешний процесс не останавливается.
   После ревью добавлены синхронное обновление ходов/источников, вывод текста
   из потока JSON, русские подписи, сворачиваемая диагностика и компактный режим.
5. Проверить изоляцию облачного режима, общие источники и отдельные истории, ошибки/отмену,
   сохранение/восстановление, чтение MCP и работу TUI в headless-режиме.
   Выполнить локальную интеграционную проверку MCP. Платные вызовы для
   проверки не нужны. Визуальные проверки выполняются только по просьбе.
6. Описать запуск, устройство памяти, метрики и ограничения в README;
   обновить оглавление проекта и history.md по фактическим результатам.

Критерии оценки: предметная корректность и полнота (ручная оценка), наличие
и точность цитат (автоматически), время retrieval и генерации, ошибки,
незавершённые ответы и изменения ответов при повторе одного контекста.

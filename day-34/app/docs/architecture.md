# Архитектура тюнера Guitar Trainer

Документ описывает фактическое устройство и поведение текущей реализации
микрофонного тюнера для шестиструнной гитары (стандартный строй E A D G B E,
A4 = 440 Гц). Все утверждения о поведении привязаны к исходному коду текущей
реализации: `web/index.html`, `web/src/app.js`, `web/src/capture.js`,
`web/src/diagnostics.js`, `web/src/pitch.js`, `web/src/display.js`,
`web/style.css`, `web/test/*.test.mjs`, а также `README.md` и `web/README.md`.
Непроверенное и относящееся к будущему помечается явно.

## 1. Назначение и контекст

Приложение — статическая веб-страница: пользователь открывает её в браузере,
нажимает «Включить микрофон», и страница слушает игру, автоматически определяя
звучащую открытую струну и показывая, настроена ли она (`web/README.md:3-6`).

Static frontend без сборки дополнен локальным сервером поддержки. Каталог `web/`
по-прежнему содержит статические файлы и Node-тесты (`web/index.html`,
`web/style.css`, `web/src/*.js`, `web/test/*.test.mjs`, `web/README.md`), а
`web/package.json` нет. Прикладной backend теперь есть: `server/` — FastAPI +
SQLite, оформленный как uv-проект (`pyproject.toml`, `uv.lock`). Он слушает
только loopback и с одного origin отдаёт `web/index.html`, разрешённую статику
и API панели «Помощь». Вся обработка звука по-прежнему выполняется локально в
браузере: звук не записывается и не передаётся (`web/README.md:4-6`,
`web/src/app.js:2`). При отправке сообщения в поддержку браузер прикладывает
диагностический снимок версии 1, который сохраняется в SQLite рядом с текстом.
Backend получает контекст обращения через MCP (раздел 8), вызывает DeepSeek
и сохраняет ответ. Сборка, менеджер зависимостей frontend и транспиляция не
используются: `web/index.html` подключает `./src/app.js` и `./src/support.js`
как ES-модули, а `web/src/pitch.js:1-3` и `web/src/display.js:1-3`
документируют, что один и тот же файл импортируется и браузером, и Node-тестами
без сборки.

Для доступа к микрофону браузер требует защищённый контекст. MDN относит
к ним `http://localhost` и `file:///`
([защищённые контексты](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Secure_Contexts));
файловый URL нельзя автоматически считать незащищённым. Однако
страница подключает `web/src/app.js` как ES-модуль (`web/index.html:32`), а
модульные скрипты из HTML, открытого как `file://`, не загружаются из-за
ограничений CORS
(https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules), и
`getUserMedia` в любом случае требует разрешения пользователя
(https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia).
Поэтому рекомендуется открывать страницу через локальный HTTP-сервер по адресу
`http://localhost` (`web/README.md:8-16`). Рекомендуемая команда запуска
локального статического сервера — в разделе «Запуск и проверки» README.md.
Совместимость проекта со всеми браузерами не проверена.

## 2. Состав файлов

- `web/index.html` — статическая разметка: элементы `#status`, `#start`,
  список шести струн `[data-note]`, область чтения `#direction`/`#cents`,
  метка `#tuned`, подсказка `#hint`, подключение модульного скрипта
  (`web/index.html:6,11-32`).
- `web/src/app.js` — браузерная обвязка: ссылки на DOM, отрисовка `render`, и
  внедрение реальных браузерных вызовов Web Audio в `capture.js`
  (`web/src/app.js:1-76`).
- `web/src/capture.js` — оркестрация стадий захвата и цикл кадров с
  внедряемыми зависимостями; реальные браузерные вызовы передаёт `app.js`
  (`web/src/capture.js`).
- `web/src/diagnostics.js` — локальное хранилище диагностического состояния и
  сбор JSON-совместимого снимка версии 1; не зависит от DOM и Web Audio
  (`web/src/diagnostics.js`).
- `web/src/support.js` — панель «Помощь»: переписка с локальным API поддержки,
  вывод текста через `textContent` (HTML не исполняется), отправка снимка через
  `collectSnapshot()` только при отправке сообщения. Не импортирует
  `capture.js`/`display.js` и не управляет захватом звука.
- `web/src/pitch.js` — чистое определение основного тона и сопоставление
  струны, без DOM и Node-глобалов (`web/src/pitch.js:1-131`).
- `web/src/display.js` — конечный автомат показаний, без DOM и аудио; время
  передаётся параметром `now` (`web/src/display.js:1-400`).
- `web/style.css` — только оформление, поведения не содержит.
- `web/test/pitch.test.mjs`, `web/test/page.test.mjs`, `web/test/display.test.mjs`,
  `web/test/stability.test.mjs` — Node-тесты логики и разметки на синтетических
  сигналах.
- `web/test/diagnostics.test.mjs`, `web/test/capture.test.mjs` — Node-тесты
  снимка и стадий захвата с управляемыми часами и подставными браузерными
  объектами.
- `server/` — локальный сервер поддержки (FastAPI + SQLite): `config.py`
  (настройки и лимиты), `db.py` (схема, транзакции и read-only доступ),
  `snapshot.py` (строгий валидатор снимка версии 1), `app.py` (маршруты,
  статика, сессии, CSRF, вызов MCP), `mcp_server.py` (дочерний read-only
  MCP-сервер на официальном Python SDK, stdio), `mcp_client.py` (короткоживущий
  stdio-клиент MCP), `responder.py` (подготовка payload, async HTTP и строгая валидация; принимает
  MCP-контекст и retrieval отдельно), `retrieval.py` и `retrieval_index.py`
  (локальная модель и индекс), `main.py` (запуск по loopback), `tests/` (pytest-проверки).
  Публикуется только явный allowlist статических файлов. Контракт API описан в
  `docs/support-api.md`, контекст снимка и MCP — в `docs/support-context.md`.

Разделение на модули реально используется: `app.js` импортирует
`detectPitch`/`matchString` из `./pitch.js`, `createReadingState`/
`updateReading`/`committedAtOf` из `./display.js`, `createCapture` из
`./capture.js` и `diagnostics` из `./diagnostics.js`
(`web/src/app.js:3-6`); `display.js` импортирует из `./pitch.js` только
`STRINGS`, `centsBetween`, `RECOGNIZE_CENTS` (`web/src/display.js:32`);
`diagnostics.js` импортирует из `./pitch.js` только `STRINGS`.

## 3. Поток обработки звука

Запуск происходит по нажатию кнопки `#start` (`web/src/app.js:75`), которое
вызывает `capture.start()` (`web/src/capture.js`). Оркестрация стадий и цикл
кадров вынесены в `web/src/capture.js`; `web/src/app.js` внедряет реальные
браузерные вызовы (`web/src/app.js:43-73`). Если запуск уже идёт, повторный
вызов игнорируется (`web/src/capture.js`).

Стадии запуска фиксируются диагностикой явно: `requesting` до запроса доступа,
`initializing` после получения потока, `capturing` после сборки аудиографа.
Флаг «идёт попытка» не является состоянием захвата.

Цепочка при успешном запуске (реализация в `web/src/capture.js`, браузерные
вызовы — из `web/src/app.js:46-51`):

1. `navigator.mediaDevices.getUserMedia({ audio: true })` — запрос доступа к
   микрофону, возвращает `MediaStream` (`web/src/app.js:46`).
2. `new AudioContext()` — создание аудиоконтекста (`web/src/app.js:47`).
3. `context.createMediaStreamSource(stream)` — источник из потока
   (`web/src/app.js:48`).
4. `context.createAnalyser()` — анализатор (`web/src/app.js:49`).
5. `analyser.fftSize = 4096` (`web/src/capture.js`).
6. `source.connect(analyser)` — соединение источника с анализатором
   (`web/src/capture.js`).
7. `new Float32Array(analyser.fftSize)` — буфер на 4096 сэмплов
   (`web/src/app.js:50`).

После вывода статуса «Слушаем: дёрните струну.» запускается цикл кадров через
`requestAnimationFrame(frame)`. В каждом кадре (`web/src/capture.js`):

1. `analyser.getFloatTimeDomainData(buffer)` — копирование текущих временных
   сэмплов в буфер.
2. `detectPitch(buffer, context.sampleRate)` — оценка основного тона, либо
   `null` при тишине или неуверенном сигнале.
3. `matchString(frequency)` — сопоставление частоты с одной из открытых струн,
   либо `null`.
4. `rmsOf(buffer)` — среднеквадратичный уровень (`RMS`) текущего буфера,
   считается один раз за кадр.
5. `updateReading(readingState, { frequency, match, level }, now)` — обновление
   конечного автомата показаний; `now` — монотонное время кадра
   (`performance.now()`).
6. `diagnostics.recordMeasurement(...)` и `diagnostics.recordReading(...)` —
   сохранение последнего измерения и удерживаемого показания с меткой фиксации
   (`committedAtOf(readingState)`).
7. `render(...)` — обновление DOM по полученному показанию.
8. Рекурсивный `requestAnimationFrame(frame)` — следующий кадр.

В фоновом цикле кадров диагностический снимок не собирается и не отправляется:
`app.js` только сохраняет состояние и показания в `diagnostics`. Новый снимок
собирается исключительно в момент отправки сообщения — панель «Помощь»
(`web/src/support.js`) вызывает `collectSnapshot()` и передаёт результат API
поддержки.

Дополнительно до запуска, на этапе загрузки модуля, выполняется начальная
отрисовка `render(updateReading(readingState, { frequency: null, match: null }, 0))`
(`web/src/app.js:76`), показывающая подсказку «дёрните струну».

### Обновление DOM (`render`, web/src/app.js:20-39)

- Снимает класс `active` со всех струн и добавляет его элементу распознанной
  струны по `data-note` (`reading.activeNote`), если он есть
  (`web/src/app.js:21-23`).
- Показывает подсказку `#hint`, если `reading.hint` (`web/src/app.js:25`), и
  метку `#tuned`, если `reading.tuned` (`web/src/app.js:26`).
- Если `reading.cents === null`, очищает `#direction` и `#cents`, снимает классы
  `flat`/`sharp` и завершает отрисовку (`web/src/app.js:28-33`).
- Иначе выводит в `#cents` число с `«центов»` и знаком `+` для положительных
  значений, выставляет классы `sharp`/`flat` по `reading.direction` и выводит
  `reading.direction` в `#direction` (`web/src/app.js:35-38`).

## 4. Ответственность модулей

- **`web/src/app.js`** — браузерная обвязка. Отвечает за: ссылки на DOM-элементы
  (`web/src/app.js:8-16`), отрисовку `render` (`web/src/app.js:20-39`) и
  внедрение реальных браузерных вызовов Web Audio в `capture.js`
  (`web/src/app.js:43-73`). Оценка уровня `rmsOf`, цикл кадров и стадии захвата
  вынесены в `web/src/capture.js`.
- **`web/src/capture.js`** — оркестрация стадий `requesting`→`initializing`→
  `capturing` и цикл кадров. Все браузерные вызовы внедряются, поэтому переходы
  состояний и сохранение результатов кадра проверяются Node-тестами с
  подставными объектами. Считает RMS один раз за кадр, сохраняет измерение и
  показание в диагностику, при сбое кадра регистрирует ошибку, не продолжает
  цикл и не маскирует исключение.
- **`web/src/diagnostics.js`** — локальное хранилище диагностического состояния
  и сбор снимка версии 1 (`docs/support-context.md`, раздел 5.3). Не зависит от
  DOM и Web Audio; наружу отдаёт только примитивы и `null`, не публикует
  `MediaStream`/`AudioContext`/`readingState`/буферы. Экспортирует фабрику
  `createDiagnostics`, singleton `diagnostics` и функцию `collectSnapshot`.
- **`web/src/support.js`** — панель «Помощь» и локальная переписка. Обращается
  только к API поддержки того же origin, не управляет звуком и не импортирует
  `capture.js`/`display.js`. Снимок получает через `collectSnapshot()` в момент
  отправки; текст выводится через `textContent`.
- **`web/src/pitch.js`** — чистое определение основного тона и сопоставление
  струны. Заявляет независимость от DOM и Node-глобалов
  (`web/src/pitch.js:1-3`); обращений к `document`, `window` или глобалам Node в
  модуле нет. Экспортирует константы `A4`, `STRINGS`, `TUNED_CENTS`,
  `RECOGNIZE_CENTS` и функции `centsBetween`, `detectPitch`, `matchString`
  (`web/src/pitch.js:6-35,40,113`).
- **`web/src/display.js`** — конечный автомат показаний. Заявляет независимость
  от DOM и аудио, время принимает параметром `now` (`web/src/display.js:1-3`);
  зависит только от `./pitch.js` (`web/src/display.js:32`). Экспортирует
  константы (`SMOOTH_FRAMES`, `SETTLE_MS`, `UPDATE_INTERVAL_MS`,
  `CONTRADICTION_WINDOW_MS`, `CONTRADICTION_CHANGES`, `FOREIGN_TONE_MS`,
  `TUNED_RELEASE_CENTS`, `TAIL_LEVEL_RATIO`, `PLUCK_GROWTH_RATIO`, `SILENCE_MS`,
  `SILENCE_LEVEL_FLOOR`) и функции `createReadingState`, `updateReading`, а также
  `committedAtOf` — nullable-метку фактической фиксации показания
  (`web/src/display.js`). Обращений к DOM или аудио-узлам в модуле нет.

## 5. Обработка ошибок

Запуск обёрнут в `try/catch` (`web/src/capture.js`): `try` охватывает
`getUserMedia`, `new AudioContext`, `createMediaStreamSource`, `createAnalyser`,
установку `fftSize` и `connect`.

При ошибке запуска (`web/src/capture.js`):

- сбрасывается guard активного запуска (повторная попытка разрешена);
- `diagnostics.failCapture(error)` переводит стадию в `error` и сохраняет
  нормализованное имя ошибки (неизвестное — `other`), без `message`/`stack`;
- `onFailure(error)` в `web/src/app.js:65-72` включает кнопку и выводит
  пользовательское сообщение: отдельное для `NotAllowedError`, общее — иначе.

Текст выводится через элемент `#status` (`web/src/app.js:60,63,68,70`).

Обработка ошибок кадра: кадр обёрнут в `try/catch` (`web/src/capture.js`). При
сбое `diagnostics.failCapture(error)` регистрирует ошибку, следующий
`requestAnimationFrame` не планируется (бесконечный цикл ошибочных кадров не
продолжается), а исключение перебрасывается — оно не маскируется. Guard
активного запуска при ошибке кадра не сбрасывается: переработка управления
аудио в задачу не входит. На успешном пути кнопка `#start` остаётся
`disabled`; остановки потока и закрытия `AudioContext` в реализации нет.

## 6. Алгоритм определения высоты и ограничения

`detectPitch(samples, sampleRate)` (`web/src/pitch.js:40-107`) оценивает частоту
основного тона по временному буферу:

- диапазон поиска — от `MIN_FREQUENCY = 65` Гц до `MAX_FREQUENCY = 450` Гц
  (`web/src/pitch.js:22-24`), с финальной проверкой результата в тех же границах
  (`web/src/pitch.js:105`);
- входные данные и `sampleRate` проверяются на корректность
  (`web/src/pitch.js:41-45`);
- отсечение тишины по `RMS`: если `rms <= MIN_RMS = 0.005`, возвращается `null`
  (`web/src/pitch.js:29-30,47-53`);
- вычисляется нормированная автокорреляционная функция (NSDF)
  (`web/src/pitch.js:55-68`);
- находятся локальные максимумы; если их нет или наибольший пик ниже
  `MIN_CONFIDENCE = 0.6`, возвращается `null` (`web/src/pitch.js:70-79`);
- выбирается первый (наименьший лаг) достаточно сильный пик — порог
  `PEAK_RATIO = 0.9` от максимума, как защита от октавных ошибок
  (`web/src/pitch.js:26-28,81-90`);
- вершина уточняется параболической интерполяцией (`web/src/pitch.js:92-102`).

Алгоритм оценивает периодичность сигнала для поиска одного основного тона,
а не классифицирует его происхождение. RMS используется как порог допуска,
но не как калиброванная громкость; тембр и состав аккорда не определяются.
Шум и несколько одновременно звучащих струн могут мешать распознаванию или
дать неверный результат; отсутствие частоты не доказывает тишину. `matchString(frequency)`
(`web/src/pitch.js:113-131`) сопоставляет частоту с шестью открытыми струнами
(`STRINGS`, `web/src/pitch.js:9-16`) по минимальному отклонению в центах и
возвращает струну, знак и величину отклонения, а также признак «настроено»
(порог `TUNED_CENTS = 5` центов). Если минимальное отклонение не меньше
`RECOGNIZE_CENTS = 100` центов, возвращается `null`; также null возвращается
для отсутствующей, неположительной или нечисловой частоты
(`web/src/pitch.js:18-20,113-131`).

Ограничения и непроверенное (не факты):

- Точность `detectPitch` подтверждена только синтетическими тестами
  (`tone`, `harmonicTone`, `noise` в `web/test/pitch.test.mjs:12-52`);
  измерения на реальных микрофонах и устройствах не проводились.
- Пороги `MIN_RMS = 0.005`, `MIN_CONFIDENCE = 0.6`, `PEAK_RATIO = 0.9` и
  абсолютные пороги показаний `SILENCE_LEVEL_FLOOR = 0.02`,
  `TAIL_LEVEL_RATIO = 1/3` в реализации не калибровались под конкретное
  оборудование и усиление.
- Состояние `AudioContext` после создания (например, политика autoplay и
  необходимость `resume()`) в коде не обрабатывается и не проверялось.

## 7. Внешние Web API

Ключевые сведения о внешних API соответствуют официальной документации:

- `MediaDevices.getUserMedia()` — доступен только в защищённом контексте
  и требует разрешения пользователя; возвращает промис к
  `MediaStream`; при отказе пользователя отклоняется с `NotAllowedError`
  (https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia).
  В защищённом контексте доступ всё равно требует разрешения пользователя.
- MDN относит `http://localhost` и `file:///` к защищённым контекстам;
  загрузка ES-модулей из файла — отдельное ограничение
  (https://developer.mozilla.org/en-US/docs/Web/Security/Secure_Contexts).
- ES-модули в браузере загружаются с использованием CORS, поэтому из HTML,
  открытого как `file://`, модульные скрипты не загружаются
  (https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules).
- `BaseAudioContext.sampleRate` — число сэмплов в секунду, только для чтения
  (https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/sampleRate).
- `AnalyserNode.fftSize` — степень двойки от 32 до 32768 (по умолчанию 2048);
  значение `4096` в коде допустимо
  (https://developer.mozilla.org/en-US/docs/Web/API/AnalyserNode/fftSize).
- `AnalyserNode.getFloatTimeDomainData()` — копирует в переданный `Float32Array`
  `fftSize` сэмплов текущего временного сигнала
  (https://developer.mozilla.org/en-US/docs/Web/API/AnalyserNode/getFloatTimeDomainData).
- `Window.requestAnimationFrame()` — планирует следующий кадр цикла; callback
  получает timestamp, но время кадра для показаний и диагностики код берёт из
  `performance.now()`
  (https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame,
  https://developer.mozilla.org/en-US/docs/Web/API/Performance/now).

## 8. Локальный сервер поддержки, MCP и retrieval

FastAPI отдаёт только разрешённую статику и API с loopback-origin. Путь сообщения:
валидация и проверка владельца → транзакция сообщения и снимка → настоящий
stdio MCP (`initialize`, `tools/list`, `tools/call get_ticket_context`) → локальный
retrieval → ограниченный messages → DeepSeek → валидация → транзакция ответа,
retrieval, успешной попытки и answered → HTTP.
MCP-клиент и read-only сервер сохранены; чтения поисковой истории в обход MCP нет.
Контракт снимка v1 и алгоритм тюнера не меняются.

`server/retrieval.py` отвечает за явную подготовку восьми файлов закреплённой
E5-small и local-only CPU singleton с защищённой инициализацией.
`server/retrieval_index.py` отвечает за корпус, разбиение, индекс и поиск.
Токенизация, файловые проверки, кодирование и ранжирование вызываются через
worker `ThreadPoolExecutor`; глобальный допуск сериализует обработки без
очереди. Модель загружается один раз на процесс. Генерация — внешний DeepSeek,
без reranker, fallback и скрытых повторов.

Корпус фиксирован: только обычные непосредственные `docs/support/*.md`, с
no-follow открытием `docs`, `support` и статей по цепочке дескрипторов от
корня проекта и проверкой типа открытых дескрипторов. Идентичность каталогов
сверяется после чтения; подмена родительского каталога не расширяет корпус.
Снимки, сообщения, служебные документы и пользовательские пути исключены.
Markdown v1 распознаёт ATX-заголовки вне fenced code. Раздел целиком сохраняется,
если помещается. Затем используются абзацы, цельные списки/таблицы/fenced code;
чрезмерно длинный блок делится по символам с продвижением и перекрытием не более
32 токенов. Коротким разделам перекрытие не добавляется. Заголовки и родительские
условия входят в embedding-текст, а дословный непрерывный фрагмент хранится
отдельно. У длинных проблем условия до «Что можно сделать» повторяются в
embedding-входе последующих частей. Если обязательный контекст не помещается,
построение заканчивается явной ошибкой.

Ревизия модели `614241f622f53c4eeff9890bdc4f31cfecc418b3`, размерность 384,
предел 512 токенов. Перед encode реальный токенизатор считает полный вход с
`query: ` либо `passage: `, заголовками и специальными токенами; усечения нет.
Векторы нормализованы, ранжирование — скалярное произведение, равенство — по ID.
До трёх кандидатов без порога similarity. Исключаются ID и одинаковые тексты;
в одном документе пересечение >= половины меньшего фрагмента исключает кандидат.
Это не утверждение о наличии ответа.

Отдельная SQLite `data/retrieval/index.sqlite` хранит манифест JSON и таблицу
чанков (метаданные/embedding-текст JSON и float32 little-endian вектор).
Манифест содержит документы/хеши, модель/SHA, размерность, схему, splitter,
параметры кодирования и отпечаток канонического содержимого, включая векторы.
Координаты — Unicode-полуинтервал start/end и строки с 1; версия документа —
SHA-256 исходных байтов. ID фрагмента включает путь, хеш документа, координаты и
версию разбиения. Чтение UTF-8 сохраняет переводы строк.

`build-index` пишет временную SQLite, проверяет векторы, токеновые бюджеты,
целостность и записанный отпечаток, закрывает/fsync и повторно сверяет корпус;
затем атомарно заменяет опубликованный файл и синхронизирует каталог.
При ошибке до публикации прежний файл сохраняется. На старте и перед поиском
проверяются полный корпус (включая добавление/удаление), параметры, координаты,
embedding-входы, векторы и отпечаток. После encode повторяются сверки корпуса
и опубликованного индекса. Гонка даёт ошибку, без автоматического повтора;
результат относится к последней успешной сверке. Нельзя гарантировать отсутствие
внешнего изменения уже после этой точки.

`server/db.py:retrieval_results` сохраняет внутренний retrieval v1 под ID
assistant-сообщения в одной транзакции с ответом и переводом вопроса в answered.
Перестроение индекса не меняет сохранённые данные. HTTP/история содержат только
ID, название, заголовки, текст и URL сохранённого источника; перед чтением проверяется владелец.
Старые сообщения без retrieval читаются. Диагностические данные и внутренняя
оценка близости в ответ не включаются. MCP read-only — договорная граница,
а не песочница для вредоносного кода сервера.

Команды подготовки, каталогов, offline-проверки и исполнители операций T009 —
в README. Протокол уточнений, ошибки и HTTP-дополнение — в support-context.md.
Отсутствующая модель или неисправный индекс не мешают чтению переписки.
Пользовательская приёмка и независимое ревью остаются отдельными этапами.

Подготовку окружения и эксплуатационные команды `build-index` с записью в
`data/` выполняет посредник; обязательные проверки запускает контроллер.
Перед запуском приложения и проверок посредник задаёт
`PYTHONDONTWRITEBYTECODE=1`. Дочерний Python настоящего MCP дополнительно
запускается с `-B`, в том числе при явно заданном минимальном окружении.
Чтение корпуса открывает `docs`, `support` и статьи относительно дескриптора
корня проекта, запрещает символические ссылки на каждом уровне и сверяет
идентичность каталогов до и после чтения. Подмена каталога вызывает ошибку.

## 10. Генерация DeepSeek и управление попыткой

`server/config.py:DeepSeekSettings` валидирует модель deepseek-flash, лимиты и
таймауты. Runtime `server.main` читает только проектный .env без расширения
команд; системное окружение приоритетнее. MCP его не загружает и не получает
DEEPSEEK_* даже через extra_env. Ключ только в заголовке backend→DeepSeek.

`server/responder.py` отделяет system от JSON недоверенных данных и разрешает
только историю, снимок текущего сообщения, snapshotReceivedAt и ограниченные
фрагменты с ID. Текущий вопрос — последнее сообщение истории, отдельной копии
нет. Служебные поля, файловые пути, весь корпус и чужие обращения не отправляются.
История и RAG сокращаются только целыми элементами; вопрос и снимок не режутся.
Бюджеты, инженерная оценка токенов с явной неопределённостью, настройки и
обоснование запаса описаны в README. Это не подсчёт реального usage.

HTTP — асинхронный httpx к фиксированному официальному endpoint, JSON Output,
thinking disabled, stream=false, без tools/SDK/retries/redirects/proxy из env.
Весь путь после сохранения ограничен 90 секундами по умолчанию. JSON ответа
строго проверяется на answer/sourceIds и finish_reason=stop. Сырые ошибки,
отклонённый текст и reasoning_content не сохраняются. Пользователь видит
нормализованную безопасную причину с явным повтором.

`server/generation_gate.py` предоставляет один процессный nonblocking-допуск
и единственный CPU-worker. При отмене ожидания или timeout фоновый CPU-вызов
может ещё работать: lease освобождается только после завершения Future.
Поздний результат отбрасывается, HTTP не начинается. Активные MCP/HTTP-контексты
закрываются; shutdown ожидает принадлежащие приложению CPU-futures. Остановка
списания у провайдера этим не гарантируется. Запуск с несколькими процессами
для этой версии не поддерживается.

`generation_attempts` — добавочная таблица без изменения существующих сообщений
и retrieval v1. Начало внешнего вызова отмечается транзакционно после проверки
скользящего лимита сессии; ошибки до HTTP расход не увеличивают. Начатая попытка
учитывается даже при неизвестном исходе и после рестарта. Каждая попытка хранит
привязку истории, snapshotReceivedAt, индекс, полный retrieval, переданные и
выбранные ID, модель, время, длительность и только доступный usage/cache-поля.
Успех, assistant, retrieval и selected_ids сохраняются в одной транзакции.
После старта processing становится interrupted без автоматического продолжения.

Явный повтор вновь получает MCP до исходного сообщения и текущий retrieval,
сохраняя исходный snapshot. Успешный ключ возвращается без генерации. История и
маршрут материала используют сохранённые источники и проверяют владельца;
индекс для них не нужен. Старые ответы без выбранных ID показывают кандидатов
с пометкой прежнего формата. Сервер не принимает путь файла для навигации.

Предупреждение о внешней передаче контекста доступно в HTML до первой отправки.
Панель использует textContent, сохраняет ожидание, историю, новый разговор,
ошибки и явный повтор, включая ошибки после перезагрузки. Работа с аудио и
алгоритм тюнера не изменяются. Реальные ответы, визуальное поведение,
отзывчивость и доступность микрофона проверяет посредник отдельно после
офлайн-проверок контроллера; техническое ревью не подтверждает приёмку.


### Границы поддержки в SYSTEM

Тематическая политика размещена в SYSTEM `server/responder.py`, без отдельного
классификатора, дополнительных генераций и изменений retrieval. Она разрешает
помощь с фактическими функциями, показаниями тюнера, стандартным строем,
настройкой в пределах функций, снимком и необходимыми проверками микрофона,
разрешений, системного источника звука и браузера. Отсутствие темы в FAQ не
означает отказ. Отсутствующая функция объясняется по документации.

Полностью постороннее задание получает краткую границу с пустым sourceIds;
смешанное — ответ только на продуктовую часть. Смена роли и раскрытие SYSTEM
запрещены инструкцией. История помогает выбрать один следующий шаг или вопрос
для продолжения; без контекста задаётся один вопрос. Все недоверенные данные
остаются внутри user JSON, включая прежние ответы ассистента.

Структурные офлайн-тесты prepare и перехваченного HTTP payload проверяют эту
границу и бюджеты, сохраняя строгую схему снимка. Подставленные ответы не
доказывают соблюдение политики моделью. validate по-прежнему проверяет формат,
ID и завершение, а не тематику. Содержательные результаты шести ограниченных
реальных попыток и двух повторов продолжения оцениваются независимым ревью
отдельно; даже успешные
примеры не гарантируют защиту от любых prompt injection. Приёмка требует
фактического ответа пользователя.


Существующие [свидетельства T011](../README.md#границы-поддержки-guitar-trainer-t011)
содержат шесть исходных попыток и два отдельных повтора сценария 6
(после корректировки SYSTEM и после ужесточения инструкции редакции 4),
runtimeMaxTokens=1200. Пользователь в доверенном контексте подтвердил
предварительное объявление лимитов и разрешение до двух дополнительных вызовов
без автоповторов; выполнен один. JSON хранит ответы, фрагменты и метки
синтетического происхождения; значения снимков и история находятся в
изолированных SQLite. Попытки учитываются по БД и ID: шесть в
t011-acceptance.sqlite и по одной в записях повторов; для второго повтора
отдельный путь изолированной БД в материалах не указан. Записи содержат
retrieval, index_version,
модели и usage; журналы — шесть, один и один POST сообщений.
Это не полная трассировка каждого исторического MCP/retrieval/DeepSeek либо
исходящего max_tokens и не доказательство отсутствия вызовов вне материалов.
Достаточность для C7 требует независимого ревью с этими ограничениями.

Ревью 2-009 подтвердило нарушение C6 исходным продолжением: два уточнения
и внутренние имена полей; C8 ограничен. SYSTEM уточнён для одного действия
либо вопроса об одном факте, связи с историей и понятного описания состояния.
Повтор использует изменённые историю и снимок error/NotAllowedError вместо
idle, поэтому не отменяет историческое замечание. Ревью 2-019 подтвердило
нарушение C6 и в повторе: проверки блокировки и расширений объединены
с вопросом об адресе, связь с уже предложенными действиями не объяснена.
Ограничение C8 и препятствие технической готовности сохраняются для исходных
ответов. Успешные
офлайн-проверки и явное правило SYSTEM не устраняют это нарушение. В редакции 4
инструкция
продолжения ужесточена ещё раз: ровно одно из двух — одно следующее конкретное
действие либо один вопрос об одном недостающем факте; действие и вопрос
не совмещаются, а список советов или проверок не выдаётся за одно действие.
Пользователь разрешил не более двух новых вызовов только для сценария 6
(max_tokens=1200, без автоповторов); перепроверку выполняет посредник по
изолированному каналу. После ужесточения посредник выполнил один такой вызов и
сохранил его как scenario6Retest2: ответ содержит ровно один вопрос об одном
недостающем факте (какой текст показан в строке состояния), без списка советов
и без внутренних имён полей, sourceIds пуст. Этот первый наблюдаемый ответ,
удовлетворяющий правилу редакции 4, фиксирует фактический наблюдаемый исход C6;
исходный ответ и первый повтор остаются историческими неуспешными результатами,
а один пример не даёт гарантии тематики. Часть материалов не содержит
отдельного пути изолированной БД второго повтора и полной трассировки
MCP/retrieval/исходящего max_tokens; эти ограничения C7 оценивает независимое
ревью.
Для ответа об удержании отсутствие сопоставления возрастов само по себе
не доказывает нарушения условного правила о свежести: свежесть не утверждалась.
Архитектура одного запроса после MCP и retrieval, validate, защиты и зависимости
на этом этапе не изменялись. Обязательные проверки текущего дерева
и независимое ревью выполняет контроллер; пользовательская приёмка ожидается.

## 11. Веб-ассистент разработки frontend

Страница тюнера содержит отдельную панель «Ассистент разработки»
(`web/src/assistant.js`, разметка в `web/index.html`). Пользователь задаёт цель
обычным языком; серверный агентный цикл DeepSeek (`server/assistant_agent.py`) с
вызовами инструментов сам ищет и читает разрешённые frontend-файлы, готовит
изменения, прогоняет фиксированную проверку и применяет их. Предзаданных
сценариев и замен строк нет.

Границу обеспечивает серверный код (`server/assistant_scope.py`), а не только
системный промпт. Разрешены `web/index.html`, `web/style.css`, `web/src/*.js`
(кроме кода панели ассистента) и прямые `web/test/<имя>.mjs`; backend, `.env`,
секреты, `.git`, зависимости, `data/`, `tasks/`, `intakes/`, `docs/`, `README.md`
и подкаталоги `web/test/` недоступны. Нормализация отклоняет абсолютные пути,
диск Windows и любой сегмент `..`; каждый компонент проверяется на символические
ссылки и обычный тип файла.

Инструменты (`server/assistant_tools.py`) работают со staging-копией `web/`
(`server/assistant_staging.py`). Изменения применяются только после успешной
фиксированной серверной проверки и совпадения исходных allowlist-файлов с
манифестом SHA-256; запись идёт временным файлом и `os.replace` с best-effort
откатом. Проверка целевая: `node --check` по изменённым `.js` и `node --test`
только по изменённым `.mjs` (либо полный прогон allowlist-тестов, если изменены
только `.html`/`.css` или изменений нет). До успешной проверки рабочий frontend не
изменяется. Одна операция одновременно, без очереди; действуют пределы шагов
(`max_steps=40`), чтения, размера изменения, времени и вывода модели
(`max_tokens=4000`) (`AssistantSettings`), в пределах согласованных caps.
Инструментов commit, push, установки зависимостей и изменения конфигурации нет.

История и итог (изменённые пути, diff, результаты проверки) хранятся в серверной
SQLite (таблицы `assistant_conversations` и `assistant_messages`) и переживают
перезагрузку. Маршруты `/api/assistant/...` переиспользуют cookie `gt_session`,
защиту `X-Support-Request`/Origin и проверку владельца. После успешного
применения клиент перезагружает страницу один раз; сохранённая история только
отображается и не перезапускает задачу. Текст и diff выводятся через
`textContent`, HTML не исполняется; ключ DeepSeek в браузер, инструменты и
историю не попадает. Контракт описан в `docs/assistant.md`; реальные платные
вызовы и браузерная проверка требуют отдельного разрешения пользователя.

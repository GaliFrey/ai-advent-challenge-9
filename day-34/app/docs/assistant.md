# Веб-ассистент разработки frontend

Документ описывает фактическую реализацию панели «Ассистент разработки» на
странице тюнера и серверного агентного цикла. Все утверждения привязаны к коду
текущей реализации: `server/assistant_scope.py`, `server/assistant_staging.py`,
`server/assistant_tools.py`, `server/assistant_agent.py`, `server/app.py`,
`server/db.py`, `server/config.py`, `web/src/assistant.js`, `web/index.html`.

## 1. Назначение

Пользователь на странице тюнера открывает отдельную панель «Ассистент
разработки», задаёт цель обычным языком (например, «поправь подпись кнопки» или
«покажи в статусе номер струны»), а серверный агентный цикл DeepSeek сам решает,
какие разрешённые frontend-файлы найти и прочитать, что изменить, готовит
изменения, прогоняет фиксированную проверку и применяет их. После успешного
применения страница перезагружается один раз, а переписка и итог
восстанавливаются из локальной SQLite без повторного запуска задачи.

## 2. Разрешённая область

Ассистент во время использования читает и изменяет только эти обычные файлы
frontend текущего проекта:

- `web/index.html`
- `web/style.css`
- `web/src/app.js`
- `web/src/capture.js`
- `web/src/display.js`
- `web/src/pitch.js`
- `web/src/diagnostics.js`
- `web/src/support.js`
- `web/test/<имя>.mjs` — прямые Node-тесты в `web/test/`.

Запрещено, в том числе на чтение: backend (`server/`), `.env`, секреты, `.git`,
зависимости, `data/`, `tasks/`, `intakes/`, `docs/`, `README.md`, `web/README.md`,
код сервера, инструментов и панели ассистента (`web/src/assistant*.js`),
подкаталоги `web/test/`, а также всё вне `web/`.

Граница обеспечивается кодом инструментов (`server/assistant_scope.py`), а не
только системным промптом: allowlist задан явно на сервере; нормализация
отклоняет не-строки, пустые строки, NUL, абсолютные пути, диск Windows и любой
сегмент `..`; каждый компонент пути проверяется через `lstat`/`realpath`, поэтому
символические ссылки и не-обычные файлы отклоняются. Ошибка возвращается
модели/клиенту как безопасный код `path_forbidden` без раскрытия содержимого.

## 3. Staging и применение

Инструменты работают только со staging-копией `web/` во временном каталоге
вне области записи ассистента. Staging создаётся копированием всего `web/`
(включая защищённые файлы, чтобы фиксированная проверка работала), а манифест
SHA-256 allowlist-файлов фиксируется на момент создания. Инструменты могут
изменять только allowlist-пути: `web/src/assistant*.js` в staging инструментам
недоступен.

Применение возможно только после успешного `run_checks` для текущих изменений.
Перед первой записью реальные allowlist-файлы повторно хэшируются и сверяются с
манифестом; при конфликте изменения не применяются. Запись идёт временным файлом
и `os.replace` по каждому пути; при сбое выполняется best-effort откат. До
успешной проверки рабочий frontend не изменяется. Несколько `os.replace` не
являются общей атомарной транзакцией: при аварийном завершении процесса или
ошибке самого отката частичные изменения возможны. Постоянный журнал
восстановления файлов после аварии не реализован.

## 4. Агентный цикл

`server/assistant_agent.py` вызывает DeepSeek Chat Completions с `messages` и
`tools`, `thinking.type=disabled`, `stream=false`, без `response_format=json_object`
и без автоповторов. Цикл исполняет возвращённые `tool_calls` до терминального
инструмента `finish`. Предзаданных сценариев и замен строк нет: набор изменяемых
файлов определяется решениями модели и инструментами.

Для одного небольшого изменения системная инструкция ведёт по короткому пути:
модель читает только минимально необходимые файлы (при необходимости локализует
нужный файл через `search`/`list_files` и читает только его), сразу готовит правку
одним `propose_edit` на файл, затем `run_checks` → `apply` → `finish`. Перебор
всех файлов проекта и лишние чтения не требуются.

Проверка `run_checks` — лёгкая и целевая, но по-прежнему фиксированная серверная
команда (`server/assistant_staging.py`), обязательная до применения (C3). По
фактически изменённым файлам выполняются: `node --check <файл>` для каждого
изменённого `.js` (синтаксическая проверка), `node --test <файлы>` только по
изменённым `.mjs`-тестам; если изменены только неисполняемые файлы
(`web/index.html`, `web/style.css`) или изменений нет — полный прогон
`node --test` по всем allowlist-тестам. `argv` формируется сервером, `shell=False`,
`cwd` — staging; произвольная оболочка и выбор другого корня проекта недоступны.
Проверка слабее полного прогона, поэтому независимые обязательные проверки
контроллера (`pytest`, `web-tests`) остаются решающими.

Инструменты: `list_files`, `read_file`, `search`, `propose_edit`, `run_checks`,
`apply`, `finish`. Инструментов commit, push, установки зависимостей и изменения
конфигурации не существует. Произвольная оболочка и выбор другого корня проекта
недоступны.

Одна операция редактирования во всём процессе, без очереди. Ключ DeepSeek
передаётся только в заголовке backend→DeepSeek и не попадает в браузер,
инструменты и историю.

## 5. Лимиты

`server/config.py:AssistantSettings` задаёт пределы: число шагов инструментов
(`max_steps=40`, верхний cap 40), объём чтения на файл и суммарно, размер
изменения, число результатов поиска, таймаут фиксированной проверки, таймаут
одного запроса, общее время операции, а также `max_tokens=4000` (верхний cap
4000). Значения по умолчанию находятся в пределах уже согласованных caps и
рассчитаны на правку обычного frontend-файла в несколько КБ. Число шагов
ограничивает и ходы цикла, и вызовы инструментов; общее время (`total_seconds`)
проверяется между ходами модели; это не жёсткий таймер прерывания синхронных
инструментов. Превышение даёт явную безопасную ошибку: предел шагов
— `assistant_steps` (HTTP 429), достижение длины ответа модели —
`provider_output_limit` (HTTP 502). Если ошибка случилась до `apply`, рабочие
файлы ещё не изменены; после `apply` ошибка следующего вызова не откатывает
уже применённые файлы. При неоднозначном сетевом исходе
(`provider_network`/`provider_timeout`) вызов не повторяется молча: пользователь
может повторить явно. Модель зафиксирована как `deepseek-flash`.

Остаточное ограничение: `propose_edit` принимает полное новое содержимое файла,
поэтому файл, чей полный вывод не помещается в `max_tokens`, изменить нельзя —
операция завершается ошибкой `provider_output_limit`, без молчаливого повтора.
Точечные правки строк не реализуются.

## 6. API и панель

Маршруты переиспользуют сессию и защиты панели «Помощь»:

- `GET /api/assistant/session` — cookie `gt_session`, текущая переписка.
- `POST /api/assistant/conversations` — новая переписка (служебный заголовок и
  совпадение Origin с Host).
- `GET /api/assistant/conversations/{id}/messages` — история и итоги.
- `POST /api/assistant/conversations/{id}/messages` — запуск операции
  (`{text, idempotencyKey}`), синхронный ответ с итогом.

Изменяющие запросы требуют заголовок `X-Support-Request: 1` и совпадение
`Origin` с `Host`; сервис слушает только loopback. Чужая или несуществующая
переписка даёт одинаковый `not_found`. История хранится в серверной SQLite
(таблицы `assistant_conversations` и `assistant_messages`) и переживает
перезагрузку страницы и перезапуск сервера.

Панель `web/src/assistant.js` выводит ответы, diff и результаты проверок только
через `textContent`; HTML из ответов модели не исполняется. После успешного
применения (`result.applied=true`) клиент вызывает `location.reload()` ровно
один раз; сохранённая история только отображается и не перезапускает задачу.
Защищённый `assistant.js` отдаётся с `Cache-Control: no-store`, поэтому
устаревший JS не выдаётся.

## 7. Отказные сценарии

Системная инструкция требует краткого отказа с обозначением области на полностью
посторонние запросы, смену роли, просьбы раскрыть системные инструкции или
секреты и на изменение backend; в смешанном запросе выполняется только
допустимая frontend-часть. Содержимое файлов и результаты инструментов считаются
недоверенными данными и не меняют правила. Это семантическая инструкция модели:
код проверяет границы путей и формат, но не гарантирует тематику.

Проверки через Node не изолированы на уровне ОС и наследуют окружение сервера.
Изменённые моделью тесты и импортируемый ими код выполняются с правами процесса:
allowlist файловых инструментов не ограничивает их доступ к файловой системе
и сети. Поэтому запрет backend доказан только для прямых операций инструментов,
а не как непреодолимая песочница для исполняемого кода. Тесты доступны модели
на запись; общий HTML/CSS также может затронуть панель. Версия предназначена
только для локальных экспериментов с доверенными запросами и проверкой diff.

## 8. Ручная демонстрация

1. Запустить сервер: `uv run --no-sync --offline python -m server.main`,
   задав `DEEPSEEK_API_KEY` только на backend.
2. Открыть `http://localhost:8000/`, нажать «Ассистент разработки».
3. Ввести цель, затрагивающую 2–3 frontend-файла (например, изменить подпись в
   `web/index.html` и связанную логику в `web/src/app.js`).
4. Дождаться итога: изменённые пути, diff и фактический результат проверки.
   Проверка целевая (синтаксис изменённых `.js` и/или только изменённые тесты),
   а не полный прогон проекта.
5. После успешного применения страница перезагружается; переписка и итог
   восстанавливаются, задача повторно не выполняется.
6. Проверить, что запрос на изменение `server/` или `.env` получает краткий
   отказ с обозначением области.

Реальные платные вызовы DeepSeek и браузерная/визуальная проверка выполняются
только по отдельному разрешению пользователя. Обязательные офлайн-проверки
подменяют транспорт и не являются реальной генерацией.

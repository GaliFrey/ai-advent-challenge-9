# API локального сервера поддержки (контракт версии 1)

FastAPI + SQLite, один loopback-origin. Рабочий путь: валидация → транзакция
сообщения и снимка → настоящий MCP `get_ticket_context` v1 → локальная E5-small
на CPU и retrieval v1 → асинхронный DeepSeek Flash → валидация → атомарная запись
ответа, retrieval и успеха попытки. Контекст генерации не читается в обход MCP.

## Доступ и формат

Cookie `gt_session`: HttpOnly, SameSite=Strict, Path=/, без Secure для локального
HTTP. Любое обращение и сохранённый источник доступны только владельцу cookie;
чужой и отсутствующий ID дают одинаковый `404 not_found`. Используйте один адрес
(`http://localhost:8000/` либо `http://127.0.0.1:8000/`), не смешивайте их.
POST требует `X-Support-Request: 1`; Origin, если задан, должен совпадать с Host.
Permissive CORS отсутствует. Статика выдаётся по allowlist; SQLite, ключи, `.env`,
код, tasks и произвольные файлы по HTTP недоступны.

Успех — JSON; ошибка:

```json
{"error":{"code":"provider_key_missing","message":"Ключ DeepSeek не настроен на сервере. Сообщение сохранено; после настройки повторите явно."}}
```

Клиент разбирает `code`, а не текст `message`. Тела ошибок DeepSeek, prompts,
ключ и reasoning_content не возвращаются и не сохраняются в общих логах.

## Маршруты

- `GET /api/support/session`: создаёт cookie при отсутствии, возвращает
  `sessionId`, `currentConversationId` (целое либо null), `testMode: false`.
- `POST /api/support/conversations`: новый разговор, ответ `conversationId`,
  `testMode: false`; прежние данные остаются в базе.
- `GET /api/support/conversations/{id}/messages`: `conversationId`, `messages`,
  `testMode: false`. История в порядке серверного времени и ID.
- `POST /api/support/conversations/{id}/messages`: обработка или явный повтор.
- `GET /api/support/conversations/{id}/messages/{assistantId}/sources/{sourceId}`:
  сохранённые название, раздел и дословный фрагмент как `text/plain` с nosniff.
  Источник берётся только из retrieval этого ответа и выбранных ID, без файлового
  пути от клиента и без чтения актуального индекса. Для старого формата доступны
  сохранённые кандидаты.

Тело отправки:

```json
{"text":"Почему показание удерживается?","snapshot":{"schemaVersion":1},"idempotencyKey":"уникальный-ключ"}
```

Здесь снимок показан сокращённо: нужен полный [контракт v1](support-context.md).
Неизвестные поля снимка или его разделов отклоняются. Роль и время назначает
сервер. Лимиты: непустой text до 4000 символов, тело 65536 байт, снимок 16384
байта, ключ до 200 символов, история обращения до 200 сообщений. Валидация до
записи; превышение не создаёт частичное сообщение. Лимит входного текста не
отменяет отдельный предел поискового входа E5 в 512 токенов.

Успех отправки: `conversationId`, `userMessage`, `assistantMessage`,
`testMode: false`. Поля сообщения:

| Поле | Значение |
| --- | --- |
| `id`, `role`, `text` | серверный ID, user/assistant, текст |
| `state` | processing / answered / error |
| `createdAt`, `errorCode` | серверное UTC ISO-время, код ошибки либо null |
| `snapshot`, `idempotencyKey` | только у user; позволяют явно повторить ошибку из истории |
| `sources` | у assistant: выбранные серверные объекты id/title/headings/text/url |
| `sourcesLegacy` | true для прежних кандидатов без выбора моделью; иначе false |

HTML сообщений и источников не исполняется. `url` — маршрут сохранённого
материала выше; клиент разрешает только этот шаблон. Названия, ссылки и цитаты
создаёт сервер, модель возвращает только answer/sourceIds.

## Идемпотентность и ошибки

Ключ действует внутри обращения. Тот же ключ и другое содержимое →
`409 idempotency_conflict`. Завершённый ключ возвращает прежний ответ без MCP,
retrieval, API, допуска и нового расхода. Ключ в processing →
`409 already_processing`. После ошибки пользователь явно повторяет тот же
исходный текст, снимок и ключ; новые сообщение и снимок не создаются. MCP снова
читает историю до исходного messageId включительно; поиск использует текущий
валидный индекс. Повтор не включает последующие сообщения.

Один глобальный допуск на всё однопроцессное приложение, без очереди. Вторая
обработка → `409 generation_busy`, её сообщение остаётся с ошибкой и доступно
для повтора. Сессионный лимит по умолчанию — 10 начатых внешних попыток за
скользящие 3600 секунд → `429 session_limit`. Новое обращение той же сессии
лимит не сбрасывает. Расход сохраняется после рестарта; предварительные ошибки
его не увеличивают. Начатый неопределённый внешний вызов учитывается.

| Коды | Смысл |
| --- | --- |
| invalid_request / invalid_text / invalid_snapshot / invalid_idempotency_key | некорректный ввод, 400 |
| body_too_large / text_too_long / snapshot_too_large | лимит входа, 413 |
| missing_request_header / invalid_origin / not_found | защита доступа, 403/404 |
| history_limit / already_processing / generation_busy | ограничение обращения либо занятость, 409 |
| mcp_error / context_invalid | контекст недоступен, 502 |
| corpus_missing / corpus_invalid / model_missing / model_incompatible | локальный поиск не подготовлен, 503 |
| index_missing / index_stale / index_corrupt / index_incompatible / retrieval_failed | индекс или обработка недоступны, 503 |
| query_too_long | полный поисковый вход E5 превышает 512 токенов, 422 |
| context_budget | текущий вопрос либо полный messages не помещается в бюджет, 413 |
| provider_key_missing | ключ не настроен, 503; сообщение сохранено |
| provider_request | HTTP 400/422 провайдера, безопасная ошибка 502 |
| provider_auth / provider_access / provider_balance | HTTP 401/403/402 провайдера, безопасная ошибка 502 |
| provider_rate_limit / provider_unavailable / provider_http | HTTP 429, 500/503, другие статусы (включая redirect), 502 |
| provider_network / provider_timeout | сеть 502 / таймаут HTTP 504; исход может быть неизвестен |
| provider_contract / provider_output_limit | неверный JSON/контракт либо finish_reason=length, 502 |
| storage_failed / provider_failed | внутренний сбой сохранения / внешнего вызова, 503; для начатого незавершённого вызова исход неизвестен |
| processing_timeout | общий deadline 504 |
| cancelled / interrupted | отменённая обработка / восстановление после старта; записываются в состоянии истории |

403 — защитная классификация доступа, а не утверждение о документированном
коде DeepSeek. Никакие ошибки не запускают скрытый или исправляющий вызов.
Успешный assistant при ошибке не создаётся. После исправления окружения/сети
нажмите «Повторить»; после слишком длинного вопроса/контекста сократите вопрос
как новый либо начните новый разговор.

## Provider-контракт и хранение

`POST https://api.deepseek.com/chat/completions`, Bearer только в заголовке,
model=deepseek-flash, thinking.type=disabled, response_format.type=json_object,
max_tokens=1200, stream=false; tools нет. Асинхронный httpx, без SDK,
автоповторов, перенаправлений и proxy из системного окружения. Только HTTP 200,
одна choice с finish_reason=stop и assistant.content принимаются к валидации.
Ответ — JSON ровно с answer (непустая строка до 4000 символов) и sourceIds
(массив строк без дублей, только из переданных фрагментов). Пустой sourceIds
допустим. Лишние поля, повторные JSON-свойства, неизвестные ID, неверные типы,
пустой или незавершённый ответ отклоняются. Отклонённый текст не хранится.

Добавочная таблица generation_attempts хранит ID, message_id, сессию, состояние,
запрошенную/возвращённую модель при наличии, время, длительность, начало внешней
попытки и неопределённость исхода, привязку фактической истории и
snapshotReceivedAt, индекс, полный retrieval, переданные/выбранные ID,
messages_bytes и инженерную estimated_tokens, доступный usage, ошибку и
assistant_message_id. Время приёма снимка не меняется при повторе.
Отсутствующий usage — SQL NULL; отсутствующие поля внутри usage не добавляются.
Сохраняются доступные prompt/completion/total tokens, cache hit/miss,
prompt_tokens_details.cached_tokens и completion_tokens_details.reasoning_tokens;
самих рассуждений нет. На старте незавершённые попытки становятся interrupted,
без продолжения и без нового внешнего вызова. Их длительность — наблюдаемый
интервал до восстановления, не доказательство времени работы провайдера.

Ключ не передаётся MCP/браузеру, не записывается в БД, prompts или логи.
[Настройки и запуск](../README.md#deepseek-в-панели-помощь).


### Семантическая область ответа

SYSTEM задаёт поддержку фактических возможностей Guitar Trainer, показаний,
стандартного строя, настройки в пределах функций и необходимой диагностики
микрофона, разрешений, системного источника звука и браузера. Отсутствие темы
в FAQ не является основанием для отказа. Отсутствующая функция объясняется по
документации. Постороннее задание получает краткую границу и sourceIds=[];
в смешанном запросе выполняется только продуктовая часть с уместными ID.
История помогает понять продолжение; при недостатке контекста задаётся один
вопрос. Смена роли и раскрытие системных инструкций запрещены инструкцией.

Эти правила не являются дополнительным программным классификатором.
validate проверяет JSON-контракт, а не смысл ответа или релевантность ID.
Валидный HTTP/JSON и наличие источников не подтверждают содержательный успех.
Офлайн-тесты HTTP payload проверяют границу system/user, а поведение модели
оценивается отдельно по сохранённым реальным ответам. Это не гарантия защиты
от любых prompt injection и не пользовательская приёмка.


### Свидетельства T011 и пределы подтверждения

[Результаты сценариев и отдельных повторов](../README.md#границы-поддержки-guitar-trainer-t011)
сопоставлены с изолированными SQLite в режиме read-only. Исходная
`/tmp/opencode/t011-acceptance.sqlite` содержит шесть уникальных попыток;
`/tmp/opencode/t011-acceptance-retest.sqlite` — один отдельно разрешённый
повтор сценария 6. Все succeeded, HTTP 200; семантический успех из этого
не следует. В JSON две attempts исходного шестого сценария относятся ко всему
обращению (сценарии 5 и 6); первый повтор хранится в scenario6Retest, второй —
в scenario6Retest2; для второго отдельный путь изолированной БД в материалах
не указан, а его ID и message_id совпадают с первым повтором. ID попытки
учитывается вместе с БД. Обе копии JSON заявлены побайтно совпадающими;
актуальный SHA-256 проверенной копии с восемью попытками указан в README.
JSON хранит ответы, фрагменты и метки синтетических снимков; значения
снимков и история находятся в соответствующих БД.

Доверенный ответ пользователя подтверждает разрешение одного дополнительного
вызова после корректировки SYSTEM, предварительное объявление шести основных
и одного дополнительного запроса, max_tokens=1200 и отсутствие автоповторов
в согласованном объёме. В журналах наблюдаются шесть и один POST сообщений.
Записи БД содержат retrieval, индекс, модели и usage; полный учёт обращений
вне этих БД и журналов недоступен, как и трассировка каждого исторического
MCP/retrieval/DeepSeek и исходящего max_tokens. Достаточность материалов для C7
остаётся предметом независимого ревью, без утверждения абсолютной полноты.

Исходный ответ 6 нарушил C6: два уточнения и внутренние имена полей;
это замечание ревью 2-009 сохранено. SYSTEM уточнён для одного понятного
действия либо вопроса с учётом истории. Повтор выполнен с другой историей
и error/NotAllowedError вместо idle: он не отменяет исходный результат.
В повторе один вопрос об адресе сопровождается рекомендациями проверить
блокировку и расширения. Ревью 2-019 подтвердило нарушение C6 также в
повторе: несколько проверок и вопрос вместо одного действия либо уточнения,
без объяснения связи с уже предложенными действиями. Ограничение C8
и препятствие технической готовности сохраняются. Usage первого повтора — 2803/139/2942; общий для восьми попыток —
21649/1188/22837. Отсутствующие метрики не заменяются нулями.

В редакции 4 инструкция продолжения ужесточена: ровно одно из двух — одно
следующее конкретное действие либо один вопрос об одном недостающем факте,
без совмещения действия с вопросом, без выдачи списка советов или проверок за
одно действие и без добавления вопроса к такому списку; выбранное явно
связывается с уже предложенным по истории. Пользователь разрешил не более двух
новых вызовов только для сценария 6, max_tokens=1200, без автоповторов.
Перепроверку выполняет посредник по изолированному каналу. После ужесточения
посредник выполнил один такой вызов; результат сохранён как scenario6Retest2:
ответ содержит ровно один вопрос об одном недостающем факте (какой текст
показан в строке состояния), без списка советов и без внутренних имён полей,
sourceIds пуст. Исторические неуспешные ответы (исходный и первый повтор)
сохранены; фактический наблюдаемый исход C6 зафиксирован вторым повтором.
Один наблюдаемый пример не доказывает устойчивое поведение модели.

Рабочий этап новых внешних вызовов не выполняет. Обязательные проверки текущего
дерева и независимое ревью выполняет контроллер; прежние успешные серверные и
браузерные проверки не выдаются за проверку текущего дерева. Второй повтор
учтён в общем бюджете и не даёт гарантии тематики; для него в материалах нет
отдельного пути изолированной БД и полной трассировки MCP/retrieval/исходящего
max_tokens — эти ограничения C7 оценивает независимое ревью. Успешные
офлайн-проверки не подтверждают семантическое поведение модели. Приёмка
пользователя ожидается.

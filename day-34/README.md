# День 34 — веб-ассистент разработки Guitar Trainer

Видео: [демонстрация без звука, 5:24](https://disk.yandex.ru/i/WwwGLw5EXOP7ww).

На странице тюнера есть отдельный чат «Ассистент разработки». Пользователь
описывает цель; DeepSeek Flash сам выбирает файловые инструменты, читает
frontend, готовит изменения, запускает проверку и применяет правки. Чат
показывает итог, diff и результат проверки. После применения страница
перезагружается; переписка хранится в SQLite и восстанавливается.

## Задание и соответствие

Сделать ассистента для чтения, поиска, анализа и создания/изменения файлов
проекта через MCP или доступные инструменты. Реализовать минимум два сценария,
работать минимум с 2–3 файлами, сохранять изменения или показывать diff,
обеспечить повторение. Пользователь задаёт цель, не список файлов. Сдача —
видео и код; оригинал задания сохранён локально в `resources/task.md`.

В решении используются собственные серверные инструменты tool calling;
MCP для редактирования не нужен. Поддержаны поиск по нескольким файлам,
чтение, анализ, подготовка diff и применение изменений frontend. В сохранённой
сессии выполнены три цели: обозначения нот, текст подсказки и цвет нот.
Совокупно изменены четыре файла, включая три файла приложения и один тест.
Обновление документации не входит в область инструментов этой версии.

Сохранён исходный frontend до демонстрационных правок, чтобы запросы можно

ограничений в `app/docs/assistant.md`; в одном тесте удалена лишняя пустая строка
в конце файла без изменения логики. Рабочий проект и его пользовательские
правки не менялись. Секреты, переписка, журналы agentflow, видео, веса, индексы
и окружение в Git не входят.

## Устройство

```text
Страница тюнера → панель «Ассистент разработки» → HTTP API
    → FastAPI + SQLite: отдельная переписка, идемпотентность, результат
    → DeepSeek Flash: выбор tool calls
    → list_files / search / read_file
    → propose_edit: полное новое содержимое файла в staging-копии
    → run_checks → apply → finish
    → сохранение ответа, diff и проверки → перезагрузка → восстановление истории
```

RAG и agentflow в runtime-цикле ассистента разработки не используются.
Существующая панель пользовательской поддержки «Помощь» остаётся отдельным
сервисом с RAG и read-only MCP; они не предоставляют права редактирования.

Файловый allowlist в `server/assistant_scope.py` разрешает фиксированный набор
HTML/CSS/JS тюнера и прямые `web/test/*.mjs`. Прямые обращения к backend, `.env`,
Git, данным, другим проектам и `web/src/assistant.js` отклоняются; проверяются
абсолютные пути, `..` и символические ссылки. Системная инструкция ограничивает
тематику frontend текущего проекта. Инструментов shell, Git, установки пакетов
и выбора корня нет.

Кандидаты создаются во временной копии `web/`. Перед применением проверяются
исходные хэши; после успешной проверки файлы заменяются через `os.replace`.
Есть один процессный допуск без очереди. API выполняет всю задачу в одном
запросе: промежуточных событий и потокового прогресса в этой версии нет.

Модель — `deepseek-flash`, `thinking.type=disabled`, `stream=false`,
`max_tokens=4000`. По умолчанию до 40 шагов, 60 с ожидания одного запроса,
300 с общего бюджета, проверяемого между ходами. Файлы передаются модели
полностью; автоматических повторов внешних вызовов нет. Токены и стоимость
демонстрации этим ассистентом отдельно не сохраняются.

## Запуск

Нужны Python 3.14, uv, Node.js 22+ и браузер. Сервер слушает только loopback.

```bash
cd day-34/app
uv sync --locked
test -e .env || cp .env.example .env
# Задать DEEPSEEK_API_KEY в локальном .env или системной переменной.
uv run python -m server.main
```

Открыть [http://localhost:8000/](http://localhost:8000/), нажать «Ассистент
разработки». Для этого чата не нужны модель E5 и retrieval-индекс. Нужны сеть и
доступный баланс DeepSeek. Не смешивать localhost и 127.0.0.1: cookie разные.
Другой порт задаётся `GUITAR_TRAINER_PORT`.

Чтобы также пользоваться прежней панелью «Помощь», отдельно выполнить:

```bash
uv run python -m server.retrieval prepare-model
uv run python -m server.retrieval build-index
```

Эти команды загружают локальную модель и строят индекс статей. Они не нужны
для правок frontend. Все runtime-данные создаются в игнорируемом `app/data/`.

## Повторение демонстрации

Запускать на отдельной копии исходного `app/`, без секретов и данных исходного
проекта; сделать резервную копию frontend перед редактированием. Ассистент
действительно изменяет файлы приложения, автоматического отката из чата нет.

1. Открыть чат и отправить «Поменяй ноты на До, Ре, Ми».
2. После перезагрузки проверить русские подписи и восстановленную переписку.
   Показать сохранённый diff.
3. Отправить «Замени “дёрните струну” на “сыграйте ноту”», затем
   «Закрась ноты в жёлтый». Проверить подсказку, цвет, diff и результаты тестов.
4. Проверить отказы: рецепт, чтение `.env`, изменение backend, коммит.

Имена файлов в пользовательских запросах не задаются. Состав правок и ответы
модели могут отличаться при повторении. Перезагрузка сбрасывает состояние
тюнера; микрофон включается только пользователем. Точность тюнера настоящей
гитарой при подготовке сдачи не проверялась.

## Проверки публикационного снимка

```bash

mkdir -p data/tmp
uv run --no-sync --offline pytest -q
node --test web/test/*.test.mjs
uv lock --check --offline
```

Полный backend-набор включает один тест настоящего E5-токенизатора. Для него
нужны веса, подготовленные командой `prepare-model`; прочие проверки используют
подмены провайдера и тестовые данные.

16.10.2026 проверены:

- 234 разных backend-теста: в полном запуске 233 прошли, один упал из-за
  отсутствия E5-весов в новом снимке; после копирования имеющихся локальных

## Выводы и ограничения

Ассистент выполняет реальные правки по целям и сохраняет проверяемые diff.
Три примера покрывают HTML, JS, CSS и тест, а отказы демонстрируют тематические
границы на конкретных запросах. Они не доказывают защиту для любых инструкций.

Фактическая версия отличается от первоначального плана:

- frontend-тесты доступны модели на запись; успешная проверка не является
  независимой гарантией корректности;
- для изменённых JS применяется `node --check`, для изменённых тестов — только
  эти тесты; полный web-набор автоматически запускается при HTML/CSS-правках
  без изменённых исполняемых файлов. Это слабее полного регрессионного прогона;
- Node запускается без изоляции ОС и с наследуемым окружением. Исполняемый
  тестовый JS может обойти границы прямых файловых инструментов. Версия только
  для локальных экспериментов с доверенными запросами, не защищённая песочница;
- защищён отдельный JS панели, но общий HTML/CSS доступен редактированию и
  может нарушить её работу;
- откат при ошибке записи best-effort; при аварии процесса нет постоянного
  журнала восстановления файлов. Несколько замен не являются общей атомарной
  транзакцией. Ошибка после применения может оставить уже применённые файлы;
- каждый новый запрос модели получает текущую цель и результаты своих
  инструментов; сохранённая переписка восстанавливается в UI, но полная история
  предыдущих целей в модель не передаётся;
- полная перегенерация файлов ограничена 4000 токенами; большие файлы могут
  завершаться `provider_output_limit`. Промежуточного прогресса нет.

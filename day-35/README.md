# День 35 — личный AI-ассистент в Telegram

Видео: [демонстрация без звука, 5:23](https://disk.yandex.ru/i/cdpACfiKoLhPwQ).

Решаемая задача — сохранять личные факты и события обычными сообщениями,
находить нужное естественным вопросом и получать напоминания о делах.
Telegram служит привычным интерфейсом; голосовые сообщения распознаются
локально, а DeepSeek понимает запрос и выбирает прикладные инструменты.

## Задание

Придумать реальную задачу автоматизации и сделать AI-приложение или сервис,
работающий в реальном окружении. Описать задачу и показать участие AI.
Допускается неполная готовность из-за ключей и доступов. Формат сдачи — видео
и код. Оригинал условия сохранён локально в `resources/task.md`.

## Исходники и возможности

[app/](app/) — самостоятельный снимок `personal-assistent` от 18.10.2026:
основа `52b55b2644c7b20649c47ed08792f3728b9fc5ba` плюс текущие локальные
изменения сжатия контекста и немедленного `/new`, использованные при записи.
Соседний рабочий репозиторий для запуска не нужен и не изменялся при публикации.
В копии одного теста удалена лишняя пустая строка в конце без изменения логики.
Личная база, переписка, ключи, веса моделей и окружение не включены.
Контрольный корпус в `app/evaluations/memory.json` содержит вымышленные данные.

- Памятки: создание, поиск, чтение, исправление и удаление.
- Разовые и повторяющиеся напоминания, перенос, отмена и откладывание кнопкой.
- Календарные события, дни рождения и явно включаемая месячная сводка.
- Постоянный профиль: часовой пояс, язык, стиль, обращение и общее время уведомлений.
- Голосовой ввод через отдельный локальный HTTP-сервис GigaAM.
- SQLite хранит данные, очереди, поручения, квитанции действий и checkpoint.

## Как участвует AI

```text
Текст Telegram ──────────────────────────┐
Голос Telegram → локальная GigaAM → текст ├→ агент DeepSeek → инструменты → SQLite
                                        └→ ответ пользователю через Telegram
Планировщик SQLite → очередь доставки → уведомление Telegram
```

DeepSeek Flash через Chat Completions и tool calling разбирает намерение,
извлекает параметры, задаёт уточнения и выбирает инструменты. Для ответов по
памяткам предусмотрен отдельный этап сбора и проверки источников: код проверяет
ID и точные цитаты из актуального текста. Поиск использует FTS5 и русский стемминг,
без векторного индекса. Решение о смысловой релевантности остаётся модельным.

Код валидирует параметры, применяет изменения транзакционно и формирует
подтверждения по квитанциям сохранённых действий. Планировщик проверяет сроки
без AI. Модель не получает shell, файловые инструменты или API-ключи.
Незавершённая обработка восстанавливается с checkpoint без повторного применения
уже сохранённых вызовов. История сжимается в постоянную сводку в пределах бюджета.

## Запуск

Нужны Linux, Python 3.14, `uv`, доступ к Telegram и DeepSeek API.

```bash
cd day-35/app
uv sync --locked
cp -n .env.example .env
```

Создайте бота через [BotFather](https://t.me/BotFather) и заполните локальный `.env`:
`TELEGRAM_BOT_TOKEN`, `TELEGRAM_OWNER_ID` (числовой user ID владельца),
`DEEPSEEK_API_KEY`. Ключи не публикуйте. Затем:

```bash
uv run python -m personal_assistent
```

Бот работает через long polling, без публичного IP и входящего порта.
Другие пользователи и группы игнорируются. На одной базе запускается один
процесс; активный webhook нужно отключить самостоятельно. Новая база создаётся
в `app/data/assistant.sqlite3`. Для повторения демонстрации личная база не нужна.
Ctrl+C завершает программу.

### Голосовой ввод

Установите системный `ffmpeg`, затем:

```bash
uv sync --locked --extra voice
uv run python -m personal_assistent.setup_voice
```

Подготовка скачивает около 854 МиБ весов GigaAM v3 E2E-RNN-T FP32 и Silero VAD
в `data/voice-models`. Ревизии и SHA-256 закреплены в
[voice_models.py](app/personal_assistent/voice_models.py). Веса не входят в Git.
Распознавание работает на CPU; Handy не требуется.

В `.env` задайте `ASSISTANT_VOICE_ENABLED=true` и запустите оба процесса:

```bash
uv run python -m personal_assistent.launch
```

Launcher ждёт готовности сервиса, затем запускает бота и завершает оба процесса
при остановке. Сервис по умолчанию слушает `127.0.0.1:8765`:

```bash
curl -s http://127.0.0.1:8765/health
```

Ответ содержит `ready`, `model`, `pid`, `busy`. При настроенном
`VOICE_SERVICE_TOKEN` проверка требует Bearer-авторизации. Для подключения вне
localhost токен обязателен; используйте закрытую сеть либо HTTPS через proxy.
Сервис сам TLS не завершает. По умолчанию голос ограничен 10 МиБ и 300 секундами.
Распознанный текст сохраняется и передаётся обычному агенту DeepSeek: весь
ассистент не является офлайн-приложением.

### Команды

| Команда | Назначение |
| --- | --- |
| `/start`, `/help` | Справка и примеры |
| `/profile` | Постоянные настройки |
| `/stats` | Накопленный расход токенов и время API |
| `/request` | Незавершённое поручение |
| `/cancel` | Остановить обработку и отменить черновик, сохранив уже применённые действия |
| `/new` | Сразу начать новую беседу, сохранив памятки, события, напоминания и профиль |

Команды выполняются только из текста, не из распознанной речи. Настройки и
данные меняются естественными просьбами, например «Отвечай кратко» или
«Напоминай по будням в 18:00 закончить работу».

Сохранённая сессия 18.10.2026, 15:43–15:47 (Europe/Kirov) подтверждает:

1. После `/new` начата новая беседа, показан `/profile`.
2. Текстом сохранена памятка о замене фильтра 18 октября и месте запасного.
   Создание подтверждено квитанцией и записью SQLite.
3. На вопрос «Где лежит запасной фильтр?» получен ответ «В шкафу над холодильником».
4. Голосовое «Когда я менял фильтр в кувшине» распознано; ответ — 18.10.2026.
5. Просьба «Напомни через минуту проверить духовку» создала напоминание
   на 15:46:38. Отправка Telegram подтверждена в 15:46:38, без повторных попыток.
6. `/stats` показал накопленный расход; второй голосовой вопрос получил
   ответ по сохранённым дням рождения октября.
7. Нажатие кнопки откладывания в 15:47:16 создало одно новое напоминание
   на 15:57:16. Его будущая доставка не проверялась при анализе записи.

В интервале основного сценария выполнены 22 успешных AI-вызова:
15 рабочих, 6 сбора источников, 1 сводки. Расход — 157 533 входных и
1 231 выходной токен; суммарное время API около 31,88 с.
Показанная `/stats` статистика включает и предыдущие сессии, поэтому её
общие числа и ошибки не равны показателям этого сценария.

Перед `/new` зафиксирован отказ из-за переполненного рабочего контекста.
После сброса основной сценарий прошёл без ошибок API. Это ограничивает
вывод о длительных беседах; демонстрация подтверждает конкретные действия,
а не безошибочную работу при любой длине истории.

Видео технически проверено: MP4/H.264, 2560×1440, 323,4864 с, одна видеодорожка,
без аудио. Визуальная проверка не выполнялась; результаты выше подтверждены
сохранёнными данными приложения, а не просмотром кадров.
Публичный объект проверен через API Яндекс Диска: имя `day-35-result.mp4`,
размер 29 815 075 байт, MD5 и SHA-256 совпадают с локальным видео,
`antivirus_status=clean`; публичная страница отвечает HTTP 200 без авторизации.

## Проверки и ограничения

На публикуемом снимке прошли **567 тестов**, включая HTTP-тесты голосового
сервиса с локальным сокетом. Успешны установка `uv sync --locked --extra voice`
в новое окружение, компиляция Python, `uv lock --check --offline` и проверка
пробелов Git. Код и тесты совпадают с рабочими файлами, кроме указанной пустой строки.
Бесплатный прогон всех 32 вопросов завершён; в первой странице поиска для
Q11, Q12 и Q13 отсутствует часть эталонных источников. Это не проверка итоговых
ответов модели и не доказательство полноты последующего добора.
Веса GigaAM заново не скачивались; живой запуск снимка с Telegram и DeepSeek
при публикации не выполнялся.

Команды проверки снимка из `day-35/app`:

```bash
uv sync --locked --extra voice
uv run python -m unittest discover -s tests -v
uv run python -m compileall -q personal_assistent tests
uv lock --check
uv run python -m personal_assistent.evaluate_memory
```

Офлайн-тесты проверяют серверное поведение на синтетических данных и подменных
ответах моделей/API. HTTP-тесты сервиса используют локальный сокет и подменный
распознаватель; они не измеряют качество GigaAM. Оценка памяти по умолчанию
проверяет только первый поиск, без внешних API; подробности —
[evaluations/README.md](app/evaluations/README.md).

Компьютер должен работать: во сне и при остановленном боте доставки нет.
После простоя досылка зависит от срока и начала события. Потерянное подтверждение
Telegram может привести к повторной доставке. Смысловые ошибки AI и пропуски
поиска возможны; квитанция подтверждает изменение базы, а не будущую доставку.
Длинный JSON проверки источников может не поместиться в выходной лимит модели.
GPU и другие ОС не проверялись. Новые внешние AI-вызовы при публикации не нужны
и не выполнялись; собственные токены и отдельная загрузка моделей необходимы
для повторения живого запуска.

Практический результат: факт можно сохранить и найти без точного совпадения
формулировок, а просьба о напоминании приводит к реальному уведомлению в Telegram.
Голосовой ввод использует тот же прикладной процесс, что и текст.

# День 12. Персонализация ассистента

Textual-приложение позволяет одному пользователю создавать несколько профилей ассистента, редактировать их и выбирать активный профиль для каждой сессии.

Профиль содержит:

- название;
- обращение к пользователю;
- язык ответа;
- стиль;
- формат ответа;
- ограничения.

Это явные настройки, а не память диалога. Активный профиль преобразуется в инструкции и добавляется в `system` каждого API-запроса. История сессии передаётся после `system` отдельными сообщениями `user` и `assistant`.

## Запуск

```bash
cd ~/Dev/AI_Advent_Challenge/day-12
uv sync --locked
cp .env.example .env
```

Добавить `DEEPSEEK_API_KEY` в `.env` и запустить:

```bash
uv run --locked python main.py
```

Для чистого эксперимента можно выбрать отдельный каталог данных:

```bash
uv run --locked python main.py --data-dir /tmp/day-12-profiles
```

## Как устроены профили

При первом запуске создаются два демонстрационных профиля:

- `Краткий техлид` — деловой ответ ровно из трёх коротких пунктов, до 80 слов;
- `Обучающий наставник` — объяснение для начинающего с разделами `План`, `Пример` и `Проверка`, до 250 слов.

Профили можно создавать и редактировать в правой панели. Кнопка `Новый` заполняет все обязательные поля нейтральными значениями: профиль можно сразу сохранить либо сначала настроить. Результат сохранения и ошибки показываются рядом с кнопками. Удаление требует повторного нажатия; единственный профиль удалить нельзя. Профиль, используемый другой сохранённой сессией, также не удаляется.

Выбор профиля сохраняется в активной сессии. При возврате к старой сессии восстанавливаются её профиль, диалог и последний фактически отправленный массив `messages`.

Локальные данные физически разделены:

```text
data/
├── profiles/demo.json
└── sessions/session-XX.json
```

Оба вида JSON исключены из Git. Запись выполняется атомарно; повреждённые данные не перезаписываются автоматически. При ошибке или незавершённом ответе API история не изменяется.

## Сборка запроса

Каждый вызов модели получает один заново собранный `system`:

```text
базовые правила приложения
+ активный профиль пользователя
+ история выбранной сессии
+ новый вопрос
```

Во вкладке `Фактический prompt` до первого вызова показывается предварительная сборка следующего запроса, а после ответа — точный массив сообщений, который был отправлен API. Профиль не записывается в пользовательское сообщение и не дублируется в истории.

## Автодемо

`Ctrl+D` или кнопка `Автодемо` выполняет три запроса:

1. задаёт вопрос о плане изучения асинхронного Python профилю `Краткий техлид`;
2. задаёт тот же вопрос в новой сессии профилю `Обучающий наставник`;
3. задаёт наставнику вопрос «С чего мне начать сегодня?» без повторения настроек профиля.

Первые два запроса различаются профилем, а не формулировкой вопроса. Третий показывает автоматическое применение профиля. Созданные сессии остаются в списке, поэтому ответы и их фактические prompts можно сравнить после демо.

## Фактическая демонстрация

В ручном прогоне выполнено восемь запросов в трёх сессиях с тремя профилями:

| Профиль | Проверка | Фактический результат |
| --- | --- | --- |
| `Краткий техлид` | вопросы о сортировке Python | ответы состоят ровно из трёх коротких пунктов; лишнего вступления, эмодзи и непрошеного кода нет |
| `Стихоплёт` | три последовательные реплики о стуке в дверь | каждый ответ состоит из трёх строк, сохраняет мрачную иронию и не содержит пояснений вне стихотворения |
| `Обучающий наставник` | реализация пузырьковой сортировки | ответ разделён на `План`, `Пример` и `Проверку`, содержит код и объяснения терминов |

В сессии со `Стихоплётом` профиль был указан один раз, однако два следующих вопроса без напоминания настроек также получили трёхстрочные стихотворные ответы. В другой сессии последовательное переключение профилей изменило один и тот же разговор о сортировке: стихотворение сменилось учебным разбором, а затем тремя краткими пунктами.

Сохранённые `last_request_messages` подтверждают механизм: первый элемент каждого последнего запроса имеет роль `system` и содержит активный профиль, после него идут история сессии и новый вопрос. Профиль не дублируется среди сообщений пользователя.

## Выводы

- Структурированных полей стиля, формата и ограничений достаточно, чтобы один агент заметно менял форму ответа без изменения модели и API-кода.
- Профиль применяется автоматически, потому что приложение заново добавляет его в `system` каждого запроса; пользователю не приходится повторять предпочтения в диалоге.
- Профиль остаётся отдельной настройкой: его можно переключить, сохранив историю разговора, либо закрепить за отдельной сессией.
- Чем формальнее ограничение, тем проще проверить результат: требования «ровно три строки» и «ровно три пункта» проявились непосредственно в ответах.

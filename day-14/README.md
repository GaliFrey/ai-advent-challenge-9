# День 14. Инварианты ассистента

Textual-приложение реализует чат с двумя профилями. Каждый профиль ссылается на собственный набор обязательных инвариантов. Выбор профиля меняет пустую сессию на месте; если диалог уже начат, автоматически создаётся новая сессия, а прежняя история не изменяется.

## Профили

`Russian tech lead`:

- `TECH-LANG-001` — основной текст на русском;
- `TECH-CODE-001` — программные решения и примеры кода только на Python 3.12+;
- `TECH-UV-001` — для Python используется `uv`, а не `pip`, `venv` и `requirements.txt`;
- `TECH-EVIDENCE-001` — нельзя выдавать непроверенный результат за факт.

`English tutor`:

- `TUTOR-LANG-001` — основной текст на английском;
- `TUTOR-ATTEMPT-001` — не давать готовое учебное решение до попытки ученика;
- `TUTOR-TERMS-001` — кратко объяснять существенные термины.

Одинаковый запрос может быть разрешён в одной сессии и отклонён в другой. Английский ответ запрещён техлиду, но обязателен для tutor.

## Хранение и проверка

```text
config/
├── profiles.json
└── invariant_sets/
    ├── tech-lead-v1.json
    ├── tech-lead-v2.json
    └── english-tutor-v1.json
data/
├── sessions/session-XX.json
└── audits/session-XX.jsonl
```

Сессия хранит ID профиля, ID, версию и SHA-256 набора. Изменение файла блокирует незаметное продолжение старой сессии с другими правилами. Профиль и инварианты добавляются в один `system` каждого API-запроса, но не копируются в диалог.

Каждое сообщение обрабатывается одним вызовом `deepseek-v4-flash`. Модель возвращает не свободный служебный текст, а JSON с `decision`, списком нарушений с доказательствами и пользовательским `response`. Приложение не пытается распознать смысл запроса регулярными выражениями: оно проверяет структуру JSON, согласованность решения, принадлежность ID активному набору и только наблюдаемые свойства готового ответа (язык основного текста, fenced-блоки кода и команды Python-инструментов). Нарушающий post-check кандидат заменяется детерминированным отказом.

Это демонстрация архитектуры, а не абсолютная гарантия соблюдения смысловых правил: их классифицирует та же модель, которая формирует ответ. Структурный контракт делает решение проверяемым и пригодным для аудита, но не доказывает правильность модельной оценки.

Вкладка `Проверка` разделяет результат последнего хода и счётчик отказов за всю сессию. Решения сохраняются в сессии как отдельные метаданные и не восстанавливаются из формулировки ответа. Для ранее созданных сессий оставлена только совместимость чтения старых текстовых отказов. Служебный system prompt формируется на русском; требуемый язык ответа задаётся инвариантом профиля.

## Запуск

```bash
cd ~/Dev/AI_Advent_Challenge/day-14
uv sync --locked
cp .env.example .env
uv run --locked python main.py
```

Для чистой демонстрации:

```bash
uv run --locked python main.py --data-dir /tmp/day-14-demo
```

`Ctrl+D` запускает три модельных хода: отказ техлида, разрешённый ответ tutor и его отказ выдать готовое решение без попытки ученика.

## Результат демонстрации

В записанном прогоне выполнено пять реальных запросов к `deepseek-v4-flash` в двух сессиях:

- `Русский техлид`: запрос реализации сортировки на Go отклонён по `TECH-CODE-001`, вариант на Python 3.14 разрешён;
- `English tutor`: приветствие разрешено, две попытки переключить ответ на русский отклонены по `TUTOR-LANG-001`;
- итого: 2 ответа `ALLOWED`, 3 ответа `REFUSED`, 3 709 API-токенов и 8,31 секунды суммарного времени запросов.

Отказы содержат ID нарушенного инварианта, объяснение и допустимую альтернативу. Вкладка `Проверка` показывает доказательство для последнего решения и накопленные нарушения сессии, а `Фактический prompt` подтверждает, что профиль и инварианты передаются отдельно от истории диалога.

## Выводы

- Разные профили действительно задают разные неизменяемые рамки: русский ответ обязателен для техлида и запрещён для English tutor.
- Структурированный JSON устраняет угадывание решения по формулировке ответа и позволяет проверить ID инвариантов, сохранить решение и построить audit.
- Смысловой конфликт всё ещё классифицирует LLM, поэтому абсолютной гарантии нет; детерминированная часть контролирует контракт и наблюдаемые свойства готового ответа.

# День 16 — подключение к публичным MCP-серверам

## Задание

Установить MCP SDK / клиент (или поднять MCP-сервер при локальном варианте).
Написать минимальный код, который устанавливает MCP-соединение, получает и
выводит список доступных инструментов. Проверить успешное соединение и
корректное получение списка. Формат сдачи: **видео + код**.

Уточнение Алексея Гладкова в чате курса от 21.09.2026, 14:03, сообщение 3554:

> Здесь пока с MCP работать не нужно просто запросить геттулз у любого общедоступного mcp

В протоколе получение списка называется `tools/list`. Вызов инструментов и
подключение LLM для этого задания не нужны.

## Решение

Самостоятельный Python-проект с Textual TUI и официальным MCP Python SDK.
Весь код и зависимости находятся в этом каталоге; импорты из других дней,
API-ключи, `.env`, локальный MCP-сервер и LLM не требуются.

В `servers.py` зашит список публичных серверов без авторизации:

| Сервер | URL | Назначение |
| --- | --- | --- |
| Microsoft Learn | `https://learn.microsoft.com/api/mcp` | Документация Microsoft |
| DeepWiki | `https://mcp.deepwiki.com/mcp` | Информация о публичных GitHub-репозиториях |
| Cloudflare Docs | `https://docs.mcp.cloudflare.com/mcp` | Документация Cloudflare |

Адреса сверены с первичными источниками:
[Microsoft Learn](https://learn.microsoft.com/en-us/training/support/mcp),
[DeepWiki](https://mcp.deepwiki.com/),
[Cloudflare](https://developers.cloudflare.com/agents/model-context-protocol/cloudflare/servers-for-cloudflare/).
Для добавления сервера достаточно добавить `Server` в `SERVERS`; клиент
поддерживает здесь только Streamable HTTP без авторизации.

Интерфейс позволяет выбрать сервер и нажать `Получить инструменты`.
Слева появляется список имён, справа — название, полное описание и
`inputSchema` выбранного инструмента. Первый инструмент выбран автоматически;
перемещение по списку — стрелками или мышью. Длинные описания и схемы можно
прокручивать. Внешний текст выводится без интерпретации Rich-разметки.

После запроса интерфейс показывает объём всего списка tools, а в карточке —
объём выбранного инструмента: точное число символов, размер компактного JSON
в UTF-8 и примерное число токенов. В расчёт входят фактически полученные поля
MCP с протокольными именами, без `null`-полей. Оценка использует прозрачное
правило `4 символа ≈ 1 токен` и округление вверх. Это сравнительная метрика,
а не биллинг провайдера: точное число зависит от конкретного токенизатора и
формата, в котором клиент передаст tools модели. Само приложение LLM не вызывает.

При смене сервера предыдущий результат очищается. Во время запроса виден
индикатор ожидания, выбор сервера и кнопка запроса заблокированы, а интерфейс
продолжает обрабатывать события. Пустой список показан отдельно от ошибки.
После ошибки можно повторить запрос или выбрать другой сервер. Повторный
запрос всегда получает свежие данные; результаты хранятся только в памяти.

## Запуск

Нужны Python 3.11+ и `uv`. Из корня репозитория:

```bash
cd day-16
uv sync --locked
uv run --locked python main.py
```

Можно также скопировать только каталог `day-16` и выполнить те же две команды
`uv` внутри него. Материалы из `resources/` для запуска не нужны.
Рекомендуемый размер терминала — от 100 столбцов и 28 строк.
`Tab` переключает фокус между элементами, `Enter` активирует выбранный
элемент, `Ctrl+Q` завершает приложение.

Для установки зависимостей нужен доступ к PyPI, для получения tools — HTTPS-доступ
к выбранному серверу. Установка дополнительных плагинов в кодовый ассистент
не требуется: запросы выполняет само приложение.

## Как устроено подключение

```text
Выбор сервера → кнопка запроса → Streamable HTTP
  → ClientSession.initialize()
  → проверка capability tools
  → tools/list, включая следующие страницы
  → закрытие сессии → показ полученного списка в TUI
```

Статус содержит имя и версию, которые сообщил сервер, согласованную версию
протокола и количество инструментов. «Соединение проверено» означает
завершившийся запрос; постоянное подключение для просмотра результата не нужно.

Общий тайм-аут подключения, инициализации и получения списка — 30 секунд.
Повторяющийся курсор пагинации приводит к явной ошибке. Частичный список
при ошибке следующей страницы не выдаётся за полный результат. Вложенные
ошибки SDK разворачиваются до причины, соединения закрываются через
асинхронные контекстные менеджеры, в том числе при отмене.

Код использует API MCP SDK **2.2.0** и Textual **8.2.8**, версии закреплены в
`uv.lock`. В SDK 2.x используются `input_schema` и `next_cursor` в Python;
на уровне протокола это `inputSchema` и `nextCursor`.

## Файлы

- `main.py`, `app.tcss` — TUI и оформление.
- `servers.py` — фиксированный список названий и URL.
- `mcp_client.py` — соединение, инициализация, пагинация, ошибки.
- `tool_metrics.py` — сериализация и статистика объёма tools.
- `test_mcp_client.py`, `test_tool_metrics.py`, `test_app.py` — локальные тесты без внешней сети.
- `pyproject.toml`, `uv.lock` — собственные зависимости проекта.
- `resources/` — локальные материалы ДЗ, проверок и видео, исключённые из Git.

## Проверки и фактический результат

```bash
uv run --locked python -m unittest -v
uv run --locked python -m compileall -q main.py mcp_client.py servers.py tool_metrics.py test_app.py test_mcp_client.py test_tool_metrics.py
uv lock --check
```

21.09.2026 прошли **14 локальных тестов**. Проверены получение всех страниц,
пустой список, отсутствие capability tools, повтор курсора, тайм-аут,
вложенная ошибка и отмена с закрытием соединения. Headless-тесты TUI проверяют
выбор сервера, автоматический показ первого инструмента, навигацию к другому,
схему параметров, очистку старых данных, состояние ожидания, блокировку
повторного запроса и восстановление после ошибки. Отдельно проверены UTF-8,
компактная MCP-сериализация, округление оценки токенов и суммарная статистика.

Реальная проверка 21.09.2026 в 17:20 (Europe/Kirov) завершилась успешно для всех

Полные ответы этой проверки сохранены локально в `resources/mcp-check.json`.
Они не нужны для работы приложения и не подменяют ответы сервера.
Названия, количество инструментов и доступность публичных серверов могут
измениться; приложение показывает фактически полученный список.

Реальные запросы проверялись через тот же `discover_tools`, который вызывает
TUI. Интерактивная визуальная проверка терминального интерфейса не выполнялась;
его поведение проверено headless-тестами. LLM-вызовов не было.

## Выводы

- Один MCP-клиент через общий протокол получил инструменты трёх независимых
  публичных серверов без специальной логики для каждого сервиса.
- Серверы согласовали разные версии MCP, но одинаковая последовательность
  `initialize → tools/list` корректно отработала во всех трёх случаях.
- Даже небольшие списки из двух-трёх tools заметно различаются по объёму:
  от примерно 379 до 1 215 токенов. Поэтому стоимость контекста зависит не
  только от числа инструментов, но и от подробности их описаний и схем.
- Оценка токенов полезна для сравнения серверов, но реальный расход появится
  только при передаче tools конкретной LLM и зависит от её токенизатора.

## Сценарий демонстрации

1. Показать фиксированные URL в `servers.py` и инициализацию/`list_tools` в `mcp_client.py`.
2. Запустить TUI, выбрать Microsoft Learn и нажать `Получить инструменты`.
3. Показать статус успешного запроса, суммарную оценку токенов, описание,
   параметры и объём одного инструмента.
4. Выбрать DeepWiki: старый список очистится. Повторить запрос и показать новый набор tools.
5. Аналогично запросить Cloudflare Docs, затем выйти через `Ctrl+Q`.

Локальная запись хранится как `resources/day-16-result.mp4` и исключена из Git.

# День 33 — AI-поддержка Guitar Trainer

Видео: [демонстрация без звука, 3:44](https://disk.yandex.ru/i/5njiJDKplxQgEg).

В микрофонный тюнер встроена панель «Помощь». DeepSeek Flash отвечает по
пользовательским статьям и учитывает историю обращения и диагностический
снимок текущего сообщения. Документация поступает через локальный RAG,
контекст обращения — через настоящий MCP stdio.

## Задание

Сделать мини-сервис поддержки: ответы о продукте, RAG по FAQ/документации,
учёт пользователя или тикета, подключение CRM либо данных обращений через MCP.
Формат сдачи — видео + код. Оригинал сохранён локально в `resources/task.md`.
В этом решении обращения хранятся в SQLite, внешний CRM-сервис не используется.

## Код и архитектура

[app/](app/) — самостоятельный снимок нового Guitar Trainer из локального
коммита `0d330682b70e8fac655fa2225d8885e9ceaff5d9` от 15.10.2026.
Этот проект переписан с нуля и отличается от приложения дней 31–32.
В рабочем репозитории нет настроенного remote, поэтому необходимые исходники,
статьи, тесты и lock-файл включены в сдачу. Соседний репозиторий для запуска
не нужен. `.env`, переписка, веса, индексы и агентные журналы не публикуются.

```text
Браузер: тюнер + панель помощи + снимок при отправке сообщения
    ↓ HTTP, один origin
FastAPI + SQLite: сессия, обращение, сообщения, снимки
    ↓ MCP stdio: initialize → tools/list → tools/call
get_ticket_context: история и снимок разрешённого сообщения
    ↓
Локальный RAG: E5-small на CPU → до трёх фрагментов статей
    ↓
DeepSeek Flash → проверка JSON и ID источников → сохранение → веб-чат
```

- MCP-процесс получает read-only доступ и область конкретного обращения
  и сообщения. Браузер не использует MCP напрямую.
- RAG индексирует только три `docs/support/*.md`: начало работы, FAQ,
  решение проблем. Разбиение по Markdown-разделам с учётом токенизатора;
  текущий индекс содержит 31 чанк. Модель — `intfloat/multilingual-e5-small`,
  ревизия `614241f622f53c4eeff9890bdc4f31cfecc418b3`, 512 токенов на вход.
  Веса загружаются отдельной командой (487 726 239 байт), далее поиск локальный.
- Снимок разделяет стадию захвата, ошибку, состояние дорожки/AudioContext,
  RMS и частоту последнего кадра, показание экрана и возраст обоих результатов.
  `null` не означает ноль, отсутствие частоты не доказывает тишину.
- DeepSeek получает ограниченную историю, снимок и выбранные статьи;
  звук и аудиобуферы не передаются. Уведомление видно до отправки сообщения.
  Используются `deepseek-flash`, `thinking.type=disabled`, JSON Output,
  лимит ответа 1200 токенов; автоматических повторов нет.
- Модель выбирает ID источников, сервер формирует ссылки на сохранённые
  фрагменты. Проверка формата и ссылок не доказывает истинность ответа.
- Тематика ограничена Guitar Trainer и необходимой поддержкой микрофона
  и браузера. Это системные инструкции модели, не абсолютная гарантия.

Подробнее: [архитектура](app/docs/architecture.md),
[HTTP API](app/docs/support-api.md), [диагностический контракт и MCP](app/docs/support-context.md).

## Запуск

Нужны Python 3.14, uv, Node.js для web-тестов и браузер на компьютере.
Сервер слушает только loopback. Публичное развёртывание не выполнялось.

```bash
cd day-33/app
uv sync --locked
test -e .env || cp .env.example .env
# Задать DEEPSEEK_API_KEY в локальном .env или окружении, не публиковать ключ.
uv run python -m server.retrieval prepare-model
uv run python -m server.retrieval build-index
uv run python -m server.main
```

Открыть [http://localhost:8000/](http://localhost:8000/), нажать «Помощь».
Для тюнера нажать «Включить микрофон» и разрешить доступ.
Запуск предполагает свободный порт 8000; другой задаётся `GUITAR_TRAINER_PORT`.
Для чата нужен интернет и оплачиваемый DeepSeek API. Поиск не загружает модель
при обычном запуске; при изменении статей индекс нужно перестроить явно.
Модель, индекс и SQLite находятся в игнорируемом `app/data/`.

## Проверки публикационного снимка

```bash
cd day-33/app
mkdir -p data/tmp
uv run --no-sync --offline pytest -q
node --test web/test/*.test.mjs
uv lock --check --offline
uv run --no-sync --offline python -m server.retrieval evaluate --offline
```

15.10.2026 непосредственно на снимке сдачи прошли:

- 174 backend-теста: контракт, настоящий stdio MCP, изоляция обращений,
  идемпотентность, RAG, ошибки и подменённый провайдер без платных вызовов;
- 62 web-теста: тюнер, диагностика, захват и интерфейс поддержки;
- `uv sync --locked --offline` и проверка lock-файла;
- реальный локальный retrieval: ожидаемый раздел в top-3 для 20/20 основных
  и 4/4 отложенных вопросов. Три вопроса без ответа рассматриваются отдельно;
  найденный кандидат не означает, что в статье есть ответ.

Первый запуск pytest потребовал создания родительского `data/tmp`; после
создания каталога полный набор прошёл. Команда выше включает этот шаг.
Платный провайдер в тестах подменён; реальные ответы проверены по сохранённым
данным записи. Новую браузерную проверку приложения при публикации не запускали.

В исходном проекте T006–T011 имеют статус `accepted`; для T010/T011 сохранены
независимые ревью. Тематические сценарии разработки проверяли рецепт,
смешанный запрос, смену роли и продолжение «Не помогло»; последний потребовал
двух исправляющих повторов. Это исторические результаты, не новые вызовы.

## Выводы и ограничения

RAG даёт инструкции о продукте, MCP добавляет состояние конкретного обращения.
Одинаковый вопрос получил разные ответы при `idle` и `NotAllowedError`;
после запуска ответ использовал свежий измеренный уровень сигнала.
Отказ на рецепт показывает соблюдение тематической границы в данном примере.

Снимок отражает момент отправки: если звук уже затих или страницу перезагрузили,
он не восстанавливает прежние события. RMS не калиброван в физическую громкость,
активная дорожка не доказывает исправность оборудования. Ответы AI могут быть
неверными; правила тематики и защита от смены роли не гарантированы для любого
запроса. Сервис рассчитан на локальное использование, не на публичную нагрузку.

Видео загружено пользователем. Публичная страница доступна без авторизации;
имя `day-33-result.mp4`, размер 13 160 539 байт, MD5 и SHA-256 совпали с локальным
файлом, `antivirus_status=clean`. Загрузка через rclone не сработала из-за
`410 Gone`; успешная публикация видео подтверждена публичными метаданными.

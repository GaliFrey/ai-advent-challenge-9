# День 30 — публичный чат с локальной LLM на ВМ

## Задание

Развернуть локальную LLM на VPS или домашнем сервере с HTTP API и чатом.
Проверить сетевой доступ, несколько запросов и ограничения rate limit / context.
Формат сдачи — видео и код. Оригинал: `resources/task.md`.

**Видео результата:** [day-30-result.mp4](https://yadi.sk/i/fDrFY9t2GjlCjg).

подключений, очередь допустима, желательно два устройства; рекомендован доступ
через интернет, чтобы другие могли пользоваться моделью.

## Открыть чат

**Адрес: https://84.201.169.43/**. Доверенный сертификат Let's Encrypt выдан

публичной регистрации нет. Логины `heimdall` и `guest`; по запросу пользователя
для демонстрации установлен одинаковый простой пароль, сохранённый только
в локальном `.env` (игнорируется Git). Вторую учётную запись
можно использовать для демонстрации независимых диалогов на другом устройстве.

Выберите «Новый диалог», отправьте сообщение. При занятой модели показывается
место в очереди, затем статус генерации и ответ. Диалоги хранятся на сервере
и доступны только их владельцу. Enter отправляет сообщение, Shift + Enter
добавляет строку. При заполненном контексте нужно сократить сообщение или
создать новый диалог. Длинный ответ отмечается как достигший лимита.

## Реализация и ограничения

```text
Браузер → HTTPS Nginx → FastAPI + SQLite → очередь → Ollama → Qwen3:1.7b
                                      одна генерация на CPU
```

Всё работает на ВМ Яндекс Облака `ai-advent-day-30` (SSH-алиас `ycloud`):
Ubuntu 24.04 LTS, 2 vCPU, 8 ГБ RAM, 20 ГБ HDD. Домашний компьютер нужен
только для разработки и SSH. Модель Qwen3:1.7b Q4_K_M, Ollama 0.40.2,
uv 0.12.19. GPU, контейнеры и внешние API генерации не используются.
Доля CPU и прерываемость определяются настройками облака; внутри гостя
они не проверены.

| Ограничение | Поведение |
| --- | --- |
| Генерации | Одна активная; FIFO, до четырёх ожидающих |
| Запросы пользователя | Не более одного незавершённого; повтор — HTTP 409 |
| Rate limit | 5 принятых запросов за скользящие 60 секунд на пользователя; HTTP 429 + Retry-After |
| Переполнение очереди | HTTP 429, `queue_full`; отвергнутый запрос не расходует пользовательский лимит |
| Контекст | 2048 токенов: вход до 1760, ответ до 256, запас 32 |
| Проверка контекста | Вся история, системный prompt и новое сообщение; HTTP 422 до очереди и модели, без скрытой обрезки |
| Время | Ожидание до 300 секунд; запрос к Ollama до 120 секунд, worker до 125 |
| Диалоги | До 20 на учётную запись; можно удалять после завершения запроса |
| Тело / сообщение | До 64 KiB / 8192 символов, дополнительно токеновый лимит |
| Вход | До 5 попыток/мин на логин и 10/мин на IP |
| Nginx | До 10 HTTP-запросов/сек на IP, burst 20 |
| Сессия | 8 часов, до 10 сессий на пользователя; logout отзывает сессию |

`model.py` строит фиксированный ChatML prompt Qwen без thinking и считает
его официальным токенизатором из `tokenizer/`. В Ollama используется
`/api/generate` с `raw=true`: дополнительный шаблон не добавляется.
Клиент не может выбирать модель, параметры, роли или системный prompt.
Служебные токены Qwen в пользовательском тексте запрещены.
Токенизатор закреплён по revision/SHA-256; лицензия Apache-2.0 сохранена рядом.

`chat.py` хранит владельцев, истории, хеши паролей, сессии, задания и счётчики
в SQLite. Пароли — scrypt с индивидуальной солью; случайный токен сессии
в БД хранится только как SHA-256. Cookie `__Host-day30`: Secure, HttpOnly,
SameSite=Strict. Изменяющие запросы требуют точного Origin публичного чата.
Текст сообщений выводится через textContent; задана CSP без внешних скриптов.
Счётчики и история сохраняются после перезапуска. Незавершённые задания
после перезапуска получают явную ошибку; их сообщения не добавляются в историю.
Завершённые задания хранятся сутки, сами диалоги — до удаления владельцем.

Ollama слушает `127.0.0.1:11434`, приложение — `127.0.0.1:8000`.
UFW разрешает входящие TCP 22/80/443. HTTP нужен для ACME-проверки и
перенаправляет посетителей на HTTPS. Службы запускаются отдельными системными
пользователями с ограничениями systemd; память Ollama ограничена 6 ГБ,
приложения — 1 ГБ. Nginx заменяет forwarded-заголовки, Uvicorn доверяет
proxy только с loopback. **Приложение должно работать с одним worker**:
очередь обрабатывает один фоновый процесс.

## Развёртывание

Скрипты рассчитаны на отдельную новую Ubuntu-ВМ и sudo без пароля.
`setup-server.sh` устанавливает Ollama/uv с проверкой SHA-256 и загружает модель;
`setup-chat.sh` устанавливает приложение/Nginx/Certbot 5.8.0, выпускает сертификат
и настраивает службы. Они заменяют конфигурацию сервисов и firewall;
не применять к постороннему серверу. Веса находятся в `/var/lib/ollama/models`,
код — `/opt/ai-advent-day30`, БД — `/var/lib/day30/chat.sqlite3`.

Из корня репозитория:

```bash
ssh ycloud 'mkdir -p ai-advent-day30 && chmod 700 ai-advent-day30'
tar -C day-30 -cf - chat.py model.py manage.py pyproject.toml uv.lock static tokenizer deploy \
  | ssh ycloud 'tar -xf - -C ~/ai-advent-day30'
ssh ycloud 'cd ~/ai-advent-day30 && bash deploy/setup-server.sh'
ssh ycloud 'cd ~/ai-advent-day30 && bash deploy/setup-chat.sh 84.201.169.43'

cd day-30
uv sync --locked
uv run --locked python provision_accounts.py --origin https://84.201.169.43
```

`provision_accounts.py` создаёт локальный `.env` с режимом 0600, если файла
нет, и передаёт пароли на ВМ по SSH stdin без вывода. При повторном запуске
использует существующий `.env`, обновляет хеши и отзывает старые сессии этих
двух пользователей. `.env` на ВМ не загружается. Для новой учётной записи
или смены пароля используйте интерактивный ввод:

```bash
ssh -t ycloud 'sudo -u day30 env UV_CACHE_DIR=/var/lib/day30/uv-cache \
  uv run --directory /opt/ai-advent-day30 --locked --no-sync python manage.py another_user \
  --database /var/lib/day30/chat.sqlite3'
```

Пароль должен быть длиной 10–256 символов. Не передавайте пароль аргументом
команды. Для обновления кода повторите tar и `setup-chat.sh`; БД сохраняется,
приложение перезапускается. Незавершённые генерации получат ошибку.

В окружении агента системный SSH-конфиг выдавал ошибку прав на
`/etc/ssh/ssh_config.d/20-systemd-ssh-proxy.conf`. Использовался
`ssh -F /home/heimdall/.ssh/config`; для provision/check-скриптов предусмотрен
`--ssh-config`. Системный файл не изменялся.

IP-сертификат действует 160 часов. `certbot-renew.timer` проверяет продление
каждый час с небольшим случайным сдвигом и перезагружает Nginx после обновления.
Внешний TCP/80 должен оставаться доступным для ACME.
Certbot-аккаунт зарегистрирован без email. Если публичный IP ВМ изменится,
нужно обновить PUBLIC_ORIGIN, Nginx и сертификат; это не делается автоматически.
Останавливайте/удаляйте учебную ВМ через облачную консоль после работы,
учитывая возможную смену адреса при следующем запуске.

## Проверки

Локальные серверные тесты не вызывают реальную модель:

```bash
cd day-30
uv run --locked python -m unittest -v test_chat
node --check static/app.js
bash -n deploy/setup-chat.sh
```

Публичные проверки используют два аккаунта из `.env` и реальные генерации
на CPU ВМ. Первая отправляет семь запросов и создаёт два демонстрационных
диалога; вторая — два запроса и ещё два диалога. Если предыдущий запуск
исчерпал лимит, дождитесь минуты перед повторением.

```bash
uv run --locked python verify_chat.py
uv run --locked python verify_boundaries.py --restart-host ycloud
```

`--restart-host` явно разрешает второй проверке перезапустить приложение
для проверки существующей сессии и истории. Без флага проверяется только
контекст и лимит ответа. Отчёты не содержат пароли/cookie и сохраняются в
игнорируемом `resources/`. `verify_server.py` отдельно проверяет приватный
Ollama API; публичный чат этим скриптом не проверяется.

На ВМ:

```bash
sudo systemctl status day30-chat ollama nginx
sudo journalctl -u day30-chat -n 30 --no-pager
sudo systemctl list-timers certbot-renew.timer
sudo certbot renew --dry-run --no-random-sleep-on-renew --run-deploy-hooks \
  --deploy-hook '/usr/bin/systemctl reload nginx'
sudo ufw status verbose
ollama ps
df -h /
```

## Проверенный результат 10.10.2026

- Пройдены 9 серверных тестов локально и на Python 3.12 ВМ: авторизация,
  CSRF, чужие диалоги/задания, FIFO и четыре ожидающих, один активный worker,
  пользовательский лимит, полный контекст, сбой модели и перезапуск.
- Публичный HTTPS проверен с рабочего компьютера без отключения проверки
  сертификата. Cookie защищена; неавторизованный запрос — 401,
  посторонний Origin — 403, чужие диалоги/задания — 404, повтор незавершённого — 409.
- Два одновременных подключения обработаны последовательно за 2,499 / 3,709 с
  с учётом ожидания. Оба сохранили свой цвет в следующем запросе:
  «Синий» и «зеленый». Арифметический ответ — «4».
- Шестой запрос за минуту отклонён с 429 и Retry-After;
  вход на 2041 токен отклонён с 422 до генерации.
- На границе приняты ровно 1760 токенов, фактический счётчик Ollama совпал.
  Следующий запрос с историей на 1778 токенов отклонён без изменения истории.
  Длинный ответ остановлен на 256 токенах за 31,783 с, выставлен признак обрезки.
- Реальный перезапуск приложения сохранил сессию и историю.
  До реализации чата также проверена полная перезагрузка ВМ и автозапуск Ollama.
- Выпуск IP-сертификата и dry-run продления с reload Nginx успешны;
  службы и таймер включены. Первый сертификат действителен до
  17.10.2026 04:29 UTC. Фактическое будущее продление ещё не наступило.

Артефакты: `resources/chat-check.json`, `resources/chat-boundaries.json`,
ранее — `resources/server-check-initial.json` и
`resources/server-check-after-reboot.json`. Они остаются локальными материалами.
Проверены JS-синтаксис, Python-компиляция, bash-синтаксис и uv lock.
Автоматические визуальные и браузерные проверки не выполнялись. Два
одновременных подключения проверены HTTP-клиентами с одного компьютера;
пользователь отдельно записал демонстрацию работы двух аккаунтов.
Проверка на двух физических устройствах не подтверждена. Длительная нагрузка
не проверялась.
Качество небольшой CPU-модели ограничено; длинные ответы заметно медленнее.

# День 23 — rewrite, фильтрация и реранкинг

## Задание

Добавить второй этап после поиска: reranker или фильтр релевантности.
Настроить порог отсечения и top-K до и после отбора. Сравнить качество
без фильтра/rewrite и с улучшениями. Итог: RAG с query rewrite,
фильтрацией/реранкингом и сравнением режимов. Формат сдачи — видео и код.
Оригинал находится в локальном `resources/task.md`.

## Решение

Самостоятельный uv-проект использует индекс дня 21 и проверенные helpers
дня 22: проверку актуальности индекса, формат контекста, system prompt,
независимые DeepSeek-вызовы и поиск по `section_windows`. Код предыдущих
дней не изменён. Для запуска нужен весь репозиторий, включая дни 21–22.
Корпус неизменен: README дней 0–20. Локальные журналы, ресурсы и секреты
в индекс не попадают. SQLite открывается только для чтения.

| Режим | Цепочка |
| --- | --- |
| `baseline` | Исходный вопрос → поиск → top-5 → ответ |
| `rewrite` | Перефразирование → поиск → top-5 → ответ |
| `rewrite_filter` | Перефразирование → top-20 → порог similarity → до 5 → ответ |
| `rewrite_rerank` | Перефразирование → top-20 → reranker → порог его оценки → до 5 → ответ |

5 и 20 — начальные настраиваемые значения. Базовый режим и rewrite также
используют выбранный итоговый K. Rewrite — один отдельный DeepSeek-вызов
на вопрос с инструкцией преобразовать вопросительное предложение в компактный
перечень темы, сущностей и искомых сведений, сохранив смысл, номера дней и
условия, без добавления предполагаемых ответов. JSON-формат ответа
проверяется; сохранение смысла требует просмотра человеком. Новые результаты сохраняют флаг `changed`;
интерфейс показывает «запрос изменён» или «запрос не изменён», сравнивая тексты
без учёта регистра и лишних пробелов. Это работает и для старых результатов
без флага. Неизменённый ответ модели принимается без автоматических повторов.
Одна формулировка используется во всех трёх улучшенных режимах. Их поиск также выполняется один раз на top-K
кандидатов; режим rewrite берёт первые итоговые K без порога. Два последних
режима получают одинаковые кандидаты. Оценки и ответы других режимов в LLM
не передаются. Генерация всегда получает **исходный вопрос**.

Reranker — локальный CPU `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`, ревизия
`1427fd652930e4ba29e8149678df786c240d8825`. Он оценивает пары **исходный вопрос
+ текст чанка** с максимальной длиной 512 токенов; более длинные пары могут
усекаться. Scores получаются с явно заданным sigmoid, диапазон 0–1.
Оценки не являются откалиброванными вероятностями и не сравнимы с similarity.
Описание модели: [Hugging Face](https://huggingface.co/cross-encoder/mmarco-mMiniLMv2-L12-H384-v1),
API: [Sentence Transformers CrossEncoder](https://www.sbert.net/docs/package_reference/cross_encoder/model.html).

Начальные пороги: similarity **0.30**, reranker **0.10**. Это экспериментальные
настройки, не результат подбора оптимального качества. Фильтр similarity
сохраняет порядок поиска; reranker меняет порядок, затем применяет свой
порог. Результат может содержать меньше K чанков или быть пустым. Пустая
выдача передаётся модели без возврата к неотфильтрованным фрагментам.
Для каждого кандидата сохраняются исходный ранг, итоговый ранг, оценки,
источник, текст и решение: в контексте, ниже порога или за пределами top-K.
Ссылки S1…SK соответствуют только итоговому контексту. Проверка номера ссылки
автоматическая; подтверждение утверждений источниками оценивается вручную.

## Подготовка и запуск

Нужны Python 3.12+, uv, индекс дня 21 и ключ DeepSeek.

```bash
cd day-23
uv sync --locked
test -e .env || cp .env.example .env
# Заполнить DEEPSEEK_API_KEY в .env; существующий файл не перезаписывается.
uv run --locked python main.py prepare
uv run --locked python main.py tui
```

`prepare` скачивает публичную модель reranker в `models/reranker/` и
проверяет загрузку, без DeepSeek. При заполненном кэше работает локально.
Кэш исключён из Git. Модель эмбеддингов использует кэш дня 21; при отсутствии
полного локального снимка потребуется загрузка с Hugging Face. Модель ответа
задаётся `DEEPSEEK_MODEL` (по умолчанию `deepseek-flash`); `temperature=0`,
thinking отключено, `max_tokens` явно не задаётся. Системные переменные
имеют приоритет над `.env`. Ключ не записывается в журнал и результаты.

Если индекс отсутствует или устарел:

```bash
cd ../day-21
uv sync --locked
HF_HOME="$PWD/indexes/hf-cache" uv run --locked python indexer.py build
cd ../day-23
```

DeepSeek получает вопрос для rewrite и вопрос с фрагментами README для
ответов. **Один запуск вопроса — 5 платных вызовов**: rewrite и четыре ответа.
Полное демо десяти вопросов — 50 вызовов. Автоматических повторов нет.

## Полноэкранный TUI и видео

Рекомендуется полноэкранный терминал от 180 столбцов × 60 строк.
Интерфейс занимает всю доступную ширину, без фиксированного узкого контейнера.
Сверху: выбор одного из десяти вопросов, поле своего вопроса, кнопки
сравнения и полного демо, настройки top-K и обоих порогов. Поле своего
вопроса используется при сравнении, полное демо всегда использует
`questions.json`. Пороги и top-K фиксируются в сохранённом результате.

Строка состояния при открытии показывает, настроен ли ключ. Во время
работы видны анимированный индикатор, активный вопрос и режим, конкретный
этап (загрузка модели, поиск, запрос DeepSeek и т. д.) и обновляемое время
с начала запуска. Отсутствие ключа или неверные настройки останавливают
запуск с заметным уведомлением и записью ошибки `configuration` в журнал.
После изменения `.env` приложение нужно перезапустить.

Вкладки четырёх режимов показывают:

- Путь этапов, текущий статус, завершённые этапы и их время. Общие rewrite
  и поиск обозначены как повторно использованный результат.
- Слева — исходный и поисковый запросы, таблица кандидатов с оценками,
  рангами и причинами отбора, ниже — полный текст выбранного чанка.
- Справа — конечный ответ, ссылки, число чанков, токены и время.
- Вкладка «Сравнение» показывает четыре ответа выбранного вопроса рядом,
  их источники и таблицу статусов, числа чанков, токенов ответа, времени LLM,
  неверных ссылок. Общий rewrite показан отдельно. Для сравнения другого
  вопроса используется верхний список. Балльная оценка ответов не используется.

Таблица чанков управляется стрелками и мышью. Области текста и ответа
прокручиваются независимо; широкие таблицы допускают горизонтальную прокрутку.
Вкладки и выбор вопроса доступны во время выполнения. Кнопки повторного
запуска и настройки блокируются до завершения. При Ctrl+Q новые этапы
не запускаются; текущий запрос может завершиться в пределах своего timeout
(до 90 секунд), после чего частичный результат сохраняется.

План записи: выбрать q05 → запустить сравнение → показать этапы, baseline,
rewrite и оба варианта отбора → выбрать отсечённый и выбранный чанки →
сравнить ответы → повторить на составном вопросе q08 и вопросе без ответа
q10. Полное демо запускается только по кнопке, не при открытии приложения.
Сохранённый прогон можно открыть без моделей и API:

```bash
uv run --locked python main.py tui resources/<имя-прогона>.json
```

Открытие не запускает запросы; нажатие кнопки начинает **новый** прогон.
Результаты каждого этапа сохраняются атомарно в `resources/ask-*.json` или
`resources/demo-*.json`; ошибка не удаляет ранее полученные ответы и чанки.

## CLI и сравнение режимов

```bash
uv run --locked python main.py ask "Как проверяется скачанный отчёт в дне 20?"
uv run --locked python main.py benchmark --top-k-before 20 --top-k-after 5 \
  --similarity-threshold 0.30 --rerank-threshold 0.10
uv run --locked python main.py show resources/<имя-прогона>.json
```

Сравниваем одинаковые десять вопросов из дня 22, включая два составных и
два без ответа в корпусе. Ожидания и источники не передаются модели.
На видео показываем работу каждого режима: исходный и поисковый запросы,
этапы поиска, кандидатов, причины отбора, изменение порядка после reranker
и итоговые ответы с источниками. Сравнение содержательное, без шкалы 0–2
и обязательного заполнения ручных оценок. Токены и время — измеренные
показатели работы, а не оценка правильности ответа. Попадание README и
высокое сходство не гарантируют наличия ответа; rewrite и пороги могут
ухудшить результат, поэтому демонстрация сама по себе не доказывает
улучшение качества.

Время этапов — наблюдаемое время текущего запуска, включая холодную загрузку
reranker в его режиме. Общие этапы не выполняются повторно, поэтому время
режимов нельзя трактовать как независимый замер скорости. Токены общего
rewrite показаны отдельно от токенов каждого ответа.

## Диагностический журнал

Каждый сеанс создаёт JSONL в **`day-23/logs/`**, отдельно от `resources/`.
Каталог исключён из Git, файлы имеют права 0600. Путь не зависит от cwd;
временные отметки UTC. Записываются этап, режим, порядковый номер вопроса,
длительность, параметры отбора, тип исключения и последние 12 кадров стека
(файл, строка, функция). Каждая запись сразу сохраняется и файл закрывается.
Путь журнала постоянно виден в интерфейсе и сохраняется в отчёте.

API-ключи, тексты запросов/ответов, сообщения исключений и локальные
переменные в журнал не пишутся. Для внешних ошибок это ограничивает
диагностику: тело ответа сервиса отсутствует. Полные запросы поиска, чанки
и ответы находятся в локальном JSON-результате в `resources/`.

```bash
tail -n 30 logs/<имя-журнала>.jsonl
```

## Результаты и выводы

30.09.2026 сохранены **10 успешных живых сравнений на двух вопросах** —
q03 о памяти дня 11 и q10 о бюджете и SLA трёх ВМ. Это 40 ответов и 10
отдельных вызовов rewrite, а не полный benchmark десяти разных вопросов.
Сравнение после изменения инструкции подтверждает, что запрос переписывает
DeepSeek: для q03 получено «День 11: три слоя памяти; очистка при создании
новой задачи», для q10 — «День 20: утверждённый месячный бюджет в рублях;
SLA доступности для трёх ВМ».

| Сохранённый прогон (UTC) | Вопрос | Порог similarity | Baseline | Rewrite | Rewrite + фильтр | Rewrite + reranker |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| `131602.721117Z` | q03 | 0,60 | 5 | 5 | 5 | 5 |
| `131704.544374Z` | q10 | 0,60 | 5 | 5 | 0 | 1 |
| `131806.515227Z` | q10 | 0,30 | 5 | 5 | 5 | 1 |

Числа в четырёх последних столбцах — количество чанков в контексте.
Во всех этих прогонах K кандидатов = 20, итоговый K = 5, порог reranker =
0,10; ответы завершились с `finish_reason=stop`, неизвестных номеров ссылок
не обнаружено. JSON-файлы и журналы остаются локальными в игнорируемых
каталогах; имена полных файлов: `resources/ask-20260930T<UTC>.json`.

**q03:** базовый ответ перечислил три слоя памяти, но не смог назвать
очищаемые слои. После rewrite в контекст вошёл фрагмент с прямым правилом
«Новая задача начинает пустые short-term и working, сохраняя long-term»;
все три улучшенных режима дали ответ на обе части вопроса. При пороге 0,60
similarity-фильтр не изменил top-5, поэтому отдельный прирост от фильтра
на этом примере не подтверждён.

**q10:** при пороге 0,30 similarity-фильтр также не изменил контекст.
Порог 0,60 отсёк все 20 кандидатов, модель получила пустой список источников
и отказалась называть бюджет и SLA. Формулировка её отказа содержит
«в предоставленных источниках» даже при пустом контексте — это неточное
описание отсутствующих данных. Reranker поднял чанк `day-20/README.md`
с 20-го места на первое и отсёк остальные 19. Этот чанк описывает лимиты
истории и аутентификацию, а не бюджет/SLA: улучшение тематического отбора
не означает наличие ответа. Все четыре режима отказались выдумывать числа.

Для q10 с порогом 0,60 ответы расходовали 1457 / 1446 / 281 / 458 токенов
соответственно; общий rewrite оплачивается отдельно. Меньший контекст
снизил расход в этом конкретном прогоне, но не доказывает общую экономию
или превосходство режима. Пороги экспериментальные, отдельной калибровки
и полного сравнительного benchmark не было. Результаты демонстрируют
реальный эффект rewrite, жёсткого отсечения и реранкинга; выводы ограничены
двумя вопросами и сохранёнными запусками.

## Проверки

```bash
uv run --locked python -m unittest -v
uv run --locked python -m compileall -q main.py pipeline.py retrieval.py shared.py \
  tui.py session_log.py check_local.py test_pipeline.py test_tui.py test_session_log.py
uv lock --check
git diff --check
```

Перед публикацией прошли 14 локальных тестов, компиляция и проверка
lock-файла. Проверены общий rewrite и кандидаты, независимость ответов,
изменение порядка reranker, пороги и пустой контекст, частичный результат,
отмена следующих вызовов, безопасность журналов и работа вкладок.
Headless TUI проверен при 180×60, включая просмотр сохранённых реальных
ответов. Визуальная проверка пользовательского терминала не выполнялась.

Реальные индекс, эмбеддинги и reranker также прошли четыре режима на десяти
вопросах с подменными rewrite и ответами. Результат
`resources/local-check-20260930T115157.340440Z.json` отмечен
`validation_only=true` и не является сравнением качества генерации.
Повторить локальную проверку без DeepSeek при заполненном кэше моделей:

```bash

```

Новые вызовы DeepSeek при подготовке публикации не выполнялись.
